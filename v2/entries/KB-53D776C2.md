No: the tree prints an em dash instead of a zero. Round one's arm C read the shipment amount as a dash in the Admin order document tree while the Shipment blade and the REST payload for the same shipment both read 0.00. The tree appears to blank a zero rather than render it, so a reader who takes the dash as absent-value rather than zero goes looking for a shipment total that was never missing. Read the blade or the payload to settle it; on this deployment a zero shipping total is itself the normal case, because fixed rate shipping prices per OPTION through a store setting.
