Five: Cancelled, New, PickPack, ReadyToSend, Send -- the value is Send, not Sent, so a check written against Sent never matches. A checkout-created shipment starts at New. What moves it is an operator, not a background process: the Admin shipment blade exposes status as a plain select listing all five, with no gate, no wizard and no required precondition, so any value can be chosen from any other and a shipment holding zero items can be set to Send. Two things follow for anyone reading shipment state. First, status is not the whole of it -- isApproved, isCancelled and cancelledState are separate fields the status select does not touch, and they are not uniform across operation types: on a cancelled order cancelledState stays Undefined while on its cascaded PaymentIn it becomes Completed. Second, the shipment's status is independent of the order's. Cancelling the order does not move it: the order goes status Cancelled and isCancelled true while its shipment stays status New and isCancelled false. That is why a Cancelled order can sit above a shipment that still reads New, and why order status is never a safe proxy for whether fulfilment is still open.
