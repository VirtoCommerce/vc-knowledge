STEP 1 - the coupon widget is not available on a NEW promotion. On the New promotion blade the widget reads 'You can add coupons after saving a promotion' and does nothing; it only becomes the clickable Coupons widget once the promotion exists. So build the promotion first (see the percentage-off flow for that), then come back for the coupon.

STEP 2 - Coupons widget, Add, then Code. The blade is New coupon with four inputs: Code, Coupon expiration date (blank means the promotion's own expiration), Maximum use number and Maximum uses per customer, both 0 for unlimited. The hint says the code may contain only alphanumeric characters. Create writes it.

STEP 3 - there is no 'requires a coupon' switch anywhere on the promotion. The promotion's hasCoupons is DERIVED from whether any coupon rows exist: create the first one and it flips to true, delete the last one and it flips back to false. That flag is the whole gate - with it true the promotion contributes nothing to a cart until a matching code is on the cart, and with it false the same promotion applies to every cart that satisfies its conditions. Deleting a coupon takes a typed 'yes' in a confirm dialog.

STEP 4 - on the storefront, the coupon box is in the Order summary sidebar of /cart, titled 'Promotion code', and it is not rendered at all while the cart is empty. Type the code and press Apply.

STEP 5 - matching is exact. The code is case-sensitive and is not trimmed: the same code in lower case, or with a leading or trailing space, is refused exactly as a code that does not exist is. If a shopper says the code does not work, ask about case before you look at the promotion.

STEP 6 - applying does NOT consume the coupon. Total use count stays 0 on the coupon row through apply, remove and re-apply; it is redemption on an order that spends a use, not application to a cart. That makes a coupon safe to test with repeatedly even when Maximum use number is set.

STEP 7 - if you need to see it NOT apply, edit the promotion rather than the coupon: add a cart condition the cart cannot meet (Promotion conditions, 'If any of these cart conditions are true', 'Cart subtotal is at least ...'). The change lands on the next cart read with no cart mutation, and the already-applied code flips to isAppliedSuccessfully false with its discount row gone.

Pitfall: the storefront pre-checks with validateCoupon and refuses to send a code it says no to, so you cannot get a bad code onto a cart through the page. Call addCoupon directly if that is what you need to observe - it stores anything.
