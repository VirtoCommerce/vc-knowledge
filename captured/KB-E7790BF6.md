A coupon on a cart is TWO records, not one, joined only by the code string. The code itself lands in cart.coupons -- on the storefront xAPI a CouponType of exactly two fields, code and isAppliedSuccessfully, with no money on it at all; on the platform REST cart the same thing is a bare array of strings (plus a singular 'coupon' holding the same string), so the stored cart keeps the CODE and nothing about whether it worked. The reward lands separately in cart.discounts as a DiscountType, and the only thing tying that row back to the code is its 'coupon' field, which carries the code verbatim. The two are joinable in one direction only: from a discount you can see which code produced it, but from cart.coupons you cannot see what any code was worth. The REST projection of the same discount is richer than the GraphQL one -- it adds the promotion's id AND its name next to the description, while DiscountType offers promotionId but no name, so the promotion's NAME is unreachable over the storefront API and the description is the only human-readable label a shopper can ever be shown.
