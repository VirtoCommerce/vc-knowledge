The cart is not consumed by the order and it is not archived: it is EMPTIED IN PLACE and handed back to the same shopper. GET /api/carts/{id} on the pre-order cart id still returns 200 after placement, with the same id, the same name (default) and the same createdDate -- which on this stand predated the run by four days -- but items [], subTotal 0, total 0, discounts [], coupons [] and a FRESH checkoutId. POST /api/carts/search for that customer and store returns exactly one row, that one. So a (customer, store, cart name) triple owns ONE long-lived cart row that outlives every order placed from it, and there is no record anywhere of the cart as it stood at checkout -- the order is the only copy. Two consequences. Nothing about a converted cart can respond to a promotion moving afterwards, because nothing about the purchase is left on it to respond. And an investigation that wants to know what a shopper's cart looked like when they ordered cannot get it from the cart: read the order's own line items and discount rows, which are snapshots, and treat the cart id on any pre-checkout evidence as a pointer that has since been reused.
