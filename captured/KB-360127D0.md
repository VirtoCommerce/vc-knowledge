The configuration a buyer assembled is not carried onto the order in the shape it had in the cart. CartConfigurationItemType has eight fields -- id, name, type, customText, files, productId, quantity and sectionId. OrderConfigurationItemType has five: id, name, type, customText and files. productId, quantity and sectionId are all dropped. So for a configuration section whose type is 'Product', the order records the chosen option's NAME and nothing that identifies the product it was or how many were taken, and it does not record which section the choice answered. Anything reconciling a configured order back to catalog products has only a display string to match on. This is read off the deployment's own schema rather than from a placed order: read the same two type tables on any deployment and a diff either confirms it or retires it.
