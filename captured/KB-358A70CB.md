It shows three of the shipment's fields and never says the word shipment. The chosen delivery method is not an order field at all -- a CustomerOrder has no shipping-method column, and its line items carry shippingMethodCode null -- so the Shipping method block on the storefront order page is rendering the SHIPMENT, building its label from shipmentMethodCode, shipmentMethodOption and price. Everything that identifies the shipment as a record is simply not selected: of OrderShipmentType's 53 fields the page asks for 7 (shipmentMethodCode, shipmentMethodOption, shippingMethod, price, discountAmount, deliveryAddress, pickupLocation) and omits number, status, statusDisplayValue, items, trackingNumber, trackingUrl, deliveryDate and fulfillmentCenter. So a customer cannot see that the shipment exists as a numbered document, cannot see its state, and would not learn it had moved; the status badge on that page is the ORDER's status, a different field on a different record that moves independently. Diagnosing this needs only the response body: GraphQL returns exactly what was selected, so an absent key proves it was never asked for -- which matters because reading the request body of an authenticated call would expose the bearer token.
