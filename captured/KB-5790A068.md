There is none to read. Round two's arm A queried GET /api/platform/changelog/Promotion/changes and GET /api/platform/changelog/PromotionEntity/changes over the window in which a promotion was demonstrably edited, and both returned an empty array: marketing promotions are not registered for change tracking on this deployment. What is left is the record's own createdDate and modifiedDate, which prove only that SOMETHING changed and not what - a deactivation moves modifiedDate exactly as a reward edit does. So when a promotion's name, description and reward disagree, the question of which one was edited is not answerable from this deployment at all, and an answer that names a culprit is a guess. Promotions on this store are routinely mutated after the orders that used them, which is what makes this worth knowing before an investigation starts rather than after.
