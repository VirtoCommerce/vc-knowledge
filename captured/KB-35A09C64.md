Promotions are re-evaluated on every storefront cart read, not frozen into the stored cart. Flipping Promotion.isActive through PUT /api/marketing/promotions changes CartType.discounts and CartType.discountTotal on the very next Query.cart, with no cart mutation in between; a no-op cart mutation afterwards returns the same numbers.

**Anchor corrected.** `Promotion.isActive` → `GET /api/marketing/promotions/{id}` — The storefront schema's Promotion type carries exactly four fields - description, id, name, type - and no isActive, so the coordinate resolved to nothing and the entry could never reach an agent standing on it. isActive is a field of the REST promotion model; the place it is read back is GET /api/marketing/promotions/{id}, which the entry's own PUT already pairs with.
