On a vc-frontend 2.60 PR build (scope-slot loader, desktop 1920px), a MutationObserver+ResizeObserver timeline on .search-bar .vc-input__decorator during breadcrumb, sidebar, Back/Forward and /category/<id> redirect navigations shows: the loader first holds the previous slot width (or the 5rem/80px minimum when coming from no scope), then resizes to the new label's width ~2-3 ms before the chip replaces it. The input left edge therefore moves by the width difference (Printers<->Laser Printers: 31.36 px; empty->Printers via id redirect: 14.89 px; long labels: ~38 px), measured inside the loader phase; at the swap itself the delta is 0. Loader and chip are never present together, the slot is never empty during category->category, and the settled chip/placeholder name the new category.
