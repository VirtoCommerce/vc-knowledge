No, not necessarily. On this deployment, a brand-new storefront account (contact + security account created via REST) had pushMessages(withHidden: true).totalCount = 1 within seconds of creation. The row was an older Sent push message with trackNewRecipients=true and memberQuery 'test' (a free-text member query). Its per-recipient createdDate equalled the account-creation time. Three new organization members matching the same and other tracked free-text queries ('admin', 'new') each got 3 such rows. 15 Sent messages had trackNewRecipients=true, several with free-text memberQuery. Any account whose name or email contains a matching token (e.g. 'test') joins those audiences on creation. Because a Sent message cannot be edited or deleted, an account created this way can never reach a 'no push ever received' state.
