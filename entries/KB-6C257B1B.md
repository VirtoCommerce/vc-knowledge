With global MultiFactorAuthentication.Enabled=true, a Customer-type account holding a back-office role and a 65-character username signed in to the Backoffice: password step OK, code sent, right code -> POST /api/mfa/signin/verify HTTP 500 body {"message":"String or binary data would be truncated in table '<db>.dbo.AspNetUsers', column 'ModifiedBy'..."} and the UI showed "Authentication error ... (Code: 500)". The session cookie was nevertheless issued (the app then opened /workspace as that user), the sign-in log recorded no MFA row for it, and GET /api/platform/security/logout answered the same 500 so the user could not sign out. A 41-character Customer with the same role completed the code step normally (200, session) and a 55-character Manager too, so the trigger is the username length versus ModifiedBy (64). The 500 body exposes database and table names to an unauthenticated caller.
