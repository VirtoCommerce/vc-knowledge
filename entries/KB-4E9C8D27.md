Admin POST /api/return/search on a stand upgraded to 3.1005.0-pr-28-62f9 listed 12 returns. All 11 returns created before the storefront flow (status New/Approved/Rejected, admin-created) have storeId null, customerId null and customerName null. Those whose order belongs to an organization (3 of 11) have organizationId and organizationName equal to the order's, so the migration backfill ran and filled only those two columns; the rest have no organization because their order has none. The one storefront-created return (Requested) has storeId, customerId and customerName set and no organization (personal account). Source (ReturnSearchService.BuildQuery @62f9aae) filters organizationReturns by StoreId == the storeId argument, so a return with null storeId cannot match; not exercised end to end because no role held the permission needed to run the query as a member.
