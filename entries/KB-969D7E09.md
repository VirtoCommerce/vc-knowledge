GET /api/catalog/products/{id} for a product that has variations returns them in the variations[] array. POSTing that body back unmodified to POST /api/catalog/products returned 500 "Violation of PRIMARY KEY constraint 'PK_Item'. Cannot insert duplicate key in object 'dbo.Item'. The duplicate key value is (<variation id>)": the save path tries to INSERT the embedded variations as new items. The same round-trip on a product without variations returned 200, both with the default response group and with respGroup=Full. Deleting the variations key from the body before the POST returned 200, and a re-read showed both variations still attached to the parent. So a GET-mutate-POST reconcile must drop variations[] from the body; a 500 on this path is caused by the request body, not the product itself.
