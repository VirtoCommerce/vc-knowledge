Trigger observed: an admin PUT /api/sales-rep removed the organization a signed-in rep had selected (the same follows from any membership deletion that leaves the access token alive). On each full page load (/, /account/dashboard, /company/tasks, /company/my-customers; 5/5) the storefront bootstrapped with pageContext still naming the removed organization (from the token claim), the header Ship to selector issued GetOrganizationAddresses for it, the response carried errors[0].extensions.code Forbidden ("Access denied."), and the page was replaced by /403 "Access denied - You do not have permissions to access the requested page" with only a Home page button; the header kept showing the removed organization and the account menu offered no switch with one organization left. Navigating inside the app from the 403 page (Home page, header links) rendered pages normally because the header does not remount. Source (vc-frontend 2.60.0): ship-to-selector onMounted -> fetchAddresses -> useOrganizationAddresses(contact.organization.id); errorHandlerLink maps any Forbidden to forbiddenEvent and broadcast.ts pushes the NoAccess route, with no session check. The state ends with sign-out + sign-in (lands in an accessible organization) or, without it, at the first full load after the access token expires: the refresh returns 400 invalid_grant and the user is sent to /sign-in?returnUrl=... with no message.
