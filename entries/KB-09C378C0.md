On Return 3.1005.0-pr-28-62f9 the Admin Return list shows an Organization column (blank for returns without an organization), sortable both ways, and its keyword also matches the customer name. POST /api/return/search accepts organizationId and excludeDrafts and then returns the same set, by id, as organizationReturns for a holder; without excludeDrafts drafts are included. At the default blade width the nine columns are about 100 px each and the headers truncate. From commit d9233ee1 (VCST-6226, 2026-10-08) the criterion is submittedOnly (Return.SubmittedDate != null) and excludeDrafts is no longer read: on Return 3.1005.0-pr-28-fb4f (vcst, 2026-10-12, one organization, 2 runs) {organizationId} and {organizationId, excludeDrafts:true} both returned 138 rows incl. 1 Draft, submittedOnly:true returned 60 with no draft and no unsubmitted return, and adding storeId cut it to that store (58): without storeId the search also returns the organization returns raised in another store. On vcptcore_dev (2026-10-09) the submittedOnly+storeId set equalled organizationReturns for a holder; that parity was not re-observed on vcst (no organization-member sign-in). The Admin keyword also matches customerName (ReturnSearchService.GetKeywordPredicate). Unreleased: PR VirtoCommerce/vc-module-return#28.
