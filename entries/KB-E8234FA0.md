On x-cart 3.1037.0-pr-141 a wishlist with no stored sharing row (admin REST sharingSettings []) returns scope Private and a sharingSetting.id that is a different GUID on every read (create response and two reads gave three ids). That id is not a working key: sharedWishlist on it returns null. The first changeWishlist that shares the list persists the sharingKey the client sends in the same write (that id then works for anonymous sharedWishlist); without a sharingKey the server mints its own, different from any id the client read before. Once a row exists the id is stable across scope changes.
