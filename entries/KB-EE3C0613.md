On ProductComparison 3.1000.0-pr-1-98d6, store B2B-store: a B2B buyer (contact with an organization; token issued with storeId) saved 2 products, own compareList returned list A with 2 items. An administrator token calling compareList(storeId, userId:<that buyer's id>) got a different list B with 0 items (null before any admin save), also with the id upper-cased; admin saveProductsToCompareList under that id added to list B, and the buyer's list A stayed at 2 items. For a buyer with no organization, the administrator got the buyer's own list (same id) and an admin save appeared in the buyer's list. Source: the organization is taken from the caller's token only (no organizationId argument), the list key is (UserId, StoreId, OrganizationId), and an admin token has no organization, so admin always addresses the org-less list. The module README documents this as intended. The org-less list an admin creates for a B2B buyer survives clearCompareList (emptied, not deleted) and is not removed by the cleanup job while the user exists.
