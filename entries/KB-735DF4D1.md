No — it depends on the rest of the rule, and the two cases look nothing alike. Clicking the 'Custom conditions' starter chip creates ONE blank row (field Name, operator is, value empty). With only that row present, choosing a field and an operator and leaving the value empty renders NO hint, the estimate panel reads '0 recipients / No conditions set', and the toolbar Save is fully ENABLED (Send stays disabled because there are 0 recipients). Once the rule holds at least one COMPLETE condition (e.g. Customer type is Employee, estimate 1 recipient) and a second row is added with 'Add condition', that second row immediately shows the inline hint 'This condition has no value.' under it, the joiner (AND/OR) is drawn, Save becomes disabled, and the estimate is unchanged by the incomplete row. Deleting the incomplete row removes the hint and re-enables Save immediately, with the estimate still unchanged. So a test that means to exercise the held-Save guard must first set a complete condition; driving only the blank row the starter chip creates exercises the opposite branch.
