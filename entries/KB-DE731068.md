2026-11-04 on vcst (platform 3.1094.0, VirtoCommerce.MFA 3.1002.0-pr-3-1a0f). Global MultiFactorAuthentication.Enabled written true and read back true. A disposable store cloned from the B2B store with StoreMode=Disabled (read back) and a confirmed-email customer whose storeId is that store, no back-office role. POST /connect/token grant_type=password, scope=offline_access, storeId=<that store> answered HTTP 200 with access_token, token_type, expires_in, refresh_token and no twoFactorToken; MfaSignInEmailNotification journal rows for the account: 0 before, 0 five seconds after. The same store set to Enabled (read back), identical request: HTTP 400 error=invalid_grant, code=two_factor_required, twoFactorToken present, no access token, and exactly one MfaSignInEmailNotification row (Pending) appeared. Observed live on the build where the source reading of KB-0929D604's dispute narrows the skip to the store's own non-backoffice accounts; this run covers only that own-customer case, not a Manager or a foreign-store user.
