In a fresh virtual catalog (one language), two parent categories were created, then one child under each, both with seoInfos [{semanticUrl: the same value, languageCode: the catalog language, isActive: true, objectType: Category}]. The second child's POST /api/catalog/categories returned 200 and its body carried the duplicate semanticUrl; no validation error, no numeric suffix. GET /api/seoinfos/explain on a store over that catalog with Stores.SeoLinksType=Long then listed both records as Candidates and resolved the one whose parent path matched (the other got PermalinkMismatch). Observed in suite 066b SEO-EXP-007, run REG-2026-10-20-1528-066b-qa1. Only category create via REST was exercised; product saves and other APIs were not.
