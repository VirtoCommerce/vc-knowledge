Seeded a configuration, then re-POSTed it to /api/catalog/products/configurations with dependsOnSectionId set on one section (PUT /{id} returns 404 on this build, so POST is the upsert path). An immediate GET /api/catalog/products/configurations/{id} returned the section with dependsOnSectionId null in one of three runs; a moment later POST /api/catalog/products/configurations/search {productIds:[...]} and GET both showed it wired, and Query.productConfiguration showed it too. Likewise, after deleting the parent product, search by productId returned 0 configurations while GET by the old configuration id still returned the 8-section body. Treat GET-by-id as possibly cached: confirm a write by polling configurations/search (or productConfiguration) rather than a single GET.
