On virtostart (storefront Ver. 2.58.0, store B2B-store), two CyberSource card orders were placed on 2026-09-23 from /cart with the same test Visa, the same single line item and the same $200.00 total. Both reached Processing with no 'Pay now' button and no held-for-review note: CO26092300004 (Shipping, Fixed Rate (Ground)) and CO26092300005 (Pickup/BOPIS). Earlier the same day on the same build and the same account, CO26092300001 was left at 'Payment required'. So the held-for-review outcome is a per-transaction decision by CyberSource sandbox fraud screening (Decision Manager), NOT a deterministic property of the build, the processor configuration or the order shape. Consequence for testing: a case that asserts a CyberSource order reaches Processing is inherently flaky, and a case that asserts it stays at Payment required is equally so. The stable assertion is the one either outcome satisfies — the order is CREATED with a CO-number and appears in /account/orders — with the payment status treated as either/or. This does not contradict the existing 'held for review' observation; it bounds it, by showing the other branch occurs on the same build.
