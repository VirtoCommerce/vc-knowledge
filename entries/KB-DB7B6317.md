In the Admin order blade the Status dropdown offers the values of the platform's Order.Status setting (GET /api/platform/settings/Order.Status), sorted, with labels as displayed - so the list differs per deployment: 8 on vcst_qa (Cancelled, Completed, Custom, New, Payment required, Pending, Processing, Ready for pickup - the stored value ReadyForPickup shows as "Ready for pickup"), 7 on vcptcore_qa1 (no Custom) and 5 on vcptcore_stable (Cancelled, Completed, New, Pending, Processing). Processing is listed and settable: selected and saved on a New order it persisted (REST status Processing). The list is scrollable, so a viewport-only look can see one value fewer. A Completed order renders the Status control disabled. Observed live 2026-10-08 on all three.

The storefront relabels statuses for shoppers, so a storefront label need not equal the admin value and the mapping is not always one-to-one (observed earlier, not re-checked). Admin seeding should use a value of the stand's own dictionary; storefront assertions should use the displayed label.
