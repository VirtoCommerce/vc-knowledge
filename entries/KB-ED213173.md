On vcptcore_qa1 (VirtoCommerce.Customer 3.1029.0 release, which predates vc-module-customer PR #321), I created a disposable buyer whose contact belonged to two organizations, A and B. With both active, the password grant with organization_id=A returned 200 and an organization_id claim of A. I then removed A from the contact's organizations. The password grant with organization_id=A still returned 200, now with an organization_id claim of B (fallback). For grant_type=otp_email with a valid code from POST /api/otp/request: organization_id=A returned 400 error=invalid_grant; organization_id=B returned 200 with claim B; omitting organization_id returned 200 with claim B. So on this build the organization fallback applies only to the password grant, and a code sign-in that resends a stale last-used organization fails outright. PR #321 changes the validator to fall back for every credential sign-in (SignInResult set). A refresh_token org switch is meant to keep failing.
