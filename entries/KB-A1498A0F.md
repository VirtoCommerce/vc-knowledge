Created a configuration via POST /api/catalog/products/configurations with options listed in a deliberate order per section. ProductConfigurationOption carries no displayOrder/priority field (entity: SectionId, ProductId, Quantity, Text, IsDefault). Read back via GET /api/catalog/products/configurations/{id} and via Query.productConfiguration, both returned the same order, which matched neither the order sent nor createdDate nor option id ordering, and differed between two fresh seeds of the identical body (e.g. a 2-option section came back reversed in one seed and as-sent in the next). Consequence: a fixture or test must not depend on which option is listed first (e.g. which option a storefront auto-selects for a required Product section without a default); make the property hold for every option instead.
