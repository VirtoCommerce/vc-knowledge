Punchout session on store B2B-store, storefront /cart in punchout mode. The first Create requisition returns the cXML and the storefront posts it to the procurement return URL. After that (session status Returned), every further createPunchoutRequisition by the session owner — a repeated API call with the same token, browser Back then click, a second tab, and a click after the buyer changed the cart — returns errorCode SessionReturned with url, formField and cxml null; nothing is posted (neither the first document nor a new one) and the button is re-enabled. Two parallel calls on an Active session produce exactly one document; the other gets SessionReturned or SessionExpired depending on the race. With store setting Punchout.Enabled off, a returned session gets StoreNotConfigured (the store check runs first), and SessionReturned again once the setting is restored. A password token, an anonymous call, or the session token with another storeId get SessionNotFound. On theme 2.61.0-pr-2564-2fa8 the storefront shows the generic "Could not create the requisition. Please try again." toast for SessionReturned; a dedicated message is added by a later theme commit.
