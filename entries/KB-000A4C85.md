On vcptcore_qa1 a cXML OrderRequest whose ItemOut SupplierPartAuxiliaryID was the cart line id upper-cased was accepted 4 of 4 times in a row (cXML 200, one customer order each), and earlier runs accepted it too; a lower-cased SupplierPartID (SKU) was also accepted and the order created. So both the cart lookup by line ids and the SKU reconcile ignore letter case. A 400 "The order items do not match any cart." seen once for an upper-cased id came from a test that referenced a cart line already consumed by a previous successful order in the same case, not from case sensitivity.
