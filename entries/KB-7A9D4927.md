No. A wishlist's sharing key is the id of its SharingSetting row, and that row exists from the moment the list is created - including for a list created Private, which has a key it never shows. Changing scope through changeWishlist rewrites the scope on that same row and mints nothing: the storefront's List settings dialog shows the same /shared-list/<key> URL before and after, and a key that returned a bare null while the list was Private returns the list's real authorization answer the moment the owner re-scopes it, at the identical link. So switching a list back to Private is a suspension, not a revocation - anyone who ever copied the link regains access the instant the owner shares it again, and there is no control anywhere in the storefront that issues a new key. Deleting the list IS a real revocation: after removeWishlist the same key resolves to null for an anonymous caller. Treat a leaked list link as permanently leaked and delete the list rather than re-scoping it.
