Observed 2026-10-07 with an admin token. POST /api/task-management with a WorkTask body carrying no dueDate (plus name, type, priority, isActive:true, and the responsibleId / organizationId / storeId copied from a task the rep created) returns 200 and persists dueDate:null. Query.salesRepTasks on /graphql/sales-rep, called as that rep, returns the row with dueDate:null, and Mutation.deleteSalesRepTask deletes it. Mutation.createSalesRepTask (rep-scoped GraphQL) requires dueDate, so this REST call is the API path to a dateless task. The swagger WorkTask schema marks dueDate nullable; the REST TaskPriority enum is Lowest, Low, Normal, High, Highest.
