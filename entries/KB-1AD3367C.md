2026-11-04, Firefox, disposable Backoffice managers (mfa:read only; mfa:read+mfa:manage) on a customer's Mode page opened from /apps/admin-shell/#/security/user/{id} (overflow → "MFA: <mode>"). The field is role=combobox, aria-labelledby → label "Mode"; its value is a child text ("Off"). Opened (mfa:manage): listbox "Mode" with options "Off", "Enabled", "Required"; the selected one carries aria-selected=true plus a check-icon span (display:flex) holding an aria-hidden svg. The Playwright MCP AI-mode browser_snapshot (@playwright/mcp 0.0.83) prints that selected option as `option [selected]` with NO name, whichever value is selected, but the same element resolves to getByRole('option', {name: <label>}) and its name returns in the snapshot when the icon span is detached; on static copies of the markup the default ariaSnapshot and Chromium's native AX tree both name it. So the option is named; the gap is the AI snapshot's removeRedundantNames distillation of a non-inline name-contributing child. Separately observed: with mfa:read the combobox is locked (Enter does not open it, no Save/Reset) but exposes no aria-disabled and keeps tabindex=0, so it is a Tab stop announced as an active combobox. AngularJS Mode blade for comparison: the select is named by ui-select's generic "Select box" (not "Mode") and the open list marks no option selected.
