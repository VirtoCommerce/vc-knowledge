vcst 2026-11-04, disposable CustomerChoice store, global MFA off, an organization with a maintainer (confirmed email) and a member (emailConfirmed set false). After the organization was turned on (maintainer updateMfaOrganizationMode enabled=true, and separately admin PUT /api/mfa/modes/organizations/{id} {mode: Enabled}, which answered 200 {mode: Enabled} only), GET /api/mfa/modes/organizations/{id}/status and GET /api/mfa/modes/users/{memberId}/status both answered with keys isGloballyEnabled, isRequiredForBackoffice, userStoreId, stores[], each store row carrying storeId, storeName, storeMode, isRequired, requiredBy, isRequiredByUserStore, isDisabledModeSkipped — for the run store isRequired true, requiredBy Organization. No field names the members, provider availability or email confirmation, while that member's password grant answered 400 mfa_provider_not_available. Source at vc-module-mfa 1a0f481 agrees: MfaStatus/MfaStoreStatus carry only these fields and the Backoffice mode blade renders only them. The only place provider availability appears is the member's OWN mfaSettings.isProviderAvailable (false); the maintainer's mfaSettings reflects only the maintainer.
