On vcptcore_dev (Seo 3.1006.0-alpha.101 PR build for VCST-5989, Catalog 3.1049.0 PR build for catalog#910), GET /api/seoinfos/explain?storeId&storeDefaultLanguage&languageCode&permalink returns a JSON array whose first element is stage 'Candidates', followed by Original, Filtered, Scored, FilteredScore, Ordered, Final; every item has seoInfo, objectTypePriority, score, reasons[] ({code, details}) and isResolved. For a permalink that resolves (category on a Collapsed store) all seven stages hold 1; the Scored item showed score 46 and objectTypePriority 1 for a Category. For a slug shared by four categories in one store+language it returned Candidates 4 (one resolved, three rejected with reason NotBestMatch) but Original 1, so the user guide sentence that Stage 1 'Displays all items from the database, not filtered by store or language' does not hold for the Catalog resolver, which filters by active, store and language in SQL before the pipeline. The Admin widget label is 'Debug SEO' (blade 'Debug SEO links'; stage rows 'Stage 0: Candidates ...'); the Candidates blade has 8 columns: Semantic URL, Resolved, Rejection reasons, Object Type, Object ID, Language, Store, Active. Only permalinks that resolve were used, because the build's explain does not log broken links but this was not tested on an unresolved one.
