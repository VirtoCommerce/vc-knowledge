On 2026-10-20 a Sales Representative with 0 push messages, at 375x812 in Chrome 155 on /company/dashboard, pressed Enter on the header bell. The Notifications popup opened, showing the heading 'Notifications', a 'Show unread only' switch, a three-dots options button, the empty text 'No new notifications at the moment.' and 'View all notifications'. axe-core 4.12.1 (WCAG A/AA tags), run with the popup open, reports button-name critical on 3 nodes. One is the bell itself (see KB-A54BD176). The second is the switch track, button.vc-switch__bg, which has no aria-label. The visible text 'Show unread only' sits on a separate tabindex=-1 label button. The third is the options trigger, button.vc-button--ghost--primary with aria-haspopup=dialog, which holds only a dots-vertical icon. On page load the console warns 'VcSwitch: Switch should have ariaLabel or name for accessibility'. The popup panel itself has no role and no name, although the trigger announces aria-haspopup=dialog. Source, vc-frontend 2.60.0: client-app/modules/push-messages/components/vc-push-messages.vue:25-27 uses VcSwitch with no ariaLabel or name, and :35-36 uses VcButton icon with no aria-label. The same popup component backs the desktop bell, but only 375 px was observed. A defect under BL-A11Y-002, which requires every interactive control to have a contextual accessible name.
