On a cold load of / as an anonymous visitor the storefront issues the GraphQL operation GetStorePlugins (store(domain).plugins(appId:"vc-frontend")). It returned one plugin, id "sales-rep", remote {name:"sales-rep", exposed:"./plugin"}, entry /modules/$(VirtoCommerce.SalesRep)/plugins/vc-frontend/remoteEntry.js, and a `contributions` JSON string with a plugin-level when (setting SalesRep.Enabled of module VirtoCommerce.SalesRep), nine declared Company routes (sales-reps open; hub routes gated on permission sales-rep:access; documents also on sales-rep-documents:read) and one Corporate header menu link. The browser then fetched mf-manifest.json (plugin 0.2.5, requiredHostVersion ^0.2.3, shared singletons vue, vue-router, vue-i18n, @vueuse/core, @apollo/client, @vue/apollo-composable, graphql, @vc-frontend/core), then index js/css, remoteEntry.js, shared-chunk stubs and the en locale chunk, all 200, no console errors. The plugin code was fetched for the anonymous visitor too, because the plugin-level condition checks only the store setting, not the user.
