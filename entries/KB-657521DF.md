With two buyers in one organization, the colleague's token got data.return = null for the other buyer's returns (Requested, Approved, PartiallyApproved), and cancelReturn / updateReturn on the other buyer's Requested return answered 200 with errors[] code RETURN_NOT_FOUND ('Return <id> was not found.'); the return stayed Requested. The storefront /account/returns/:id shows 'This return was not found' and the colleague's /account/returns list is empty ('There are no returns yet'). Buyer availableActions on a return list only edit, submit and cancel; on New, Approved, PartiallyApproved and Cancelled returns all three are isAvailable=false with unavailableReason WRONG_STATUS, and the Mutation type exposes only createReturn, updateReturn, submitReturn and cancelReturn - no decision mutation.
