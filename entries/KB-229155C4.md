On PageBuilderModule 3.1035.0-pr-171-61df: body {storeId, assetUrls[], includePages:true} returns one row per asset {assetUrl, normalizedAssetUrl (store-relative), referencesCount, pageReferencesCount, sharedComponentReferencesCount, pages[{id,name,permalink,cultureName,status}], sharedComponents[{id,name}]}; absolute and store-relative asset URLs both resolve. Pages that are only Draft, whose content was saved via POST /api/page-builder-pages/grouped/{id}/content with an image block {type:'image', image:<absolute asset url>}, were counted on the very next call (no publish, no reindex wait); a shared component created via POST /api/page-builder-shared-components with an image block was counted as sharedComponentReferencesCount. Seeded 1/3/2-page refs (+1 component) were all returned exactly. When folderUrl is sent, the response is a single aggregate row for that folder (assetUrl = the folder) and assetUrls is ignored; a folder lookup on a parent finds a reference 5 levels deeper.
