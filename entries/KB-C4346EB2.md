Placing an order with exactly one product added to the cart produced an order containing TWO line items. The cart page shows a "+ Add a gift" panel below the product table offering a printer with its checkbox ALREADY CHECKED on arrival, a disabled quantity of 1, and no price. Nothing else on the cart reflects it: the product table lists one row, the cart badge reads 1, "Subtotal" is the single product's price, and the GA4 view_cart event reports items_count=1. After Place order, createOrderFromCart returns the gift as a second line item with isGift:true, price $0.00 and a discount from promotion "Auto Gift (no coupon)", and the GA4 purchase event reports items_count=2 with the printer at $0.00, qt1, carrying that promotion. The placed-order page likewise renders the printer in its own "+ Add a gift" panel, outside the product table, so the order's product table and subtotal still show only the one purchased product. The panel offers no visible indication that the item is an applied promotion reward rather than an optional add-on. Net effect: a shopper who never interacts with the gift panel still receives an extra order line, and a check that asserts confirmation line items equal cart line items, or an items[] length, sees an extra row it never added. The stored order record shows the gift line is well-formed: quantity 1, price/placedPrice/extendedPrice all 0, taxTotal 0, isGift=true, a discount of 0 from the promotion; it contributes nothing to money, since the order subtotal is the other line alone and the total reconciles without it. The promotion fires every time because it is active, has no coupons, and its condition tree is everyone plus empty catalog and cart conditions with a gift-item reward, so the backend behaviour is correct per the promotion as configured. It is not specific to one order or to configurable products: a gift line was on 11 of the last 12 orders of the store, across three shoppers and both configured and plain carts. The gift IS visible over the API - GraphQL Query.order items{isGift} returns true for it - so a storefront order page that omits it from the product table is choosing to, not missing the data.
