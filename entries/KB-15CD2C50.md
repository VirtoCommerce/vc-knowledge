B2B-store: GET /api/site-builder/theme/status returns {publication, drafts, newDrafts}; GET /api/site-builder/history/status answered setupRequired, so the designer offers 'Enable history' and no version to restore. Every Publish theme wrote the next number (1 to 12 in one session). Rules, header and footer were put back through the designer, palettes by saving '{}' through POST /api/site-builder/designer/save, and the next publish dropped the palette key from the snapshot. Templates created in the designer cannot be deleted: there is no delete action, and saving a theme file with content null answers 400 'is not a JSON document.' Header and footer groups, once written, stay in the snapshot as default sections.
