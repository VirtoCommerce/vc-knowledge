Admin, platform 3.1087.0-pr-3134-a3d2. ShowMeridian was set to false via POST settings/v2/me/values, the admin then signed in to the Admin SPA (profile loaded with showMeridian false), and ShowMeridian was set back to true via the same REST call (GET confirmed true). After ~20 minutes of normal navigation in that SPA session (workspace changes, menu collapse/expand, language change in User profile), GET settings/v2/me/values returned ShowMeridian false again. The SPA sends POST /api/platform/profiles/currentuser (204), usually twice per workspace navigation, and its request body carries the complete profile (language, regionalFormat, timeAgoSettings, timeSettings.showMeridian, mainMenuState and the full settings array) from the copy the SPA loaded, so a value changed elsewhere after load is written back to the stale one. A full page reload re-reads the profile and stops the overwrite.
