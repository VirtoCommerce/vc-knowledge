Signed in as a freshly created Sales Representative (password grant with storeId B2B-store, token carrying sales-rep:access), the query salesRepTaskTypes on /graphql/sales-rep returned HTTP 200 with ["Registration Review","Order Review","Order Processing","Product Catalog Management","Pricing and Promotions","Content Management","Customer Support","Other","Call"] — exactly the allowedValues of the global TaskManagement.TaskTypes setting read through the admin REST API on the same stand (value null, i.e. the built-in list), in the same order. "Call" is the value the Sales Rep build under test (vc-module-sales-rep PR #26, unreleased) appends at startup. The same token's salesRepCustomers(storeId) returned the rep's two served organizations immediately after the rep was created through POST /api/sales-rep, with no reindex.
