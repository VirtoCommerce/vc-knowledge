On virtostart (VirtoCommerce.Return 3.1005.0) a membership role holding xapi:my_organization:return:view and :submit was added to an Organization maintainer and to a sales rep's membership. Their org-scoped tokens carried both permission claims, and organizationReturns answered. But returnableItems(orderId) for a COLLEAGUE's delivered, returnable, Completed order in the same organization returned [] for both holders, exactly as for a non-holder. So the Request return entry point cannot appear on a colleague's order, and the submit permission has no observable effect on this build. This matches the repo's org-returns fixture, which declares the permission as unchecked (organization returns are read-only). Not tested: createReturn on a colleague's order, a mutation.
