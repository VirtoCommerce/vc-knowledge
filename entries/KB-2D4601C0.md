2026-11-10 20:29Z, administrator token. /health reports "Active background-job engine 'RabbitMQ'". POST /api/background-jobs/enqueue {"name":"SitemapDownloadJobHandler","payload":{}} returned 200 with a 32-hex job id, twice. GET /api/platform/jobs/{id} returned {"state":null,"completed":true} for both from the first poll (~1 min) and never reported Failed. The Hangfire dashboard (/hangfire/jobs/failed) still runs (2 servers, 1 recurring job) and showed Failed 0; the MCP admin tool list_failed_jobs (operator) returned counts failed 0, succeeded equal to the Hangfire dashboard's Succeeded, the 2 Hangfire servers, queues [] and failed_jobs []. So on a RabbitMQ stand the Hangfire-based failed-job recipe (KB-B6A59402: 3 retries then Failed after ~3 min) does not apply, and list_failed_jobs reflects Hangfire storage only. No delete path for the enqueued jobs was found.
