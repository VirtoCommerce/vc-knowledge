Theme 2.62.0-pr-2629 (VCST-5994), Chromium, org user, /account/orders > Filters, Created date = Custom date. Split layout (1440 px): inputs are role=combobox, aria-haspopup=dialog. Before input both have aria-invalid="false" and no aria-describedby. Typing Start 12/31/2026, End 01/01/2026 + Tab: both inputs aria-invalid="true", aria-describedby="date-range-picker-<n>-details", a single div (unique id) whose text is "End date must be on or after start date". Closed calendar: no aria-controls, aria-expanded="false". Clicking 'Open calendar: Start date' sets aria-controls on the Start input to vc-popover-<m> (role=dialog, aria-label Calendar, displayed), aria-expanded="true", describedby kept; the End input stays without aria-controls; Escape removes aria-controls again (same for End). Combined layout (375 px, filters drawer): the inputs are plain textboxes (aria-label Start date / End date) with the same invalid/describedby pair pointing to date-range-input-<n>-details; aria-controls/aria-expanded live on the single 'Open calendar' button (aria-controls only while open). Correcting End to 01/15/2027: aria-invalid goes back to "false" (attribute kept, not removed) and aria-describedby is removed, in both layouts. Same on the sales-rep /company/my-customers/<orgId>/orders Filters.
