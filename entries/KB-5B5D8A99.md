Non-admin Manager, Chromium with a WebAuthn authenticator. Admin Shell /apps/admin-shell/#/login shows 'Sign in with a passkey' first (above 'Continue with Google' and the password form, also at 768px and in Arabic RTL); AngularJS #!/login shows a 'Passkey' link. Both register a key from the profile Sign-in methods blade (POST /api/passkeys 204; row 'Unnamed key', 'Device only · Created <date>'), rename it (PUT, a name with HTML markup renders as literal text), and sign in with it through cookie sign-in POST /api/platform/security/sign-in (204). Deleting the password while one passkey exists is allowed in both (DELETE .../Password/keys/password 204; AngularJS confirm says 'Delete key', Admin Shell says 'Delete your password? ...'), leaving a passkey-only account; the password can be set again from the same blade without an old password. With the passkey as the only key, Admin Shell renders 'Delete: Unnamed key' disabled; AngularJS keeps the trash icon active, the DELETE returns 400 last_sign_in_key 'The last sign-in key cannot be removed.' and the blade shows only '400: Bad request'. Key create/rename/delete leaves no entry in the user's changelog; password delete is logged as 'Password changed'.
