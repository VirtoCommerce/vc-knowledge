On theme 2.60.0-pr-2523-9e4e with Return 3.1005.0-pr-28-62f9, opening /account/returns?scope=organization&page=-1 sent GetOrganizationReturns with after "-20"; the response was errors[0].extensions.code SQL ("Error trying to resolve field 'organizationReturns'") with data null. The page showed the toast 'Something went wrong. Please try again later.' and the empty state 'There are no returns yet'. The own list (/account/returns?page=-1) behaves the same. A page past the end (page=5 with 11 rows) is clamped to the last page, and an unknown sort value is ignored. That held on builds without vc-frontend 59a78b57 (VCST-5884, 2026-10-08, 'read a page below 1 in the link as the first page': useReturns.ts page = Math.max(parseInt(page) || 1, 1)); 9e4e67ef predates it. On 2.60.0-pr-2523-b9a7 (local storefront over the vcst backend, Return 3.1005.0-pr-28-fb4f, 2026-10-13, organization tab, 58 returns) page=-1, 0, -20 and abc each send after "0" and load page 1 with rows, no toast, the URL keeps the invalid value; page=99 first requests after "980" (0 rows) and then the last page (after "50"), rewriting the URL to ?page=6; an unknown sort is sent to the server as is and the list returns without error. PR VirtoCommerce/vc-frontend#2523 is not merged.
