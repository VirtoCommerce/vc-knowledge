Firefox lane, browser loading the deployed plugin chunk sales-rep-tasks-page-Dss09knJ.js, rep serving 5 organizations, every filter applied (2 customers, Status Upcoming, Priorities High + Highest, plus the Due today chip). The search box and the three selects sit inside an element with container-type inline-size (class sales-rep-tasks-page__toolbar-container), so the layout follows that element's width, not the viewport. Measured with read-only geometry (viewport -> container width -> arrangement): 375 -> 327 one select per line; 640 -> 592 one select per line; 768 -> 500 one select per line (the account sidebar appears at 768, so the container is narrower than at 640); 900 -> 632 search alone, three selects on one line below; 1024 -> 740 same; 1100 -> 816 same; 1280 -> 956 search and the three selects on one line; 1920 -> 1144 one line. At every width scrollWidth equalled clientWidth, every select and the last chip ended inside the viewport, and no width showed two selects on a line with the third alone; the arrangement only ever got flatter as the width grew. The step points therefore lie between 592 and 632 px of container (C to B) and between 816 and 956 px (B to A), consistent with about 616 and 868 px. With these filters the chips wrap to 2 lines at 1024-1100 and the 'No tasks match the filters' empty state starts at y=829, below the fold of an 800 px tall window.
