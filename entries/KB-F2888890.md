Multilanguage page with en-US (default), fr-FR (custom permalink) and de-DE published. PUT /api/page-builder-pages/grouped on the fr-FR version with startDate = now + 3 days: within ~6 s pageDocument(en id).alternates lists only de-DE and en-US, and anonymous slugInfo(fr permalink, cultureName fr-FR) returns entityInfo null — no fallback to en-US, unlike a translation hidden by user group or Visibility, whose permalink falls back to the en-US version on the same build. Setting startDate = now - 2 days restores fr-FR in alternates and slugInfo(fr permalink, fr-FR) returns the fr-FR version. Consistent with the resolver searching the permalink only among currently active (published, in date range) documents, so a scheduled version gives no translation group to fall back from.
