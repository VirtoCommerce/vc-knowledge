On vcst_qa (2026-11-26), an Approved association-only contact (contact.organizations = two orgs, 0 rows in organization-memberships/search, empty global roles) was set to status Rejected via full-body PUT /api/contacts (204, re-read Rejected). Password grants to POST /connect/token with storeId=B2B-store and organization_id set to each associated org both returned HTTP 400 error=invalid_grant with errors[0].code user_is_rejected_in_organization ("Your access to organization '<id>' has been rejected. Please contact your organization administrator."). The security account stayed unlocked (lockoutEnd null). After PUT of the original contact body (status Approved) a fresh grant for the same org returned HTTP 200. So a blocking global contact status, with no membership row to override it, denies every org grant, and it is a status denial, not a lockout.
