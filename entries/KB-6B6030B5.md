SalesRep 3.1013.0-pr-18 on platform 3.1076.0, 2026-10-08. With SalesRep.Statistics.TopSellerInvalidateOnChange at its default (false, TTL-only) and TopSeller TTL 60 min, one cookie-less read of a never-read salesRepTopSellers key (organization + period at whole-second resolution) cached it on one instance; the rep then placed an order that moved the figure. 45 later cookie-less reads of the same key returned a persistent MIX: 22 stale (pre-order, empty list) and 23 fresh (the new units), interleaved, while every never-read twin key returned the fresh value. So there are >=2 instances with independent memory caches and requests without an affinity cookie are distributed roughly evenly between them. Response latency does NOT identify the instance or a cache hit: hit and miss reads both ran ~180-300 ms with baselines drifting between runs. Every cookie-less response sets a new INGRESSCOOKIE value; its part after '|' is identical on all responses, so the cookie value itself does not name the instance. Consequence for cache-freshness tests: a single-read warm-up warms one instance only; warm with >=20 cookie-less reads before judging cross-instance eviction.
