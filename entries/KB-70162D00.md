Read in vc-module-background-jobs source (Module.cs, RabbitMqOptions.cs at 5e5c330): Module.cs says all background-job configuration (provider, mode, default queue, retries) is read from VirtoCommerce:BackgroundJobs at startup; RabbitMqOptions is bound from VirtoCommerce:RabbitMQ with HostName (default localhost), Port 5672, UserName/Password (default guest), VirtualHost "/", an optional Uri (amqp://user:pass@host:port/) that takes precedence over the separate fields, ManagementUri, Queues, UseDeadLetterQueue, DeadLetterQueueSuffix ".dlq", RetryDelaySeconds 5, PrefetchCount/ConsumerDispatchConcurrency auto-scaled when 0. EnableLegacyHangfire defaults to true, so Hangfire storage and the /hangfire dashboard keep running under the RabbitMQ engine. The VirtoOZ appsettings.json reference documents the selector as a top-level BackgroundJobs node, which does not match the source; a stand that sets VirtoCommerce__BackgroundJobs__Provider=RabbitMQ reports "Active background-job engine 'RabbitMQ'" in its health check.
