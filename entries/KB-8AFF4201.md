Hangfire engine (BackgroundJobs /health). The global setting was unset (value null, default true). I set ProductSubscription.Scheduler.Enabled=false through POST /api/platform/settings at 17:43:42Z. GET /api/background-jobs/recurring then showed ProductSubscription.RenewalScheduler enabled=false, nextRunUtc=null. I made an Active subscription due by setting its nextOrderDate to tomorrow (PUT subscriptions/{id}; reminder lead is 3 days). The 17:45 and 17:50 ticks passed and no renewal was created: renewals/search was unchanged and nobody ran the scheduler by hand. I set Enabled=true at 17:52:24Z with no restart. The recurring view went back to enabled=true, nextRunUtc 17:55. At 17:55:12Z the tick created the renewal with createdBy/modifiedBy "system:ProductSubscription.RenewalScheduler"; manual scheduler/run renewals carry the caller's login instead. Because the scheduled date was inside the 24h cutoff, the renewal ran Scheduled > Notified (reminder) > Ordered > Authorized within about 2 s of one tick, and the subscription's nextOrderDate moved one interval ahead. With Enabled=false, POST /api/product-subscription/scheduler/run still answered 200 {"processed":0}; nothing was due, so this does not show whether the manual run honours the flag. POST renewals/{id}/cancel on the Authorized renewal returned 400 "This renewal can no longer be cancelled: the order has been placed."
