Published page with permalink '/agent-test-6443-4a%20pct' (visibility on). Opening http://<storefront>/agent-test-6443-4a%20pct: GetPageContext sends permalink 'agent-test-6443-4a%20pct' and its slugInfo DOES match the page, but the router then sends GetSlugInfo with the decoded 'agent-test-6443-4a pct', gets entityInfo null and renders '404 Page not found'. The page renders only at the double-encoded URL /agent-test-6443-4a%2520pct. A Cyrillic permalink works the other way round: the browser encodes the path, GetPageContext sends the encoded form (miss), GetSlugInfo sends the decoded Cyrillic (hit), and the page renders. xAPI slugInfo matches only the stored raw string (with or without the leading slash); encoded Cyrillic, decoded '%20' and '%2520' forms all return null.
