On theme 2.62.0-pr-2622-caac275a (before PR #2424), a personal user (no organization) selected one of two address-book addresses in the header Ship to popover with one line in the cart, then deleted it on /account/addresses (Actions > Delete > OK). Right after the delete the header Ship to still showed the deleted address in the same tab (stale in-memory list); after a reload it read "Select address". In both cases /cart still showed the deleted address as Shipping address and billing "Same as shipping address". Server side: currentCustomerAddresses with ids = the deleted id returned totalCount 0 with no errors; Contact.selectedAddressId kept the deleted id; the cart shipment deliveryAddress is a copy with its own id different from the address-book id and was not touched by the delete. So the checkout side of the behaviour predates PR #2424; only the same-tab header differs (old build kept showing the stale address, 2.62.0-pr-2424 shows "Select address" at once). Source read of vc-frontend main: removeAddresses in useCustomerAddresses only calls deleteMemberAddresses and refetches the list; selectAddress in useShipToLocation copies the address into the cart shipment with updateShipment, so the two stores are never reconciled on delete.
