Sent POST /connect/token (form-encoded, grant_type=password, username, password) for the platform admin account, once without extra fields and once with storeId + scope=offline_access: both returned 200 with an access token, so storeId is not required for an admin. With the username replaced by a non-existent string (an unexpanded "${env:ADMIN}" placeholder) and the same correct password, both variants returned HTTP 400 with JSON {"error":"invalid_grant","code":"login_failed","errorDescription":"Login attempt failed. Please check your credentials.","errors":[{"code":"login_failed",…}],"userId":null,"lockoutSecondsRemaining":null,"accessToken":null}. The 400 does not distinguish an unknown user from a wrong password, so a 400 here means credentials, never a missing storeId.
