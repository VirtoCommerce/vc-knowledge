A Sales Representative served organizations X and Y and had X selected (storefront token minted with organization_id=X). An admin sent PUT /api/sales-rep without X, which deleted the rep's X membership (REST: one membership left, contact.organizations = [Y]). With the same access token, 6 s and 3 min later, Query.me returned the rep (HTTP 200) with contact.organizationId = X, contact.organization = X (name resolved), and contact.organizations totalCount 1 listing only Y; Query.organization(id: X) in the same session answered errors[0].extensions.code = Forbidden, message "Access denied.", data.organization null. The storefront pageContext request returned the same contact shape. Source (vc-module-profile-experience-api 3.1021.0, ContactType): organizationId and organization resolve context.GetCurrentOrganizationId(), i.e. the principal's organization_id claim, after only an is-current-user check, so they echo the token rather than the memberships; ProfileAuthorizationHandler denies organization(id) when contact.Organizations does not contain it. Consequence: until the access token expires, clients are told the current organization is one they cannot read.
