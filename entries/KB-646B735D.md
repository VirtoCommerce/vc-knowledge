On store B2B-store (virtual catalog with 54 own and 19 linked physical root categories), Catalog.Search.EventBasedIndexation.Enable=false and the Category index last built weeks earlier. Two physical root categories created by a seeder today and linked into the virtual catalog (REST GET /api/catalog/categories/{id} returns them, with an outline under the virtual catalog) are absent from the index (GET /api/search/indexes/index/Category/{id} returns []). For them Query.category(storeId,id), Query.categories(categoryIds) and Query.categories(query) return null / 0 for anonymous and signed-in users, and the product-comparison module's compareList.categories[].category is null (HTTP 200, no errors[]) because it loads through XCatalog LoadCategoryQuery, which searches the Category index (SearchCategoryQueryHandler). The other 71 root categories, including 17 linked physical ones, are in the index and all resolve: xAPI resolution matched index presence for 73 of 73. Being linked is not the cause; a category created with event-based indexation off stays null until the Category documents are indexed. The products themselves resolve if the Product index was updated.
