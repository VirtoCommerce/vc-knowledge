On 2026-10-09 11:17 to 11:23Z, a buyer token built 13 fresh named carts through xAPI. Each cart held one in-stock product priced at $2, used FixedRate/Ground shipping and DefaultManualPaymentMethod, and the buyer's own address. Each call was timed client-side from request send to the end of the body read, over a warm keep-alive connection. createOrderFromCart took 8153, 9015, 3684, 2197, 821 / 5015, 4855, 1258, 1692, 717 / 1330, 3023, 3842 ms across three batches: median about 3.0 s, max 9.0 s, none under 500 ms. The `me { id }` control in the same session took 128 to 461 ms, typically about 140. A `cart(cartName)` read took 188 to 1869 ms, median about 940. addOrUpdateCartShipment took 0.6 to 3.3 s. There was no clean cold-start pattern: batch 3 rose from 1.3 s to 3.8 s. Every order returned status New with no errors[]. Stand versions: platform 3.1076.0, XCart 3.1040.0-pr-149, XOrder 3.1015.0-pr-55, FileExperienceApi 3.1007.0-pr-25, Xapi 3.1026.0. Other agents were driving browsers on the same stand during the window, so concurrent load is a confounder. BL-GQL-002 sets thresholds for queries only, not for mutations.
