As a user with IT Platform Operator, tools/call restart_platform {reason} returned {status:pending_approval, change_id, expires_at = +72 h}; /health stayed 200. get_pending_change showed preview.dry_run true, change state running -> will restart, and a warning naming the requesting instance of 2. As a second user with mcp:approve, Admin Shell #/mcp-approvals showed the change with a Now/After table; Reject plus the dialog "Reject this change? It will never run." set status Rejected, Reviewed by = that user, with the comment. The requester's get_pending_change then returned status Rejected, reviewed_by, reviewed_at, review_comment. The back-office reject is audited as reject_pending_change with client "back-office". In #/mcp-audit the restart call shows outcome "Waiting for approval", user, client, scope, duration, a trace id and an "Open the change" link. The search box "Tool name or trace id" filters by tool name (6 restart_platform rows) and by trace id (1 row). approve_pending_change over MCP, with initialize capabilities elicitation {} or {form:{}}, returns isError "this MCP client cannot ask the user, so nothing was done", audited "Declined by the user", and points to a menu "MCP > Pending changes" that does not exist (the menu is Agent approvals). REST POST /api/mcp/pending-changes/{id}/approve with an agent token gives 403 "An AI agent cannot review pending changes here" with the same wrong menu name.
