Chromium, 1920x1080, guest. On /sign-in (password form), /sign-up (personal and company account) and the Ship to > New address dialog, every required VcInput is an input with aria-label equal to the visible label text (Email, Password, First name, Company name, ZIP / Postal code, City, Address...) and a bound label element (label for=input id) whose text ends in a span.vc-label__asterisk. Because aria-label wins over the label, the ARIA accessible name never contained the asterisk on either build. Theme 2.62.0-pr-2622 (vcst storefront): inputs carry no required and no aria-required attribute, and the asterisk span has no aria-hidden, so required state is not exposed. Theme 2.62.0-pr-2586 (the VCST-6215 fix, served locally against the same backend): the same inputs carry aria-required=true, still no native required, and the asterisk span carries aria-hidden=true while staying visible (inline, visibility visible, 6x19 px). The Country combobox in the address dialog carries aria-required=true on both builds. On both builds an empty submit of /sign-in shows 'This field is required' under each field (aria-invalid=true, aria-describedby to the message), no native :invalid state and no browser validation bubble.
