Signed in as an organization maintainer on /company/info, I changed localStorage 'auth' (the vueuse useLocalStorage ref of useAuth) and dispatched a storage event so the in-memory ref followed. Two cases: access_token set to a non-JWT string, and access_token set to null (no Authorization header). Then I switched the addresses table page. Both GetCurrentOrganizationAddresses requests returned HTTP 200 with errors[{message 'Access denied.', extensions.code 'Forbidden'}] and data.currentOrganizationAddresses null. No 401 and no 'Unauthorized' code, so the storefront emitted forbiddenEvent and routed to /403 ('Access denied') without re-fetching the user. Only the refresh path emits unauthorizedErrorEvent: expires_at in the past plus an invalid refresh_token makes POST /connect/token answer 400 invalid_grant ('The specified refresh token is invalid.', OpenIddict ID2003). useAuth.refresh() then resets the tokens and emits unauthorizedErrorEvent, and me re-fetches as Anonymous. That is the way to simulate a dead session client-side. Seen with theme builds 2.62.0-pr-2620 and 2.62.0-pr-2647 on the same backend.
