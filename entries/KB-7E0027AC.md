In vc-module-punchout at a79b841 (PR #6 head), PunchoutOrderRequestProcessor resolves the requisition session either by the session id from SupplierPartAuxiliaryID (GetReturnedSessionAsync: status Returned AND session.StoreId = configuration.StoreId AND session.ConfigurationId = configuration.Id AND session.UserId = mapping.UserId) or, without one, as the latest Returned session for (StoreId, ConfigurationId, UserId) (FindReturnedSessionAsync, sorted by ModifiedDate desc). None found → cXML 400 "No punchout requisition was returned for the order." The module has no REST endpoint or admin UI that lists, deletes or resets PunchoutSession rows, and Returned is terminal. So a buyer that has returned a requisition on a configuration keeps that state; the only way to get a mapped buyer with no Returned session is a new user id, e.g. delete and recreate the account and mapping. Deactivating or editing the mapping does not help, because the session is keyed by user id, not by mapping.
