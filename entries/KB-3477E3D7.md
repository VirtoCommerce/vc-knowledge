Mission with an en-US (and alternate) translation only. Query.loyaltyMissionProgress (operation GetLoyaltyMissionProgress, storeId B2B-store) with cultureName en-US returned localizedName = the en text and the en description; the same call with cultureName fr-FR returned localizedName = the internal Name field and description null, no errors[]. /account/missions in French therefore shows the internal name and no description in the modal. Source (vc-module-loyalty LoyaltyUserMissionType, identical 3.1009.0 to dev): localizedName = LocalizedName.GetValue(culture) ?? Name; description = Description.GetValue(culture) with no fallback. The storefront renders what xAPI returns. The docs do not say whether a default-language fallback is expected.
