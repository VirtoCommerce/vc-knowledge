Customer persona (ACME_BUYER), two password grants with storeId=B2B-store: Token-A and Token-B. Before the change both answered 403 on GET /api/platform/security/users (accepted, not permitted). Token-A called Mutation.changePassword (command: userId, oldPassword, newPassword; no sessionGroupId) -> 200, succeeded=true. Immediately afterwards both Token-A and Token-B answered 401 on GET /api/platform/security/users and stayed 401 for 30 s. So every session of the user is terminated, the caller's too when no SessionGroupId is passed (source: ChangePasswordCommandHandler.TryTerminateUserSessions excludes only command.SessionGroupId, VCST-4576). Probe trap: GET /api/platform/security/currentuser is AllowAnonymous and returns 200 for a revoked token, and xAPI Query.me still returns an id for it, so neither shows revocation; use an [Authorize] REST endpoint (403 vs 401) or a protected xAPI query such as Query.orders (Unauthorized). The platform REST change-password endpoint answers 403 for a customer.
