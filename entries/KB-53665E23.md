The Vendor Portal's API calls are authenticated by HttpOnly identity cookies, not only by the bearer data it keeps in local storage: document.cookie reads empty, corrupting the local-storage auth entry changes nothing and calls still return 200, and only clearing the cookies produces 401. No client-side change produces a 403, and /Account/Login, /account/login and /Account/AccessDenied return 404 while /connect/authorize returns 400, so session-expiry paths cannot be reached naturally.
