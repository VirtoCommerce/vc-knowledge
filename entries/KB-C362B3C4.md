Docs (Configuration-Reference/appsettingsjson) give QueryIgnoreSubstrings default [HangFire]., sp_getapplock, sp_releaseapplock; the stand sets no override. Over 7 idle overnight hours the new build recorded 246 916 SQL dependencies, of which 230 370 contain '[HangFire].' (mostly 'update top (?) JQ set FetchedAt ... from [HangFire].JobQueue') and 3 327 contain sp_getapplock/sp_releaseapplock. The previous build (SDK 2.23.0) recorded 34 225 SQL dependency rows over the same hours, none with Hangfire statement text. Result: ~7x dependency volume and matching ingestion cost on an idle stand.
