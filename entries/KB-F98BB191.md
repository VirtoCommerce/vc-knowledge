On vcst_qa 2026-11-27 (platform 3.1101.0, WhiteLabeling 3.1008.0) Query.whiteLabelingSettings(organizationId: "WL-ORG-A", storeId: "B2B-store", cultureName: "en-US") with an admin token returned HTTP 200, no errors[], and the store's own branding (store logo, Mercury preset, the store's footer and main-menu link lists); with the real organization GUID the same call returned the organization's logo, Watermelon preset, its own footer and main menu. So a wrong organizationId is silent and looks like a valid store-level answer: a case that passes a fixture key instead of the GUID reads the store's branding and fails (or vacuously passes) with no hint. The domain map's "invalid organizationId returns null fields" does not hold for this build.
