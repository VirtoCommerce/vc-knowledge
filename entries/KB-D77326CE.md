On a vc-frontend-next build served locally against the vcst_qa backend, signing in with password on /sign-in for an account whose lockout is active returned HTTP 400 from POST /connect/token; the form showed the alert 'Your account has been temporarily locked. Please try again later.' and, at the same time, a global notification toast 'Something went wrong. Please try again later.' The header kept the 'Sign in' link. A deep link to /account/dashboard then redirected to /sign-in?returnUrl=/account/dashboard and the page sent no GetOrderStatistics, GetOrders or GetLayout request (only GetStorePlugins, GetPageContext, GetShortCart, GetCategory, GetMenu, GetPasskeyRequestOptions). The same alert+toast pair appeared for a second account that was locked out.
