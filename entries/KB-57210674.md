As a sales rep with a password grant carrying storeId and organization_id (the served org), addItem with a custom cartName created a named cart stamped with that organizationId. Two different products were added (qty 3 and qty 7), then unSelectCartItems took the qty-7 line out of checkout. salesRepCustomerCartStatistics(organizationId=<that org>, currencyCode USD) period(from 2000-01-01, to tomorrow) then returned selectedItemQuantity 3, unselectedItemQuantity 7, count 1, total = 267 = the selected line's extended price only (cart.subTotal 267; the unselected line's 175 was not included). The no-organizationId roll-up rose by the same 3 / 7. removeCart dropped the org back to 0/0/0 on the very next read, and re-adding restored 3/7 immediately, so no cache delay was seen. So a named cart is a valid seedable fixture for the selected/not-selected split; storefront flows (default cart) do not touch it. The same query on this build takes period(from,to)/comparison(current,previous) arguments, not a cartFilter argument.
