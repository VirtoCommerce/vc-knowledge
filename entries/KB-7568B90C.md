The order of the fields does not change while the admin toggles modes or checkboxes. In Exact mode with zero fields selected Save is disabled. Reset restores the saved selection and mode and disables Save. Closing the blade with unsaved changes opens a 'Save changes' dialog (Yes / No); No discards. Closing while the form is dirty AND invalid (Exact, zero fields) opens a different 'Warning - Validation failed for this object. Will you continue editing and save later?' dialog; No closes the blade without saving. After toggling the mode away and back, Save stays enabled although the form equals the saved state.

Re-observed live 2026-10-08 on vcst_qa (Catalog 3.1048.0) and vcptcore_qa1 (Catalog 3.1049.0-pr-910): toggling fields and switching Exact -> Full-text -> Exact leave every row where it was and keep the checked boxes; Exact with no field checked disables Save; Reset returns to the saved mode, hides the checklist and disables Save; closing with unsaved changes opens "Save changes" ("The barcode scanner settings have been modified. Do you want to save the changes?", Yes / No) and No discards. Closing while the form is dirty AND invalid (Exact with zero fields, after another change) opens a different dialog, "Warning" - "Validation failed for this object. Will you continue editing and save later?" (Yes / No); No closes the blade without saving. With the saved state Full-text and no fields, toggling to Exact and back to Full-text disables Save again.
