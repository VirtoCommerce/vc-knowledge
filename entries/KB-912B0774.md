Signed-in buyer, store default en-US. On /fr/<slug> the visitor picks English in the language selector: the app loads /<slug> (or the translation permalink for a multilanguage page) with en-US content. Browser Back then returns to /fr/<slug> without a reload; the html lang stays en-US, GetSlugInfo is sent with permalink 'fr/<slug>' and cultureName en-US, slugInfo is empty and the 404 view renders at HTTP 200. Reproduced on a multilanguage Page Builder page, a plain landing, a PDP, a category, /catalog and /search?q=... A reload of the same URL renders the French page correctly. When the target language is non-default (nl-NL -> nl-BL) Back lands on an intermediate /nl-BL/<previous permalink> entry and renders nl-BL content instead. On a stand running theme 2.61.0-pr-2570 (without the language-selector rework) Back from /sv/catalog lands on /catalog and is redirected to /sv/catalog without a 404.
