On ImageTools 3.1006.1 (same code at 3.1003.1), I ran a task with workPath containing 5 .jpg images (1600x898) and 1 .png through POST /api/image/thumbnails/tasks/run with regenerate=true. Every PNG thumbnail was produced (100/300/800, FixedWidth, FixedHeight, Crop), but no .jpg thumbnail was, and the notification read 'Thumbnails generated successfully!' with total 0. In the source, AllowedImageFormatsService.IsAllowedAsync returns allowedValues.Any(x => x.EqualsIgnoreCase(extension)), where allowedValues is ['JPEG','PNG','Webp','SVG'] and extension is 'jpg'. RasterImageFormat.Jpeg already maps the extensions jpg/jpeg/jfif, but that mapping is not used here. Uploading .jpeg or .jfif to POST /api/assets returns 405 'File extension .jpeg is not allowed', so an admin cannot work around it. On this stand the newest catalog *_64x64/_sm/... .jpg thumbnail dates from 2025-11-25, while .webp thumbnails were generated in 2026. The docs (thumbnails/generating-thumbnails) list JPEG as supported and use a .jpg example.
