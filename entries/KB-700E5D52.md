The Return module permission set is return:access, read, create, update, delete, authorize (platform:access does not exist on this build). A Manager account (isAdministrator=false) whose role holds return:access + return:read + return:update signs in, gets 200 on POST /api/return/search, and gets 403 on POST /api/return/{id}/authorize (body ReturnAuthorizationRequest {returnId, rejectReason, items[] of ReturnLineDecision {lineItemId, approvedQuantity, rejectReason}}). Probed with a nonexistent id, so the gate runs before the handler. Observed on VirtoCommerce.Return 3.1003.0-pr-27-51fc.
