---
By default the platform validates access tokens statelessly (Authorization EnablePersistentStorageTokenValidation is false), so neither logout nor POST /revoke/token invalidates an access token already issued - it keeps working until its lifetime ends. Refresh-token reuse after revocation does fail with 400 invalid_grant. /connect/revocation returns 404 because it is not an endpoint; discovery advertises no revocation endpoint. Immediate invalidation is an operations setting (enable persistent-storage validation or shorten the access-token lifetime), not a code defect.
