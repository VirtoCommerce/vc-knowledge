2026-10-21, admin token, DefaultManualPaymentMethod. After a Processed refund with transactionId T, POST /api/order/payments/payment/refund with the same T returns HTTP 200 {succeeded:false, errorCode:PAYMENT_FAILED, errorMessage:'An error occurred while saving the entity changes. See the inner exception for details.'} and creates no refund -- for both an over-limit amount (200 vs 65 remaining) and after a full refund. The same requests with a new transactionId succeed (Processed), including the over-refunds. PaymentFlowService.CreateRefundDocument only reuses a refund with that transactionId when it is NOT Processed, so it inserts a second refund with a duplicate TransactionId and the save fails. A negative refund test that reuses one transactionId therefore passes for the wrong reason.
