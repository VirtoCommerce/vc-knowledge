On the VCST-5989 PR build (Seo 3.1006.0-alpha.101, Catalog 3.1049.0-pr-910), broken links were read per permalink and store with POST /api/seo/broken-links/search (keyword + storeId, exact-permalink match) before any Debug. Then the Admin tool (Stores > store > widget Debug SEO > Debug SEO links) and REST explain were run on 16 permalinks across three stores: unknown slugs, never-used random slugs, a nested slug requested bare, a path under a never-used parent, records rejected for store/language/activity, and resolving ones. Re-read 3.5 minutes after the last Debug: no new record and no HitCount change for any of them. In the same window slugInfo for a never-used permalink did create a record within seconds, so recording itself was working. Explain uses the resolvers' candidate path and publishes no SeoInfoNotFoundEvent.
