On Platform 3.1076.1 with BackgroundJobs 3.1052.0, read about 6 hours after the 13:57 UTC platform start. Every overridden setting-driven job ran on its setting's default in Hangfire. IndexChangesJob was 0/5 (setting 0/8). ProcessSubscriptionJob was 0/5 (setting daily 0 0 1/1 * *). ProcessSubscriptionOrdersJob was 0/15 * (setting 0/15 0 1/1 * *). DeleteObsoleteCartsJob.Process was absent from Hangfire although Cart.EnableDeleteObsoleteCarts=true (default false). GET /api/background-jobs/recurring, which uses the same RecurringScheduleResolver as the applier, returned the configured values. Jobs whose settings hold defaults matched. RecurringJobsApplier applies schedules once at start (hosted service) and afterwards only on ObjectSettingChangedEvent, so a schedule resolved wrongly at start persists until the setting changes or the platform restarts. Cause of the default reads at start is not confirmed.
