Read as an administrator with a bearer token on a stand running VirtoCommerce.AdminShell 3.1000.0-pr-1-f481. GET /api/admin-shell/menu answered 200 with an object {sections[], personalization, pinned, recent, hidden}. It had 7 sections (dashboard, catalog, orders, marketing, insights, configuration, apps) and 55 items. Targets were vue 43, app 9, url 3, and 0 legacy primaries. 21 Vue items carry a `fallback` of type legacy, so the AngularJS screen sits behind the Vue item instead of being the menu target. Replaced legacy items show up as aliases, e.g. orders.aliases=["legacy.orders"] and stores.aliases=["legacy.stores"]. The Menu Editor is item platform.menu in the group "Monitoring & Tools", with permission admin-shell:menu:manage. Without a token the endpoint returned 401. POST to the same path is what the host sends at boot to submit browser-discovered blades. It is not a second way to read the menu.
