A non-admin Manager held a second session from a password grant (access + refresh token, no storeId). Deleting the user's passkey from the back-office Sign-in methods blade (REST DELETE .../sign-in-methods/Passkey/keys/{id} -> 204) made the second access token unusable (GET currentuser/sign-in-methods -> 401; GET currentuser -> 200 with an empty object) and the refresh_token grant -> 400 invalid_grant. The browser session that made the delete stayed signed in after a full page reload (AngularJS cookie session and Admin Shell cookie session alike). Seen twice, on two accounts, from both admin UIs.
