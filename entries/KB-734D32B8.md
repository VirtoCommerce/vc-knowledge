On vcst_qa (storefront theme 2.63.0-alpha.2681; the env's deploy config carries no StoreAssets KnownAssetHosts key), B2B-store's Store asset URL was set in the Admin SPA store blade (PUT /api/stores 204) to a non-resolving test host. Immediately, with no reindex, Query.products on /catalog returned imgSrc and images[].url on that host for every image (16/16 imgSrc, 34/34 url), keeping the original path: images normally served from other Virto platform hosts (/cms-content/assets/catalog/...) AND images normally on the third-party host ae01.alicdn.com (/kf/...) alike. The PDP product query and gallery did the same. The header theme logo (/cms-content/assets/customization/...) was NOT rewritten and kept loading 200 from the platform host. Clearing the field and saving again restored the original hosts on the next page load. So without KnownAssetHosts the rewrite does not distinguish platform assets from external ones.
