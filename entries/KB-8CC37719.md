With the token of a sales rep whose user is bound to store B2B-store and who serves one organization, Query.salesRepCoupons(storeId: <a second existing store>) returned that store's public promotion coupon (totalCount 1, created for the probe), and storeId: "" returned the union of all stores' listable coupons (one more than storeId=B2B-store). The same token on Query.promotionCoupons with the second store or with "" returned the error "Access denied." A non-existent store id returned an empty list, no error. Both /graphql and /graphql/sales-rep behaved the same. In the handler source the storeId is copied straight into the promotion search criteria; the only gate is at least one granting org membership.
