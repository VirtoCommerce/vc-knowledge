2026-10-06, x-cart 3.1038.0-pr-141-b404 + sales-rep 3.1012.0-pr-21-8964 (registry-based sharing scopes). A list carries an OrganizationId only while its sharing scope is Organization (switching Organization -> Private removes it from org-mates' Organization view and makes wishlist(listId) Forbidden for them). With no scope argument, wishlists returns the caller's own lists plus lists of the caller's current organization (Organization-scope lists of org-mates appear with isOwner false, access Write). scope "Private" returns only the caller's own lists with no OrganizationId, i.e. Private AND AnyoneAnonymous AND Customer lists (it is not a filter on the Private scope). scope "Organization" returns only the org's Organization-scope lists (own and org-mates'), without the caller's own non-org lists. scope "Customer" behaves exactly like "Private" (OrganizationId null): for a sales rep it returned the rep's Customer list plus the rep's Private lists, not only Customer lists; for a buyer it returned the buyer's own non-org lists. A member of a Customer share's target org does NOT get that list from wishlists with any scope value. Values "AnyoneAnonymous", "AnyoneAuthorized", "User", "Foo" and "" do not narrow (same result as no argument), no error. Lower-case "organization" / "customer" narrow exactly like the canonical names. All responses HTTP 200, no errors[].
