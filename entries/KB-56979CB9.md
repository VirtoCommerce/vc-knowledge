Placed a real order on the storefront and read window.dataLayer on the confirmation page. Exactly one `purchase` event fired, with transaction_id = 9facd49a-dfdc-4480-9800-ca5cb50ad9b9 — the order GUID — while the confirmation page displayed order number CO26092200001. value, currency and items[] were all correct, and a page refresh fired no second event. This matches the shipped source: vc-frontend client-app/modules/google-analytics/events.ts `purchase()` sets `transaction_id: order.id` (and `placeOrder()` does the same), so the GUID is by design, not a defect. Consequence for test authors: an assertion that transaction_id equals the human-readable order number is wrong and will fail on a healthy build — BL-CROSS-005 correctly says "order ID". Consequence for reporting: GA4 transactions cannot be reconciled against order numbers without a join.
