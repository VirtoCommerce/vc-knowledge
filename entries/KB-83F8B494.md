On vcst_qa (2026-11-09), REST POST /api/catalog/search/products shows the catalog product field `vendor` holds a member id, a free-text name ("QA", "Cisco Systems" from repo seeders) or null. xAPI Query.products returns vendor {id name} only when that id resolves to a Member; it resolves for a Vendor member (Decathlon: codes 895012, 9fb9c34b95b24c6094cab9b7b991ff62) and also for an Organization member (VirtoCommerce1: JEX-60639126, LG55EG9600). Most GUIDs in the catalog (e.g. on Canon 566903892) do not resolve to any member, so vendor is null and the storefront cart groups the line under "Vendor: N/A". Repo seeders write vendor: 'QA' (a string, not a member id), so seeded products always land in N/A. For a multi-vendor cart on vcst_qa, use the Decathlon and VirtoCommerce1 products above together with any N/A product.
