On a stand with Orders 3.1018 / XOrder 3.1014, a Customer user whose contact has a current organization had two orders in POST /api/order/customerOrders/search filtered by customerId: one created through the storefront (organizationId = the user's org, status New) and one created through admin REST with organizationId null (status Completed). Signed in as that user, Query.orders (first:5) returned only the org-attributed order (totalCount 1) and orders(filter:"status:Completed") returned none, although the CustomerOrder index had run after the order's last modification. So an order created over REST for an org member must carry the member's organizationId to appear in the buyer's order list; a test that captures a purchased product from Query.orders gets nothing otherwise. Observation only; the filter source was not read.
