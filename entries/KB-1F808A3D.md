Store 3.1010.0-pr-186-87fa, Seo 3.1007.0-pr-24-9025, Platform 3.1077.0-pr-3123-6664, 2026-10-13. Temp store with no SEO: Stores > store > SEO widget > Add (en-US, slug) > OK > store Save (PUT /api/stores 204, then exactly one GET /api/stores/{id}); kept the SEO list open, selected the row checkbox > Delete > Yes: row disappears AND store Save/Reset become enabled; Save > PUT 204 and GET /api/stores/{id} returns seoInfos []; reopening the SEO widget shows No data. Repeated 3/3, plus add>Save>add>Save>delete one>Save (remaining record intact, deletes persist), Reset after delete (row reappears in the open SEO list, no request, server unchanged), and slug edit after Save (same seo id, new slug persisted). Supersedes the pre-fix behaviour recorded for Store 3.1009.0 (Save stayed disabled). Trade-off of the fix: store Save refreshes every open child blade (settings/payment/shipping each reload once), so an unsaved edit in an open store Settings blade is silently discarded on store Save.
