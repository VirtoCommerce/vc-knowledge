Theme build 2.61.0-pr-2458-3f0b sets module_federation_enabled=true and sales_rep_builtin_enabled=false, so the hub is no longer in the theme. The platform lists the plugin via store.plugins(appId:"vc-frontend") (sales-rep 3.1015.0-pr-15-e5bc, entry /modules/$(VirtoCommerce.SalesRep)/plugins/vc-frontend/remoteEntry.js; the literal $(...) is the platform's module folder name). The storefront requests mf-manifest.json, remoteEntry.js and plugin.json from its own origin. On vcptcore_qa the storefront host has no `/modules -> platform` path in vc-deploy-dev infra/environments.yml: all three return 404 from nginx, while the platform host returns 200 application/json. A signed-in plain rep then gets "404 Page not found" on /company/activities and /company/my-customers, and the account menu has no Sales Rep entries. On vcst_qa, whose storefront host declares `- path: /modules / route: platform`, the same files return 200 application/json. vc-frontend core/federation/scenarios/s6-enable-on-an-environment.md step 3 names this route as the environment requirement. Before the hub moved (theme builds without the switch), the missing route had no effect.
