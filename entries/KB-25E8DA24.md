Storefront, store B2B-store, a disposable customer with a passkey registered under its password session, then admin POST /api/platform/security/users/{userName}/resetpassword {forcePasswordChangeOnNextSignIn:true}; the admin user record reads passwordExpired=true throughout. Passkey sign-in ("Sign in with Passkey", POST /connect/token grant_type=passkey) 3 times in a row and email-code sign-in (POST /api/otp/request, then POST /connect/token grant_type=otp_email) 3 times in a row: every time the browser lands on the home page, not /change-password; the page's GetPageContext user.passwordExpired and forcePasswordChange are false; GetShortCart (Query.cart) answers with no errors; Query.me with the same session token answers passwordExpired false. The control in the same account, a password sign-in, still lands on /change-password?returnUrl=/ with passwordExpired true and Query.cart errors[].code PasswordExpired. So the expiry is enforced only on a password sign-in, as BL-AUTH-018 requires (fixed by vc-platform#3154, VCST-6630). Read passwordExpired from the session, never from the admin user record, which stays true on every path.
