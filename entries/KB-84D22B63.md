Catalog 3.1051.0. Created physical catalogs A (category CA) and B (category CB). POST /api/catalog/products {catalogId: B, categoryId: CA} returned 200 with no validation error; GET returned catalogId = B, categoryId = CA. Also created one product in CB and one at B's root (categoryId null). DELETE /api/catalog/catalogs/{B} returned 500 "The DELETE statement conflicted with the REFERENCE constraint FK_Item_Catalog_CatalogId ... table dbo.Item, column 'CatalogId'". The whole delete rolled back: B, CB and both of B's own products were still there. After the cross-catalog product was deleted (DELETE /api/catalog/products?ids=), DELETE /api/catalog/catalogs/{B} returned 204. Side note: DELETE /api/catalog/catalogs?ids={B} (query form) returns 405 on this build. Only the id-in-path form exists.
