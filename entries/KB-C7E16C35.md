Payment selection is on the /cart page itself, in a "Payment details" section (alongside "Shipping details"), not on a separate /checkout/payment route. The control is a "Payment method*" dropdown. Nothing is preselected: the control reads "Select a payment method" and no option carries a selected state, and Place order is disabled with "Complete all required information to proceed." until a method is chosen. The list renders in full before any shipping address or delivery method is chosen, so it is not gated on shipping selection. The dropdown renders the methods in exactly the order Query.cart.availablePaymentMethods returns them - the UI does no filtering or re-sorting of its own. That order is not priority: with priorities 1,0,0,1,0,0 the rendered order is neither ascending nor descending by priority. It is alphabetical by method code (AuthorizeNet < CyberSource < Datatrans < DefaultManual < Loyalty < Skyflow). The platform developer guide states that a store's priority setting determines "the order in which the payment methods will be displayed at checkout" - that did not hold here. On a second deployment with a smaller set the order was still alphabetical by code (AuthorizeNet < CyberSource < DefaultManual < Skyflow), so the sort key is not per-deployment. The observation cannot distinguish alphabetical-by-code from registration order that happens to coincide with it.
