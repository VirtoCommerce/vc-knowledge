Anonymous POST /api/platform/security/sign-in with a JSON body: grant_type=passkey reaches the grant handler (missing credential -> 400 missing_parameters, bogus credential -> 400 login_failed). grant_type password, refresh_token, client_credentials, impersonate, external_sign_in and an unknown name all answer 400 error=unsupported_grant_type, so the PR text "any registered grant type" is true only for IGrantTypeHandler-based grants. Malformed bodies never 500: empty body, non-JSON text, JSON null, [] and {} all answer 400 unsupported_grant_type (a parse error is reported as an unsupported grant); a body whose credential value is a JSON object instead of a string also answers 400 unsupported_grant_type; a numeric credential is coerced and gives login_failed; no Content-Type or form-encoded -> 415; GET -> 405. Authenticated PUT /api/platform/security/currentuser/sign-in-methods/{name}/keys/{id} for an unknown method, unknown key or a non-base64url id -> 400 {succeeded:false, errors:[sign_in_key_not_found]}; anonymous -> 401; the path written in the PR text (without currentuser/) -> 404.
