On vcst (platform 3.1099.0, VirtoCommerce.OTP 3.1002.0-pr-4-83d4, store B2B-store), REST plus Admin SPA. With OtpSignIn.Enabled on, POST /api/otp/request returned 200 succeeded=true and an OtpSignInEmailNotification with a 6-digit code was journaled. The setting was then turned off in the classic Admin SPA (Stores > store > Settings widget > OTP Sign-In > General, toggle, OK, store Save = PUT /api/stores 204). About 5 s after Save, POST /api/otp/request answered otp_disabled on the first poll (no store-settings cache lag seen). POST /connect/token grant_type=otp_email with the code requested before the switch answered 400 {error:"invalid_grant", code:"otp_disabled", errors:[{code:"otp_disabled"}], accessToken:null}, no access_token. Turning the setting back on the same way made POST /api/otp/request answer succeeded=true on the first poll about 7 s after Save, and a fresh code then signed in (200).
