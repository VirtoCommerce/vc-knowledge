On a B2B store the product page has no separate "Add to cart" button for a simple product; the quantity stepper is the entry point. Clicking "Increase quantity" on an empty cart issued the operation UpdateShortCartItemQuantity calling mutation updateCartQuantity(command: InputUpdateCartQuantity) with items:[{productId, quantity:1, itemCurrencyCode}] — it did NOT call addItem. The response was HTTP 200 with no errors[] and returned the created line item. Subsequent quantity changes from the cart line use changeCartItemsQuantity. Configurable products differ: they keep a real "Add to cart" button. Consequence for test authoring: a cross-layer assertion written as "addItem returns 200 / addItem errors[] empty" for the simple-product stepper path will never match the traffic the UI actually produces.
