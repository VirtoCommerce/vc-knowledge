The theme's index.html declares preconnects plus a stylesheet link to fonts.googleapis.com/css2?family=Lato (seen verbatim on local builds of the same theme). The HTML served on vcst_qa (Server: cloudflare) instead carries the comment '<!-- Google fonts -->' followed by an inline <style> of Lato @font-face rules (400/700/900, italic 400, latin + latin-ext, font-display swap) whose src is /cf-fonts/s/lato/5.2.7/... on the storefront host. Cold loads of /, a PDP and /cart made 0 requests to fonts.googleapis.com or fonts.gstatic.com, no <link> to Google Fonts in <head>, and fetched only same-origin /cf-fonts/.../lato/...woff2. Consequence: on this stand, a test that expects 'the Lato stylesheet request to fonts.googleapis.com' sees none. That is the CDN's font optimisation, not a theme change; check the local build or the source to see what the theme itself requests.
