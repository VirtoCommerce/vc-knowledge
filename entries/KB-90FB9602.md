Platform 3.1079.0-pr-3135-163c (the VCST-6315 fix build). VirtoCommerce.Platform.Security.CronPruneExpiredTokensJob has valueType Cron (on Stable 15 it was ShortText). Posting the full ObjectSettingEntry with value "0 0 */2 * *" returned 204 and read back. Posting it with value "99 99 * * *" returned HTTP 500 with body {"message":"Setting with name VirtoCommerce.Platform.Security.CronPruneExpiredTokensJob is invalid","stackTrace":null}. A GET afterwards still returned the previous valid value, so the rejected value was not stored. Unchanged and valid re-saves returned 204 in 95 of 95 attempts, including the minutes right after a deploy (before the fix they were intermittently rejected with the same 500, VCST-6315). Admin Settings > Platform > Security saves through POST /api/platform/settings/v2/global/values, which returned 204.
