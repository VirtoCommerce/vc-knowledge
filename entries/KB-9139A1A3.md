mergeCart takes the source cart's id in secondCartId, a required String - not cartId, which is a common wrong guess from older examples; the schema rejects a command without it. userId names the destination user whose cart absorbs the source, and storeId, currencyCode and cultureName go alongside. The guest-to-signed-in merge on sign-in happens server-side, so it need not show as an explicit mergeCart call.
