On vcptcore_qa1 a buyer signed in on the storefront /sign-in (password mode); the storefront's POST /connect/token (storefront host, proxied) returned a refresh_token. That same token, POSTed with grant_type=refresh_token storeId=B2B-store organization_id=<org> to the platform backend host's /connect/token, returned HTTP 400 error=invalid_grant error_description "The issuer associated to the specified token is not valid." and no errors[] array. POSTed instead to the storefront host's /connect/token (the issuer) it was evaluated normally (e.g. 400 with errors[0].code=user_is_locked_in_organization for a locked org). So a code-less invalid_grant on the backend host is an issuer mismatch, not a revoked token and not a product refusal: test steps that redeem a storefront-captured refresh token must send it to the storefront host.
