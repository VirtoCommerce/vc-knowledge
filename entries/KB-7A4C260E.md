A storefront sign-in token request needs the store as storeId in camelCase; store_id, a header, or no store at all return 400 user_cannot_login_in_store, indistinguishable from a real store refusal. A wrong secret returns a different code, login_failed, which is the cheapest way to tell a store-resolution failure from a credential one. Administrator-type platform users can sign in to the Admin back office but not to the storefront: the store-scoped request returns user_cannot_login_in_store, and the storefront sign-in form's email validation rejects a non-email username before any call. The Admin session does not carry over to the storefront.
