On vcst 2026-11-23 (WhiteLabeling 3.1007.0), GET /api/platform/settings/WhiteLabeling.ThemePresetNames listed allowedValues Default, Mercury, red, Watermelon, Coffee, black-gold, Purple Pink (no Paprika; red lowercase). POST /api/white-labeling {organizationId, isEnabled:true, themePresetName:"Paprika"} for a fresh AGENT-TEST organization returned 200 and GET /api/white-labeling/organization/{id} read back themePresetName "Paprika"; the same with "red" read back "red". xAPI Query.whiteLabelingSettings(organizationId, storeId:"B2B-store") as a member of each org returned themePresetName "Paprika" and "red" exactly as stored (no case normalisation, no rejection). So the REST save does not validate the preset name against the dictionary; the dictionary only feeds the Admin picker, and whether an unknown name renders is the storefront's preset lookup.
