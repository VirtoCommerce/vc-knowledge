Platform build with vc-platform PR #3182 (hashed API keys), Admin Shell PR #25. Admin Shell user blade > API keys > Generate key sent POST /api/platform/security/users/apikeys with body {isActive:true,userId} (no apiKey). The 200 response held one key object with apiKey = full value (vc_ + 43 chars, 46 total), apiKeyHash null, apiKeyHint = first 4 + '…' + last 4. The blade showed a banner 'New API key' / 'Copy the key now. It is not stored and will not be shown again.' with Copy and Done; Copy gave a toast 'API key copied' and the clipboard held exactly the shown value, which authenticated as the owner (currentuser userName = owner; a permission-less protected call 403). The following GET /api/platform/security/users/{id}/apikeys returned apiKey = hint (9 chars), apiKeyHash null; after reload the row shows only the hint. Toggling Active sent PUT /api/platform/security/users/apikeys with apiKey = hint and the key id; isActive=false made the key 401 on GET /api/platform/modules (currentuser 200 {}), and isActive=true restored the SAME key (no regeneration). Delete sends DELETE users/apikeys?ids=<id>, no key. Four keys that existed before the migration list as 4…4 hints, active, apiKeyHash null in the API response.
