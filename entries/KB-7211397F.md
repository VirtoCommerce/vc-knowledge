Created 13 AGENT-TEST promotions on B2B-store via REST and read salesRepCoupons(storeId: B2B-store, first: 200) as a sales rep. Listed: active public promotions with exactly one coupon, coupon without expiry or expiring in 3 days, uncapped or capped with 0 uses, a promotion without endDate. Not listed: a coupon whose own expirationDate was yesterday (its promotion still active), a non-public promotion, an inactive one, a promotion whose endDate was yesterday, and both coupons of a promotion that has two coupons. Item id is the COUPON id (promotionId is a separate field). endDate = the coupon's expirationDate when set, else the promotion's endDate (promotionEndDate and expirationDate are also returned). Order: endDate ascending, items with no endDate last, equal endDate ordered by coupon id ascending; first/after (offset as string) pages of 4 were disjoint and their union equalled the full list; totalCount equals the filtered count; first: 0 returns no items with the real totalCount. sort: "name:desc" and keyword: "P12" returned the identical default list and totalCount, with no error. cultureName de-DE returns the promotion's de-DE display name, label and description; en-US with no en values returns the invariant name and description and a null label. The storefront plugin sends this query to /graphql (the same field also answers on /graphql/sales-rep). Used-up filtering (totalUsesCount >= maxUsesNumber) could not be exercised: coupon usage cannot be set through REST.
