POST /api/members created a Contact with phones ["+1 555 010 2030", "+1-555-010-2031", "(555) 010-2032"]. GET /api/members/{id} returned ["+1-555-010-2031", "(555) 010-2032", "+1 555 010 2030"] on three consecutive reads, and the scoped /graphql/sales-rep salesRepCustomers / salesRepCustomer primaryContact.phones returned the same order; the server's `phone` field (primaryContact.phones[0]) was therefore +1-555-010-2031, not the first number written. Deleting and re-creating the contact with the same list gave the same read order again. So anything that treats phones[0] as "the default / first-entered number" gets the platform's persisted order, not the entry order; a test must assert the default against what phones[0] reads back, never against the written list.
