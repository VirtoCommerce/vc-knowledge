On a store with GitContentEnabled=true (set through PUT /api/stores) and GET /api/site-builder/git/connection configured:false: POST /api/site-builder/designer/save of a database page -> 200; POST /api/site-builder/save draft=true of a file page -> 200 and the draft is readable from Themes/<store>/default/content/pages/ (blob). GET git/site?storeId -> enabled:false, configured:false; history/status -> setupRequired. Adding GitContentRepository "owner/name" not in AllowedRepositories (or a non owner/name value) changed nothing: no error on the store PUT or on saves. Source at 28d00e0: IsEnabledForStoreAsync needs a resolvable repository, and the AllowedRepositories check only runs once a connection is available. Setting a store setting back to null through PUT /api/stores leaves the old value; send false or "" instead.
