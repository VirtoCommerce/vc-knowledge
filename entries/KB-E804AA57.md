On build 3.1107.0-pr-3182-2232, POST /api/platform/security/users/apikeys as admin with client values gave these results. 31 and 129 visible-ASCII chars returned 400 "The API key must be 32 to 128 characters long. Send an empty value to have the platform generate one.". 32 and 128 chars returned 200, and the key authenticated in both the api_key header and the ?api_key= query. An inner space, a tab, an NBSP, é or a Cyrillic letter returned 400 "The API key may contain only visible ASCII characters, without spaces. Send an empty value to have the platform generate one.". A value containing "…" returned 400 "The API key looks masked…". A value padded with surrounding spaces returned 200 and was stored trimmed (hint = first4…last4 of the inner value, which works in the header). A 36-char GUID-shaped value with dashes was accepted, and later saves with its hint or an empty value kept it. A value already stored (for any user) returned 400 "This API key cannot be used. Send an empty value to have the platform generate one.". Error bodies are bare JSON strings, not {message} objects.
