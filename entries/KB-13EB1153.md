On vcst (SalesRep 3.1018.0-pr-33-ff13 plugin chunk sales-rep-tasks-page-Dss09knJ, Firefox), as a rep serving organizations, clicking the dashboard '2 overdue tasks' notice opened /company/tasks?filter=overdue while the edge returned HTTP 521 for Query.salesRepTaskFilterRules and 522 for the overdue SalesRepTaskMarkers request (an origin outage, not a product error). The page rendered a notice "The filters couldn't be loaded, so the full list is shown. Try refreshing the page.", the list showed all 25 tasks (2 pages, every status), the Status select showed no value, and the chip row kept a single raw token chip "overdue" (lowercase, with a remove button) instead of the localized "Overdue". No toast and no console error. One retry after the origin recovered rendered normally: chip "Overdue", Status = Overdue, 2 tasks, URL cleaned. So the fallback is fail-open (full list), and a run that hits it must not be judged as an Overdue result.
