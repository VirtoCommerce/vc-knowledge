vcst_qa 2026-11-04, global MultiFactorAuthentication.Enabled off. The stand's admin account password grant (POST /connect/token, grant_type=password, no storeId) returned tokens while the stand's main storefront store was Disabled, CustomerChoice and AdminManaged; within a minute of setting that store to Enabled the same grant answered 400 with a twoFactorToken (two_factor_required) and an MfaSignInEmailNotification was queued; after the store was set back to Disabled the grant returned tokens again. The Backoffice (AngularJS) sign-in of the same account completed with no code during the Enabled window, and the store setting could be restored from there. Consistent with the own-store rule (the user's own store applies to every password sign-in); which store the admin account is bound to was not read, only this correlation. Consequence: tools that mint an admin token by password (seed scripts) cannot run while that store is Enabled unless they hold a pre-minted or refresh token.
