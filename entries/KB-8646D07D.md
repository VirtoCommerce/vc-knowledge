On theme 2.59.0-pr-2476-43b1 with x-cart 3.1038.0-pr-141 and sales-rep 3.1012.0-pr-21, a list whose sharingSetting.message was stored over 250 chars via changeWishlist opens in the Share dialog with the full message pre-filled and the counter reading e.g. '600 / 250' in red; there is no other error state, and the textarea's native maxlength=250 only blocks inserting characters (deleting still works). Share is disabled until a recipient is added and is enabled as soon as one is (the save gate checks recipients only). Share then sends ChangeWishlist with the full over-cap message, which is stored, and one SendCustomerCommunication to the newly added org with message = note + '\n\n' + absolute /shared-list/<36-char key> link (91 chars on this stand). Threshold T = 1000 - 2 - link length (907 here): a 907-char note sent 1000 chars and succeeded with toast 'List shared with 2 customers.'; 908 and 950 sent 1001/1043 chars, got 'Message must not exceed 1000 characters.' as errors[] inside HTTP 200, the list and the new target were already saved, and the rep saw the warning toast 'The list was saved, but the notification could not be sent.' Reopening shows the org as an ordinary recipient with Share disabled and no resend action; removing and re-adding it in the same dialog leaves Share disabled. Pasting 600 chars into an empty field keeps 250 and the counter reads 250 / 250, with no other message.
