On a build with VirtoCommerce.PageBuilderModule 3.1036.0-pr-175, opening the vc-shell Page Builder app (apps/page-builder-shell/?storeId=<store>) issues POST /api/page-builder-pages/list (200), not the older /api/page-builder-pages/search. Calling it with an admin bearer and {storeId, take} returns {totalCount, results[]}; each result has type ("Landing" for a regular page; the PR adds a Multilanguage row type), id, name, permalink, createdDate/modifiedDate, a nested page (the GroupedPageBuilderPage: cultureName, permalink, status, visibility, userGroups, organizationId, startDate, endDate, multilanguagePageId, overriddenFields, sourceRevisionDate, pages[] with per-version status) plus multilanguagePage and languages (null for a Landing row). The language badge in the list comes from page.cultureName; legacy rows without a culture show a "null" language badge. Admin tests that wait for the /search request no longer match the list load.
