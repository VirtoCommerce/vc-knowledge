On x-cart 3.1038.0-pr-141-b404 / sales-rep 3.1012.0-pr-21-8964 / cart 3.1011.0-pr-194-8331, 2026-10-06, 2 runs: a rep shares a list scope Customer with orgs X, B and A (all served). Admin removes X from the rep's organizations[] via PUT /api/sales-rep (salesRepCustomers no longer lists X; the rep needs a fresh token). Then changeWishlist(scope Customer, addSharedWithIds [X]) while X is still a target → HTTP 200, errors[Forbidden 'Access denied.'], targets unchanged. changeWishlist(scope Customer, removeSharedWithIds [X]) → 200, no errors, targets = A, B (other grants intact; a B member still reads via sharedWishlist). A second addSharedWithIds [X] → Forbidden again, nothing written. Revocation is allowed regardless of assignment; granting requires a current assignment.
