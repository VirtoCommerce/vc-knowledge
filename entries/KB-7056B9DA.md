Platform 3.1076.0. PUT /api/platform/settings returns 405; the update verb is POST /api/platform/settings with an array of the full ObjectSettingEntry objects. Posting an entry with value null for a Boolean module setting that currently held a stored true returned 204 and changed nothing (GET /api/platform/settings/{name} still returned true). POST /api/platform/settings/v2/global/values with {"<name>": null} also returned 204 and changed nothing. Settings that were never written read back value null (= default applies). So once written, the only way back through the API is to store the default value explicitly; the Admin Settings blade shows a 'Reset to default value' icon for integer settings but none for Boolean toggles. A settings write was visible on both backend replicas at once: 14 GETs (10 cookie-less + 2 pinned per pod) right after the write all returned the new value, and a TTL change to 0 took effect on both pods on the next statistics read.
