SalesRep 3.1013.0-pr-18 (VCST-5755) on a 2-replica stand, Cart TTL 60, Cart InvalidateOnChange true. Pinned-pod canary via INGRESSCOOKIE: the rep's Org-B cart-statistics key (period.to frozen in the future) was warmed with the flag on, so it carries the Cart:{Org-B} change token, on pod X and pod Y. The flag was set false (confirmed by settings GETs pinned to each pod) and the rep added a line to the Org-B cart: the key stayed stale on X and Y while its cold twin (to + n seconds) moved 0 -> 3, so the cached copy now differs from the truth. The flag was set true again (the flip alone left the key stale), then the rep added a line to an Org-A cart through pod X: the Org-B key read stale 3/3 on Y and 3/3 on X, while an Org-A control key warmed on both pods went fresh (0 -> 4) on both, proving the Org-A change did fire and reach both pods. Positive control: a quantity change in the Org-B cart through pod X made the Org-B key fresh (6 = twin) on X and Y, proving the entry was evictable all along. So a cart change evicts only the changed organization's entries, cluster-wide; other organizations' cached cart statistics are untouched.
