A customer signed in with no code (store CustomerChoice, mode Off). An administrator then set the user's mode to Required via PUT /api/mfa/modes/users/{id}. The old access token still served Query.mfaSettings, and a grant_type=refresh_token request answered 200 with a working new access token. Only the next grant_type=password answered 400 two_factor_required. The same held for an organization switched from Enabled to Required while a member was signed in. Sessions are listed with a 30-day expiry in the Admin Shell Sessions blade; Terminate all is the only way to end them. No session revocation happens on a mode change.
