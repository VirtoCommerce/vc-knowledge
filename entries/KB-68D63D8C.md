xAPI organization.assignableRoles(storeId) is filtered by the Customer module setting Customer.MembershipRolesWhitelist. When the store has a store-level override of that dictionary setting, its values are used as-is, and an override that exists but holds no values yields an empty list: assignableRoles returns [] (HTTP 200, no errors) and the storefront shows 'There are no roles available. Please contact your store administrator.' with Send disabled. Without a storeId argument, or with an unknown store, the code defaults (Organization employee, Organization maintainer, Purchasing agent) apply. The Admin SPA role picker treats the same empty value the opposite way (falls back to the global list, and an empty whitelist means no restriction), so the back office keeps offering roles while the storefront offers none. Check the store's settings entry for an empty override before treating an empty assignableRoles as a code defect.
