The storefront xAPI publishes contact.firstName, .lastName and .fullName as NON-NULL GraphQL fields over nullable Contact columns, so a contact with a null first or last name makes query { me { contact { firstName lastName } } } fail with extensions.code INVALID_OPERATION ('Error trying to resolve field firstName.') and resolve contact to null. That locks the user out of the storefront entirely, because the sign-in page context reads the same fields. Observed on both a pre-fix and a fixed Sales Rep build, so it is a schema-level property of the Experience API, not of any one module. Filling both names makes the identical query return normally.
