A B2B-store buyer's fresh real-click storefront assertion posted to POST /connect/token with storeId=store2 (a store with no trustedGroups) -> 400 invalid_grant, code user_cannot_login_in_store, "Access denied. You cannot sign in to the current store". The password grant for the same user and store2 gives the same code, but its log row reason is NotAllowed while the passkey row is signInType Passkey, succeeded false, failureReason Unknown, userName set, storeId B2B-store (the user's store; store2 appears nowhere). storeId=Clothing (trustedGroups includes B2B-store) issues a token for both grants, so a store that trusts the user's store cannot serve as a store-restriction probe.
