Localhost stand, CustomerChoice store, global MFA off. Maintainer (org role with xapi:my_organization:mfa:manage), user mode set to Required via PUT /api/mfa/modes/users/{id}, organization mode Off. On /company/info, Turn on sends RequestMfaChangeCode with command {storeId, organizationId=<current org>}; it answers succeeded=true, the inline code step opens, exactly one MfaSignInEmailNotification journal row is added, and UpdateMfaOrganizationMode with that code sets the organization to Enabled (Turn off and Turn on again work the same way: 3 of 3). The same maintainer's /account/security shows the user mode read-only ("Set by the administrator: you can't turn it off.", canChangeUserMode=false, no button). A direct requestMfaChangeCode with command {storeId} only (no organizationId) answers succeeded=false, errorCode mfa_locked_by_administrator, and adds no journal row. The /account/security Turn on for a user whose mode is Off sends command {storeId} with no organizationId and works with the emailed code. A member without the permission sees no company widget; a direct request with organizationId answers mfa_organization_not_allowed, no email. With the organization set to Required by the administrator, the widget is read-only and requests with or without organizationId answer mfa_locked_by_administrator, no email.
