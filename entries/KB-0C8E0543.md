Theme 3.1.0-pr-11-d67b-d67b0e0a, guest, AGENT-TEST-Wedding-Cake-Cond and AGENT-TEST-Req-File-Child. The 'Configuration checklist' list sits under Add to cart in Price and delivery (desktop), and in the 'Share & Actions' widget at 390 px, where Add to cart is a sticky bottom bar. It has one row per visible section in configuration order. A done Product row reads '<name> — <option>', a done Text row the name only, each with a check icon and an sr-only '(completed)'. An open required row is red '<name> — required' with 'Fill it in' (Text) or 'Upload a file' (File). An optional row is yellow '<name> — optional' with 'Review'. A root required Product section arrives preselected (done). On first load only the first section is expanded. A row link expands that section, scrolls its header just below the sticky header, focuses the header button, keeps the URL and selects nothing. Choosing Creme (Product) revealed Message live, and choosing Message revealed 'Custom text required' (Text, required) and Image (File, optional). Setting Message back to None removed both rows and re-enabled Add to cart. Five spaces in the required text kept the row red and Add to cart disabled. Real text turned it green and enabled Add to cart, and the cart line's Components list carried every choice and the text. Clicking an option's image or the 'None' label does not select it. Only the radio circle does. A simple PDP shows no checklist, and an SPA link from one configurable PDP to another shows only the second product's sections.
