On vcst_qa a signed-in user placed a CyberSource order on /cart (authorizePayment isSuccess true, held for review by Decision Manager; order status Payment required, InPayment New, 0 transactions). Replaying storefront /graphql AuthorizePayment for the same orderId/paymentId with (a) the token JWT payload edited (masked PAN changed, signature kept) and (b) the signature segment replaced both answered 200 data.authorizePayment.isSuccess true with errorMessage 'Your transaction was held for review...'; (c) 'not-a-jwt' and (d) an empty token answered errors[0].extensions.code API with data null. Admin GET /api/order/customerOrders/{id} after each replay still showed status Payment required, InPayment New, isApproved false, 0 transactions, so no authorization was recorded, but the tampered tokens were not refused either.
