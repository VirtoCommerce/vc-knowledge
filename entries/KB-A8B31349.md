As an administrator, in the Menu Editor I renamed the built-in section orders (English title "AGENT-TEST Orders") and the item returns, then saved. The global patch stored sections.orders.titles.en, and after a full reload POST /api/admin-shell/menu served title "AGENT-TEST Orders". The item showed the new name, and so did the panel heading and the rail button's accessible description (tooltip). The rail button's visible label and accessible name stayed the default short label. The deployed host bundle computes the rail label as the translation key MENU.RAIL.<sectionId>, falling back to the first word of the title only when no such key exists. Every built-in section has that key, so a rename never reaches the rail. Seen in Hebrew here and in German in an earlier run; the logic is the same for every locale. Restoring the empty patch brought everything back.
