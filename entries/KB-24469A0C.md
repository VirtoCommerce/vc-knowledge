On vcst (theme 2.63.0-pr-2667-0444-0444048a), twice: a 33-org buyer opened the header Organizations panel (Maple row enabled), an admin then locked that membership (POST /api/customer/organization-memberships/{id}/lock, 200, isCurrentlyLocked true), and the buyer clicked the Maple row. POST /connect/token grant_type=refresh_token with organization_id=<Maple> returned 400, then the page fully reloaded (GET /) as a guest (header shows Sign in). No error alert, no rollback, panel gone. The theme's useOrganizationSwitcher maps a lockout code to switchError, but a membership write revokes refresh tokens minted before it (KB-3CBA0D5F), so the 400 most likely carried no lockout code and the storefront treated it as a dead session. Signing in again landed in the previous org and the panel showed Maple disabled; after unlock, reopening showed it enabled.
