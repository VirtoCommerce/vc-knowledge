On vcst (platform 3.1099.0, VirtoCommerce.OTP 3.1002.0-pr-4-83d4), inside one floor(UTC epoch/180 s) window. (1) REST: request code1, grant it (200), request code2 about a second later - the journal's code2 had different digits from code1. (2) Storefront /sign-in: code 993912 signed the buyer in at 13:03:59Z, the buyer logged out, Continue at 13:04:50Z emailed 057319; typing 993912 gave 'That code didn't work.' (POST /connect/token 400) and typing 057319 signed in. So the same-digits-within-a-window behaviour (KB-38B0EAE3) is for requests with no accepted code between them; accepting a code changes the next code.
