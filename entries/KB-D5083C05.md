On vcst_qa 2026-10-26, POST /connect/token with only grant_type=refresh_token and refresh_token=<an admin refresh token minted earlier with scope offline_access> (no client_id, no scope) answered 200 with access_token, expires_in=1799 and a NEW refresh_token, five times in a row, each call sending the token the previous call returned. A script that keeps an admin bearer alive this way must write the returned refresh_token back before using the access token, and re-mint before ~30 min. This is also how an admin keeps API access while global MultiFactorAuthentication.Enabled challenges the admin password grant.
