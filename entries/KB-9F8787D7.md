On a stand running the vc-module-search PR #159 build (SimpleString [\p{L}\p{N}_\-./@+'&]+): productPickupLocations and cartPickupLocations (115 eligible locations) return 0 for "O'Neil", "Arts & Crafts", "St. Mary's", 3 of 3 runs, instead of the unfiltered 115. Each of the 7 locations whose name contains ' or & is returned when searched by its full name (productPickupLocations) and by its ' fragment such as "Children's" or "Barclays'" (cartPickupLocations). A bare "&" or "'" now returns 0, while the DB-backed store-level pickupLocations returns 3 and 4 for them, because the index analyzer drops the lone character. A fragment that is only "&" does not find "Stop & Shop". Side effect on the same parser: organization.contacts(searchPhrase) with single-quoted filters 'roleId':'<id>' and 'status':'Invited' now returns 0 (on 3.1010.0 they returned 5 and 9, because the dropped ' left a valid filter); the double-quoted "roleId":"<id>" and "status":"Invited" forms return 5 and 9 on both builds. Catalog products(query) with "O'Neil" or "&" returns 0, not the full catalog. Note: in xCatalog products, field filters written inside query (e.g. "printer price:(0 TO)", "x is:product") return 0 on both 3.1010.0 and the PR build; filters must go in the filter argument.
