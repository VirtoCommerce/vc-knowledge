Signed in as a two-organization member on two storefront origins backed by the same platform. A GraphQL updateContact mutation (command.selectedAddressId = an organization address id) followed by AddOrUpdateCartShipment (shipment.deliveryAddress = that address) was sent from one origin. A fresh load on the OTHER origin, with its own separate login, then showed the same address in the header Ship to selector, where it had shown the 'Select address' placeholder before. localStorage on that origin held only local_ship_to_addresses_<userId>=[] and local_ship_to_addresses_anonymous=[]. This matches vc-frontend useShipToLocation.ts: for CORPORATE and PERSONAL users, selectedAddress = accountAddresses.find(id === user.contact.selectedAddressId), and selectAddress() calls updateContact plus updateShipment. Anonymous users, and corporate-limited users choosing a non-organization address, use the local selectedLocalShipToAddressId instead. So a test that reads the Ship to state for an organization member depends on shared server state: selecting an address on one storefront changes what every other storefront and session shows.
