An anonymous JSON-RPC tools/call of search_products at {FRONT_URL}/ucp/mcp (arguments query, store_id, currency, language, limit; prices are minor units) returns products[] each with availability {is_buyable, is_available, is_in_stock, available_quantity}. A product created via POST /api/catalog/products in a physical catalog linked into the store's virtual catalog, priced via PUT /api/products/prices, stocked via PUT /api/inventory/plenty (inStockQuantity 2, reserved 0, status Enabled) on a fulfillment center that is in the store's additionalFulfillmentCenterIds but is NOT store.mainFulfillmentCenterId, and then indexed with POST /api/search/indexes/index [{documentType:'Product', documentIds:[id]}], was returned by search_products on the first poll ~20 s later with available_quantity 2 — so stock on a non-main store FFC counts toward available_quantity. Event-based indexation was off on this deployment, so the explicit documentIds request is what made it searchable.
