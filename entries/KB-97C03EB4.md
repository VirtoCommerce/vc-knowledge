A QuoteRequest created through the admin REST API POST /api/quote/requests with no languageCode is returned by the buyer's xAPI quotes(storeId, cultureName, currencyCode) list query, but the single quote(id, storeId, cultureName, currencyCode) query fails with extensions.code ARGUMENT_NULL even when only id/status are selected; the storefront quote detail page then shows 'Something went wrong'. Re-creating the same quote with languageCode en-US makes quote(id) resolve normally. A storefront-created quote carries languageCode from the request culture, so only API-created quotes hit this.
