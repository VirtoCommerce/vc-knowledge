2026-11-10 ~20:18-20:35Z, client claude-code-ucp-qa, B2B-store. For two buyers who had already allowed the client (the authorize round trip went straight to the callback), logout_buyer {} returned logged_out:true; the next {FRONT_URL}/connect/authorize for the same buyer, with the storefront browser session still signed in, went to the 'Allow Claude Code — Shop (QA)' consent page again (no sign-in page), and Allow issued a new code. After logout_buyer every earlier token of that buyer - the one used for the call and a second token minted earlier in another authorize round trip - got 401 on /ucp/v1 (restore and DELETE /ucp/v1/internal/handoff/{session}), so logout_buyer revokes all of the buyer's sessions for the client, not just the calling token. A handoff minted before logout_buyer was still restorable (200) with a freshly minted token.
