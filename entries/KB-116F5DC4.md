On B2B-store: Landing pages created via POST /api/page-builder-pages/create-group-page with cultureName xx-XX (accepted, 200) and with cultureName null. POST .../convert/{id} for both -> 400 "Page '<id>' must have a language of store 'B2B-store'." A valid en-US published page -> 200, root created with the page's name/permalink and defaultCultureName en-US; the page becomes its en-US version (multilanguagePageId set, status and permalink unchanged) and still renders at its original storefront URL for a signed-in buyer. Convert of the same page again, and of a fr-FR page linked to that root -> 400 "Page '<id>' is already a language version of '<rootId>'." Root search count rose by exactly one (the valid convert); no root carrying the refused pages' names exists.
