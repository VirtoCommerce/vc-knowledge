QA Storybook (storefront UI kit), stories components-organisms-vcstatwidget--loading and --error-state, read on first render. The card always renders an output element (implicit role status, no explicit aria-live) that is visually hidden (absolute, 1x1). It holds "Revenue this week: loading" in Loading and "Revenue this week: Couldn't load" in Error State from the first render, so the live region is inserted together with its text rather than empty and then filled. Per ARIA live-region practice, text present when the region is inserted is usually not announced, so a card that MOUNTS loading or in error may say nothing until its state next changes. In the ready state the status text is empty, so the value itself is never announced, only read. The pending dash, the error row and every icon (span.vc-icon) carry aria-hidden=true. The visible label is not hidden, so in browse mode the label is read twice: once as the label and once inside the status text. Measured from DOM attributes and text. No screen reader was run.
