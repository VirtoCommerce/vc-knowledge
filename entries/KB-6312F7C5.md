Password grant (scope offline_access, storeId=B2B-store) at the storefront host POST /connect/token answered 200 with token_type Bearer, expires_in 1799, an access_token whose header is alg RS256 (3 segments), and a refresh_token whose protected header decodes to alg RSA-OAEP, enc A256CBC-HS512 - a JWE in compact form (dot-separated). Its payload is encrypted, so the client can read only the header, never the claims. A check that the refresh token contains no dots fails on this build although the token is not readable; assert 'header alg is RSA-OAEP / payload not decodable' instead.
