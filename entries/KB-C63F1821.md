On XCart 3.1039 / Catalog 3.1048, productConfiguration(configurableProductId:"" storeId:"B2B-store") returned HTTP 200 with the "Choose Upgrade" section and options of a different configurable product (the oldest active configuration by CreatedDate), while a non-existent id returned configurationSections []. Source agrees: x-cart GetProductConfigurationQueryHandler.GetConfiguration sets criteria.ProductId from the argument with IsActive=true and takes FirstOrDefault, and catalog ProductConfigurationSearchService.BuildQuery applies the product filter only when ProductIds is non-empty. REST POST /api/catalog/products/configurations/search with productId "" likewise returns all configurations. A stand with only one inactive configuration answers [] and so cannot show it.
