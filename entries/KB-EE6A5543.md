POST /api/inventory/fulfillmentcenters/search returns centers in a stable order equal to name ascending (four repeated calls, and the same as sort "name:asc", on vcst_qa, vcptcore_qa1 and vcptcore_stable on 2026-10-08) - so its first result is the alphabetically first center, not necessarily the store's own: the store's main center sat at positions 6, 1 and 0 on those three stands. Take the store's center from store.mainFulfillmentCenterId (and additionalFulfillmentCenterIds), never from the head of a search. A fulfillment center has no code property at all - not in search results, not in GET /api/inventory/fulfillmentcenters/{id}, not in the swagger schema (name, description, shortDescription, geoLocation, address, outerId, organizationId, dynamicProperties, ids and audit fields) - and the criteria offer outerId and keyword (which matches the name, not the id), so matching a center on code never succeeds.
