Return 3.1005.0-pr-28-fb4f, 2026-10-12. Opened an admin-created New return in Admin > Returns (#!/workspace/Return), edited Resolution, clicked Save. PUT /api/return returned 200 with body {"id":...} only; the blade then issued only GET /api/return/{id}/available-statuses and the grid's POST /api/return/search, no GET /api/return/{id}. The blade's Modified date kept the pre-save value (10:03:35Z) while GET /api/return/{id} and the search payload carried the new modifiedDate (10:04:56Z); a second Save repeated it (blade 10:04:56Z vs API 10:05:51Z), 2 of 2. Clicking Refresh on the blade re-reads the return and shows the new value. The blade shows Created by but no Modified by field. The data is correct server-side; only the blade display is stale. Source: return-details.js saveChanges copies currentEntity into originalEntity on success and never re-reads the entity.
