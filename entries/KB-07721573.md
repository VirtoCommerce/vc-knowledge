As a guest on the storefront with no other cart, I created a named cart through addItem(cartName "AGENT-TEST-...", userId = the guest session id from localStorage user-id); the header cart badge then showed 1. On signing in by password, the storefront sent GraphQL MergeCart with secondCartId = that named cart's id and no cartName; the response was the user's default cart with the guest line in it, and the named guest cart no longer resolved by id. A later explicit mergeCart by the same user with that secondCartId returned the target unchanged and no error (the id matched no cart). So a test that needs a guest cart to survive sign-in must create it under a guest id other than the browser session's (an anonymous call with a fresh id works; the cart is still isAnonymous=true).
