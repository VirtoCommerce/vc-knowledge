Signed in, Chromium, one cart line, Fixed Rate (Ground) + Bank card (CyberSource) selected. Each selector is a div with id select-N-trigger, class vc-select__button, tabindex=0, role=button, aria-haspopup=listbox, aria-expanded, aria-label equal to the field label ("Delivery method" / "Payment method") and aria-describedby pointing at an empty details element. On theme 2.62.0-pr-2622-caac the trigger also carries aria-required="true", and axe-core 4.12.1 (WCAG A/AA tags) reports aria-allowed-attr (critical) on both; the selected method's image (an inline data:image/svg+xml placeholder, img.shipping-details-section__method-image, and the payment method icon under div[data-selected-payment-method-id]) has no alt attribute, so axe reports image-alt (critical) on both. On theme 2.62.0-pr-2632-4c61e29f (VCST-5711 fix, unreleased PR build in a local container proxied to the same backend, same cart) the trigger has no aria-required, both images have alt="", and neither rule fires in three runs. On both builds the accessible name is only the label: the selected method shows as visible text inside the trigger but aria-label overrides it, so it is in neither the name nor the description. Keyboard on both builds: the trigger is in Tab order with a 2px solid focus outline; Enter opens the listbox, ArrowDown moves focus into the options, Enter selects and returns focus to the trigger, Escape closes; Space does not open it. The required combobox vc-selects (Country, State / Province in the Edit address dialog) keep aria-required="true" on the fix build.
