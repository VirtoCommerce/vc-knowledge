Placed a $200 order on the B2B storefront cart using the inline CyberSource Flex Microform v2 form. createOrderFromCart returned 200 with no errors[] and the order was created with status "Payment required" (orders are created in that status before authorization resolves). authorizePayment then returned isSuccess:true with errorMessage "Your transaction was held for review: The order is marked for review by Decision Manager". Because the authorization is held rather than approved, the order REMAINS at "Payment required" and the order-detail page offers a "Pay now" button, instead of advancing to "Processing". Re-submitting the card via Pay now reproduced the same held-for-review result. A same-amount order placed minutes later through the Skyflow saved-card flow returned authorizePayment isSuccess:true with errorMessage null and DID advance to "Processing", which isolates the hold to CyberSource sandbox fraud screening rather than to the platform's order or payment pipeline. So "Payment required" after a CyberSource checkout is not by itself evidence of an order-creation or payment-integration defect.
