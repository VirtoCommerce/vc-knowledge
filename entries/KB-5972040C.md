On vcptcore-qa (PageBuilderModule 3.1036.0-pr-175), setting a language version's user-group restriction through PUT /api/page-builder-pages/grouped with "userGroups": ["AGENT-TEST-group"] (a JSON array) returned HTTP 500 with a NullReferenceException body; the same PUT with "userGroups" as a plain string ("AGENT-TEST-group") succeeded and the restriction took effect (the version left pageDocument.alternates). So the field is a string on the model, and a type-mismatched body is not rejected with a 400 validation error — the body most likely binds to null and the controller dereferences it. The PUT grouped endpoint predates the multilanguage feature, so this is likely pre-existing.
