As a personal storefront contact, updateContact with lastName "Tester2" returned HTTP 200, data.updateContact null and errors[0] = message "'Last Name' contains invalid characters.", extensions {code:VALIDATION, codes:[VALIDATION], field:"lastName", errorCode:"InvalidCharacters"} (3/3 runs). Both names invalid in one call gave two errors (firstName, lastName). updateMemberAddresses with two invalid new addresses gave errors at field "addresses[0].firstName" and "addresses[1].lastName" and saved nothing. updatePersonalData gave field "personalData.firstName". Other codes seen: NotEmptyValidator (empty lastName), MaximumLengthValidator (firstName over 128 chars), HtmlTagsNotAllowed (address line1/city), InvalidEmail (address email). HTML or "javascript:" in a NAME field comes back as InvalidCharacters, because the name pattern rejects < > : first; UnsafeContent was not triggered ("javascript:alert(1)" in address line1 was accepted). No message echoes the typed value. After a rejected updateContact, me, contact(id) and GET /api/members/{id} all keep the saved name. The same requests on vcst_qa with ProfileExperienceApi 3.1021.0 still return one bare error "Error trying to resolve field 'updateContact'." with only {code, codes}, and contact(id) + REST there show the rejected name from cache. Fix: vc-module-profile-experience-api PR #150 (VCST-5690), not merged at observation time.
