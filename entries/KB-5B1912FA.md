Admin token. POST settings/v2/tenant/Store/B2B-store/values {"Sanity.Dataset":"agent-test-r2b"} -> 204; GET settings/v2/tenant/Store/B2B-store/values returned the new value immediately, but GET /api/stores/B2B-store?responseGroup=Full still returned the previous value (value "production", itHasValues true from an earlier write). After POST {"Sanity.Dataset":""} the v2 GET returned the default at once; /api/stores caught up only ~4 minutes later (value null, itHasValues false). The default response group of GET /api/stores/{id} returned value null for this setting throughout. So a v2 tenant save does not invalidate the store cache; the store module (and anything reading settings through the store object) sees the old value until the cache expires. The v2 SaveValuesAsync path was not changed by vc-platform PR #3134 (only controller validation), so this is not introduced by that PR.
