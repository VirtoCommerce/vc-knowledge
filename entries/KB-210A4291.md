Saved a Product/color mapping (POST /api/search/index-field-settings, value AGENT-TEST-Dark, synonyms Black + DKNAVY). POST .../search and GET .../{id} returned it at once, identical across repeated reads; the settings value VirtoCommerce.Search.IndexSettings holds all mappings as one JSON array. field-values was unchanged until a Product Build (POST /api/search/indexes/index, deleteExistingIndex false); after it, field-values for color dropped Black, black and DKNAVY and listed AGENT-TEST-Dark (23 -> 21 values), so the synonym match is case-insensitive. The xAPI products color facet count of the merged value was 15 = Black 14 + black 1 (DKNAVY had no products in the store), and a filter on the merged value returned 15 products. Renaming the value and removing a synonym, adding a synonym by writing the setting directly through POST /api/platform/settings (visible in .../search on the very next request), deleting one mapping while another field's mapping exists, and deleting all mappings were each reflected by the next build only, never by a stale copy; deleting the last mapping leaves the setting at "[]", and deleting a field mapping restores that field's original values on the next build. A save that adds a synonym already used in the same field (any letter case) is refused with HTTP 500 and the message "Synonym 'Product.color.<synonym>' already exists.", and nothing changes. GET .../{id} of a deleted mapping returns 200 with a null body, not 404.
