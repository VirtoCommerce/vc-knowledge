A Manager account (isAdministrator=false, status Approved, emailConfirmed, password applied via resetpassword) with storeId=B2B-store and memberId pointing to a Contact was created through POST /api/platform/security/users/create (userType Customer, memberId, storeId) and then switched to userType Manager with a role via PUT /api/platform/security/users. POST /connect/token grant_type=password without storeId answered 400 invalid_grant code login_failed ("Login attempt failed. Please check your credentials."), also with scope=offline_access; the same request with storeId=B2B-store answered 200. A Manager with the same storeId but no memberId got 200 without storeId. So the store rule binds an account that has a contact, whatever its userType; the Admin SPA's sign-in sends no storeId, so such an account cannot sign in there.
