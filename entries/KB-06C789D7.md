On vcst_qa (platform 3.1076.0, Customer 3.1029.0), POST /api/customer-preferences/search with {userId, take} as admin listed each account's CartShipmentLastAddress.<orgId>.<shipmentMethodCode> rows: id, name, value (the address JSON or a pickup-location id) and createdDate. DELETE /api/customer-preferences?ids=<id>&ids=<id>… with an admin token returned 204 for 5 ids across three accounts, and the same search afterwards returned none of them. xCart's addOrUpdateCartShipment and checkout write these rows, so a test run that ships carts leaves one row per user, organization and shipping method. Deleting them by id restores the account's pre-run state; the next checkout simply writes a new row.
