2026-11-10, admin token: GET the full order, change customerId/customerName/organizationId (and on one order isCancelled=true + status Cancelled), PUT /api/order/customerOrders with the full body -> 204; re-GET showed the new customerId/organizationId/isCancelled, createdDate byte-identical to before (14 orders from 2025-01..2025-12), total unchanged. This is the only REST way to give a buyer orders in past periods, since POST ignores createdDate (KB-971BC129). Separately, POST /api/order/customerOrders with a sales-rep user's storefront token (password grant + storeId) -> 403, so an 'on-behalf' order cannot be created by the rep over REST; an admin-created order carries createdBy=admin.
