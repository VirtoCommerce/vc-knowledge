Observed 2026-10-13 on vcptcore-regression (Orders 3.1018.0, Notifications 3.1018.0, BackgroundJobs 3.1052.0, Hangfire engine). Each PUT /api/order/customerOrders that only changed the order Status (Processing->Cancelled, Cancelled->Pending, Pending->Completed) returned 204 and, via OrderChangedEvent handlers run as Hangfire jobs (LogOrderChangesJobHandler, SendOrderNotificationsJobHandler, AdjustInventoryJobHandler all Succeeded), produced within about 3 seconds: one new GET /api/order/customerOrders/{id}/changes entry (operationType Modified, createdBy admin, detail "property 'Status' changed from 'X' to 'Y'"), prior entries untouched; and exactly one NewOrderStatusEmailNotification journal row (status Sent) whose body names the new status. Setting status to Cancelled via PUT alone did not set isCancelled and did not cancel the Paid in-payment. AdjustInventoryJobHandler succeeded (not Failed) on an order with no inventory reservation behind it.
