Platform 3.1084.0-pr-3142-b518, Admin > Contacts > member > Dynamic properties widget. Created Required ShortText dictionary props (single, multivalue, multilingual, multivalue+multilingual), a Required plain ShortText and an optional dictionary on Contact, Organization and Employee. With any Required dictionary empty, the ui-select carries ng-invalid, renders with the invalid tint, and OK stays disabled (3/3 fresh opens on Contact; each variant shown to block on its own). Removing the last chip of a multivalue dictionary disables OK again. Optional dictionary left empty does not block (ng-empty but not ng-invalid). With all filled, OK -> Save -> PUT /api/members 204 and GET /api/members/{id} returns the selected values. Single-value dictionary ui-selects offer no clear control, so a saved single dictionary value cannot be emptied from the UI. Earlier stable builds (3.1039.x, 3.1076.1) did not block — see KB-3D793889.
