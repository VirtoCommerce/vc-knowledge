On a platform build with hashed API keys (vc-platform PR #3182, ApiKeyAuthentication:AllowQueryString not configured, so default true), four API keys that existed before the AddUserApiKeyHash migration (owners of types Administrator, SiteAdministrator, Manager, Customer; 32 to 36 characters) were sent after the upgrade to GET /api/platform/security/currentuser, once in the api_key header and once as ?api_key=. All 8 calls answered 200 with the key's own owner as userName. The admin's key also got 200 on GET /api/platform/modules. A made-up key in the header, and a call with no credential, both got 401 on GET /api/platform/modules, while GET /api/platform/security/currentuser answered 200 with an empty object {} for both. So currentuser's status code does not show whether a key authenticated: read the body (userName), or call a protected endpoint.
