On vcst_qa (Customer 3.1033.0, ProfileExperienceApi 3.1024.0), temporary contacts in an org, each holding a role nobody else held, were put through each flow, and contact.organizations, the membership rows, organization.contactRoles and organization.contacts(roleIds) were read after each one. PUT /api/members with the full contact body minus the org removed the link AND deleted the membership row within seconds, so the role also left contactRoles (Customer DeleteOrganizationMembershipUserChangedEventHandler handles MemberChangedEvent org removal). Storefront Delete (status Deleted), Block user (isLocked), an existing-user invite then rejectOrganizationInvite (status Rejected), and a new-user invite then revokeOrganizationInvite (status Deleted) all kept the contact linked and the membership row with its roles, so the role filter still returned the contact. The only flow that produced a membership whose contact is not linked was POST /api/customer/organization-memberships for a user whose contact has no organizations. The endpoint accepts it (it checks only for duplicates), and the role then appears in contactRoles while contacts(roleIds) returns 0.
