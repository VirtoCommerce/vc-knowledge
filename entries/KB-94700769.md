On Return 3.1005.0-pr-28-62f9 a buyer signed in, then PUT /api/platform/security/users set passwordExpired=true. With the old token, returns, return(id), returnableItems, returnPolicy, returnReasons, returnStatuses, createReturn, updateReturn, submitReturn and cancelReturn all succeeded (the draft was actually submitted and cancelled). With the same buyer locked instead (POST /api/platform/security/users/{id}/lock), every one of them answered UserLocked except returnStatuses, which still answered.
