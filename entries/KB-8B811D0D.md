Page A published (everyone, en-US, evergreen), then its content edited (draft row alongside the published one, hasChanges=true). New page B with the same permalink: permalink-usages reports A Certain with canUnpublish=false; publishing B returns 409 both without and with unpublishConflicting=true, error "Pages 'A' are published with the same permalink for the same visitors, and some of them have unpublished changes. Publish or discard those changes first."; afterwards A is still Published with its pending draft content intact and B still Draft. Without pending changes the error reads "... Unpublish them first, or publish with unpublishConflicting=true." and unpublishConflicting=true returns 200: the other page's published row flips to Draft keeping its page id and content (republishing it restores the same id). permalink-usages for a new page lists other Draft pages (conflict None, canUnpublish=false) and Published ones, never Archived ones or the page itself, and nothing from another store. With one Certain and one Possible published page on the permalink, the 409 conflicts[] contained only the Certain page and the error named only it. A builder:read-only user gets 200 on permalink-usages and 403 (empty body) on publishing, with or without unpublishConflicting.
