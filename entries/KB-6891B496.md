On CatalogCsvImportModule 3.1007.0 (same code at 3.1002.0), I imported a hand-built semicolon CSV with the export header, where each row left StartDate empty. This was done both through the Admin catalog Import > 'VirtoCommerce CSV import' wizard and through POST /api/catalogcsvimport/import. The final notification read 'Import finished successfully' with totalCount 0, processedCount 0, errorCount 0 and errors [], and no product was created. The same rows with StartDate filled imported 3/3. In the source, CsvProductReader.ReadProducts catches each row's TypeConverterException and records it on its own progressInfo. DoImportAsync then creates a NEW ExportImportProgressInfo for DoImport, so the per-row reader errors never reach the final notification. Exported files always carry StartDate, so an export→re-import round trip is unaffected.
