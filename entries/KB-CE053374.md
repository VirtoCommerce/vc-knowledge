On vcst_qa (2026-10-07) I read 30 code-sorted catalog products via GET /api/catalog/products?ids=…&respGroup=ItemInfo. Every record carried both minQuantity and maxQuantity as numbers; products without a limit returned 0 (e.g. min 0 / max 0), limited ones returned the limit (e.g. min 10 / max 0, min 0 / max 17, min 10 / max 20). No record had null or an absent field. So in the full product record, 0 means "no limit" on that side, and a caller can treat the value as authoritative; the POST /api/catalog/search/products projection is a separate surface (see KB-11E3EE30).
