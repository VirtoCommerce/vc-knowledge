On vcptcore_qa1, opened order AGENT-TEST-ORD-RET-DEC-PARTIAL (id a1a06e92-4c00-409f-8d10-120e0fe5bcef) as its owning buyer via the real storefront UI (/account/orders -> order detail). This order has an existing return (RET260928-00022, status Requested, submitted via xapi-buyer) per test-data/aliases.vcptcore_qa1.json RETURNS_AUTH_PARTIAL_LINE. The rendered order detail page shows only: order data (Created/Status), line items with disabled read-only quantity spinners, order summary, shipping method, payment method, and a still-active 'Request return' button — no return status badge/section, no RMA/return reference number, no returned-quantity indicator anywhere. Captured the GraphQL traffic: the page's single data query is GetFullOrder (operationName), whose fullOrderFields/shortOrderFields fragments on Query.order request id/number/createdDate/status/items/discounts/totals/shipments/inPayments/availablePaymentMethods/orderTotals — no return-shaped field at all. The only return-related GraphQL calls fired on this page are Query.returnPolicy(storeId) and Query.returnableItems(orderId), both of which describe what CAN be returned (policy + returnable-items list for starting a NEW request), not the status of a return that already exists. Cross-checked against .claude/knowledge/api/graphql-schema.md's live CustomerOrderType field inventory (line 479): no return/RMA field is listed there either. Conclusion: the storefront has no query surface and no UI to show existing-return status on the order the return was made against — a buyer who has already submitted a return sees no acknowledgement of it anywhere on that order's detail page.
