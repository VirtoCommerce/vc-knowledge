On vcst_qa with every organization membership of a buyer set to status Rejected, entering a valid emailed code on /sign-in sends POST /connect/token grant_type=otp_email (organization_id=last-used org) which answers 400 invalid_grant with one errors[] entry code user_is_rejected_in_organization. The page stays on the code step with one inline alert whose text is the raw server description including the organization id: "Your access to organization '<guid>' has been rejected. Please contact your organization administrator." - not the generic "That code didn't work." and not a localized copy without the id (the BL-AUTH-013 case expectation). Observed once through the UI, API shape re-read by a REST replay of the same grant.
