2026-10-06, x-cart 3.1038.0-pr-141-b404 + sales-rep 3.1012.0-pr-21-8964. changeWishlist on a Private list with scope AnyoneAuthorized, User, Foo, or (as a buyer, no targets) Customer returns HTTP 200, data null, errors[{message "Error trying to resolve field 'changeWishlist'.", code INVALID_OPERATION}] - the server's "Unsupported sharing scope" text is not exposed - and a re-read shows scope and sharing key unchanged. createWishlist with scope AnyoneAuthorized, User or Foo is refused the same way and no list is persisted. scope "" on changeWishlist is a no-op success. Case variants are accepted as the canonical scope: changeWishlist scope "organization" sets Organization (org-mate then reads with Write), createWishlist scope "anyoneanonymous" / "PRIVATE" create AnyoneAnonymous / Private lists. The GraphQL WishlistScopeType enum (used only by SharingSettingType.scope) still lists Private, AnyoneAnonymous, AnyoneAuthorized, Organization, User plus Customer from sales-rep, so AnyoneAuthorized and User are output-only values.
