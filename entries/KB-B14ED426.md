A storefront order (createOrderFromCart, status New, no payment) for an organization member was created at 15:22:52Z; an Earned operation of 30000 points appeared in the loyalty operation log at 15:22:54Z, about 2 s later, with no status change. That row carried both userId and the buyer's organizationId, so GET /api/loyalty-program-operation-log/balance/user/{userId} returned 0 while balance/organization/{orgId} included the points. In the operation log every Earned row before the store ran in Organization mode had no organizationId. Caveat observed the same day: B2B-store's Loyalty.LoyaltyBalanceCalculationMode read Customer through the settings API (written ~40 min earlier via POST /api/platform/settings/v2/tenant/Store/B2B-store/values), yet this accrual was still organization-scoped; organization-scoped rows started only after a platform restart two days after the mode had been set to Organization. The effective mode therefore did not follow the settings-API write (cause not established).
