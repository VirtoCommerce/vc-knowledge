Admin REST: POST /api/customer/organization-memberships {userId, organizationId, roles:[{roleId:"org-maintainer"}]} (no roleName) -> 200; GET of the membership shows roles[0].roleName null. Signed in on the storefront as a member of that organization, /company/members ran GetOrganizationContacts and the response carried errors[] "Error trying to resolve field 'name'." (code INVALID_OPERATION, path organization.contacts.items[0].rolesInOrganization[0].name) with rolesInOrganization:[null] for that contact inside HTTP 200; the storefront console logged an ApolloError. After PUT /api/customer/organization-memberships/{id} with roleName "Organization maintainer" the same query returned the role name with no errors. So rolesInOrganization.name is read from the stored roleName, not looked up from roleId, and REST accepts a role without it.
