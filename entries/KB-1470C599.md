On a stand running VirtoCommerce.AdminShell 3.1000.0-pr-1-f481, GET /api/apps/admin-shell/manifest answered 200 with no token. The body held appId admin-shell, the module version and 50 plugins. Each plugin entry was of type script with path /modules/$(<ModuleId>)/plugins/admin-shell/remoteEntry.js plus a hash, a remote {name: <lowercase>_admin, exposed: "./Module"} (e.g. orders_admin), and the module's contributions.menu. All 50 listed remoteEntry.js files were served with 200. The response carries exact module ids and prerelease build versions, so it is readable before sign-in. Modules without a Vue remote (e.g. Hotjar, BuilderIO, TaskManagement) do not appear in it, and their menu items are app or url targets.
