Admin REST: POST /api/members (Contact), POST /api/platform/security/users/create (Customer, storeId B2B-store, memberId), then POST /api/customer/organization-memberships {userId, organizationId, roles:[org-employee]} -> HTTP 200, membership created (status null). GET /api/members/{contactId} still shows organizations: [] and currentOrganizationId null. Signing in on the storefront then yields a /connect/token access token with NO organization_id and NO permission claim, and /company/members redirects to /account/dashboard. After PUT /api/contacts with organizations:[orgId] (HTTP 204) a fresh sign-in yields organization_id = that org and permission [storefront:organization:view, storefront:user:view]. So a REST-built org member fixture needs the contact-organization link as well as the membership row.
