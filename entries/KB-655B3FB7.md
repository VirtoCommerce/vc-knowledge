Admin token, TaskManagement 3.1005.0. POST /api/task-management answered 200 and persisted the task for: {name:""} (name stored as empty string), {name} with no type (type null), {type:"<not in TaskTypes setting>", name} (type stored verbatim), and a responsibleId that matches no member (stored with the given responsibleName; Admin All tasks grid shows that name as Assignee). Notification handler (SendNotificationsWorkTaskChangedEventHandler) only emails when the member is found with an email, so a ghost assignee silently gets nothing. Two inputs answer HTTP 500 instead of 400: a name longer than 256 chars (message is the raw SQL "String or binary data would be truncated in table '<db>.dbo.WorkTask', column 'Name'" text, naming the database and table) and priority set to a value outside the TaskPriority enum (body fails to bind, controller dereferences null -> "Object reference not set to an instance of an object"). Created tasks were deleted via DELETE /api/task-management with the id as a JSON string body.
