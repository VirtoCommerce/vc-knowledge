GET /api/return/{id}/available-statuses, mirrored by the Admin return Status dropdown, lists the statuses a return can move to by an edit, intersected with the deployment's Return.Status dictionary.

On the Return 3.1003 PR build it offered both spellings: New -> [New, Completed, Canceled, Processing, Cancelled], Cancelled -> [Canceled, Cancelled], and the Returns 'All statuses' filter showed both, indistinguishable in translation (de Storniert twice, ru Отменён twice).

From Return 3.1004.0 (ReturnController offers one spelling) only one appears - the one the stand's dictionary holds. Observed live 2026-10-08: on vcptcore_qa1 (dictionary has both plus Draft, Requested, PartiallyApproved, Rejected) New -> [New, Completed, Cancelled, Processing], Cancelled -> [Cancelled], a legacy "Canceled" return -> [Canceled], Draft -> [Draft], Requested -> [Requested], Approved -> [Approved, Completed, Processing], PartiallyApproved -> [Completed, Processing, PartiallyApproved], Rejected -> [Rejected], and the 'All statuses' filter lists "Cancelled" once. On vcst_qa (dictionary: Completed, New, Canceled, Processing, Approved) New -> [Completed, New, Canceled, Processing], Requested and Rejected -> [], PartiallyApproved -> [Completed, Processing], and a PUT to "Cancelled" is refused (400). A decided return moved to Processing offers [Completed, Processing]. vcptcore_stable (Return 3.1001.0) has no such endpoint.
