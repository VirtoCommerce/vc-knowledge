GET /api/return/{id}/available-statuses, mirrored by the Admin return Status dropdown, lists the statuses a return can move to by an edit, intersected with the deployment's Return.Status dictionary.

On the Return 3.1003 PR build it offered both spellings: New -> [New, Completed, Canceled, Processing, Cancelled], Cancelled -> [Canceled, Cancelled], and the Returns 'All statuses' filter showed both, indistinguishable in translation (de Storniert twice, ru Отменён twice).

From Return 3.1004.0 only one spelling appears (ReturnController.OfferOneSpelling): the spelling the return itself is stored with, else "Cancelled" when the stand's Return.Status dictionary holds it, else the one the dictionary holds. So which spelling is offered depends on the dictionary and on the return: on vcst on 2026-10-12 (Return 3.1005.0-pr-28-fb4f, dictionary now holding all 10 values incl. both spellings) New -> [Completed, New, Cancelled, Processing], Cancelled -> [Cancelled], a stored "Canceled" return -> [Canceled]. The list is NOT enforced on save: PUT /api/return validates against the whole dictionary (ValidateStatusChangeAsync, both spellings normalize to one), so on that build a New return PUT with the unoffered "Canceled" was accepted (200) and stored "Canceled", and a closed return can be re-spelled Canceled -> Cancelled; moving a Draft, Requested, Rejected or Cancelled return to another status is refused 400 "Status 'X' cannot be changed to 'Y' by an edit." Observed live 2026-10-08: on vcptcore_qa1 (dictionary has both plus Draft, Requested, PartiallyApproved, Rejected) New -> [New, Completed, Cancelled, Processing], Cancelled -> [Cancelled], a legacy "Canceled" return -> [Canceled], Draft -> [Draft], Requested -> [Requested], Approved -> [Approved, Completed, Processing], PartiallyApproved -> [Completed, Processing, PartiallyApproved], Rejected -> [Rejected], and the 'All statuses' filter lists "Cancelled" once. On vcst_qa (dictionary: Completed, New, Canceled, Processing, Approved) New -> [Completed, New, Canceled, Processing], Requested and Rejected -> [], PartiallyApproved -> [Completed, Processing], and a PUT to "Cancelled" is refused (400). A decided return moved to Processing offers [Completed, Processing]. vcptcore_stable (Return 3.1001.0) has no such endpoint.
