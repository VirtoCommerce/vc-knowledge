Admin bearer token, Platform 3.1076.1. GET /api/catalog/catalogs → 405; POST /api/catalog/catalogs/search {take} → 200 with totalCount matching the Admin Catalog blade count. GET /api/inventory/fulfillmentcenters → 405; POST /api/inventory/fulfillmentcenters/search → 200. GET /api/catalog/search/products → 405; POST /api/catalog/search/products → 200. GET /api/catalog/products?productType=…&take=… and GET /api/catalog/categories?catalogId=… return 200 [] because they resolve only ids= query params. GET /api/platform/security/users?take=10 → 200 [] (use POST /api/platform/security/users/search). GET /api/catalog/products/{id}/variations → 405 (variations come in the variations[] of GET /api/catalog/products/{id}). GET /api/search/indexes/Product → 404 (GET /api/search/indexes lists all types). GET /api/pricing/pricelists/{id}/prices → 404; the Admin prices grid uses GET /api/catalog/products/prices/search?pricelistIds=…&groupByProducts=true. GET /api/pricing/pricelists?keyword=&take= does work (200, totalCount). A test that asserts a 200 status on the GET forms passes without checking anything, because the response is an empty array.
