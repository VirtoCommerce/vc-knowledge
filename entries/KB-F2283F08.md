Firefox 1440, sales rep, keyboard only. Open a task with Enter on its title (Edit task), Shift+Tab to Delete, press Enter: the 'Delete task' confirmation (Cancel / OK) renders on top, but document.activeElement stays on the Edit task's Delete button. Successive Tab presses move through Edit task's own controls (Cancel, Save, Close...) and never enter the confirmation; both dialogs are aria-modal. OK could only be activated with the pointer. Source (sales-rep module StorefrontApp sales-rep-task-modal.vue, tag 3.1016.0) opens VcConfirmationModal via useModal().openModal while the Edit modal is still open, so the confirmation is a sibling dialog and the outer dialog's focus trap keeps focus. Observed once on one task; other browsers not checked.
