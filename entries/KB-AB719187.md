The xAPI me.contact.organizations(searchPhrase) filter resolves through the Member search index, the same path as POST /api/members/search with a keyword. Without a phrase the user's organizations are listed (totalCount 11); with any phrase - partial, full exact name, quoted or unquoted - totalCount is 0 when those organizations' Member documents are missing from the index. Quoting the phrase (as the storefront org switcher does) makes no difference: quoted and unquoted both returned 0 for the unindexed orgs, while other organizations with hyphenated names created on the same day were found by full name. So an org-switcher search returning 'No results found' for every term is first a Member-index freshness question: check keyword search by objectIds+keyword for those ids, reindex them, and only then suspect the code.
