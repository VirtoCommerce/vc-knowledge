vcst, Catalog 3.1046 (PR 909 build), event-based indexation off: with barcode fields = [a Product ShortText property], xAPI products(filter: ... barcode:'<value>') returns 1 hit; after DELETE /api/catalog/properties?id=<id>&doDeleteValues=true (204) and POST /api/search/indexes/index for that product (200), the same query returns totalCount 0 within about 5-10 s, with no errors[]. The store setting still lists the field, and the dedicated barcode fields GET still lists it, while the /fields list no longer contains the property; re-PUT of the same selection returns 400. On a store whose only configured barcode field was the deleted property, the response still listed the deleted field as a filter with isGenerated true, and a GTIN that exists on a product also returned 0.
