2026-11-03, store B2B-store: GET /api/stores/B2B-store lists the setting Stores.AllowAnonymousUsers=false, and a token-less xAPI query store(storeId, cultureName){ settings{ anonymousUsersAllowed } } returns false — that field is what the storefront SPA reads to redirect anonymous visitors to /sign-in (the server answers GET / with 200; the redirect is client-side). In the same state a token-less Query.products request returns HTTP 200 with errors[0].extensions.code=Unauthorized ('Anonymous access denied or access token has expired or is invalid'), so a seeder or probe that reads the catalog as a guest must sign in first. The same products query with a bearer token of a signed-in personal (no-organization) buyer succeeds. It is a store setting, not compiled into the theme.
