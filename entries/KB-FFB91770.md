On SalesRep 3.1012.0-pr-21 (/graphql/sales-rep, rep token), all errors arrive in HTTP 200 errors[] with data null. organizationIds [] / omitted / [''] / legacy organizationId '' -> 'Organization is required.'. 1001 distinct GUIDs -> 'Message must not target more than 1000 organizations.'; 1000 distinct GUIDs -> passes the count and returns 'Access denied.' (Forbidden); 1001 entries where one is an uppercase duplicate count as 1000 (Forbidden, not the cap error); 1000 organizationIds plus a different legacy organizationId count as 1001 (cap error). Whitespace-only id '  ' is NOT treated as missing and returns Forbidden. Empty/whitespace message -> 'Message is required.'; 1001-char message -> length error; neither channel -> 'At least one delivery channel must be selected.'. These validations win over authorization (empty message + unserved org -> 'Message is required.'). A batch mixing a served org with an unserved, or a nonexistent, org (either order, or the unserved one passed as legacy organizationId) returns 'Access denied.' code Forbidden, and no push record or journal entry is created for the served org. A buyer token on /graphql/sales-rep gets Forbidden; anonymous gets Unauthorized. The mutation is also callable by the rep on /graphql.
