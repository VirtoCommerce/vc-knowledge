A MutationObserver installed before navigation logged document.title, h1 and location changes. Cold full loads of /company/dashboard, /company/my-customers, /company/customer-orders, /company/tasks and /company/documents were run with the HTTP cache disabled (first visit). A buyer (no sales-rep permission) saw h1 "404" and title "<store> & 404 Page not found" in 9/10 loads, for 69-126 ms at about 0.9-1.7 s, then landed on /account/dashboard. Anonymous visitors saw it in 10/10 loads, for 44-83 ms, then landed on /sign-in?returnUrl=<route>. A screencast captured the painted 404 frame. With a warm cache the same loads showed no 404: buyer 0/10, anonymous 0/20. A sales rep saw no 404 on the four hub routes (0/4). The same rep, lacking the documents read permission, saw the flash on /company/documents and was redirected to /account/dashboard. Source cause: the plugin manifest gates hub routes with when: userCan(sales-rep:access), so the host declares no placeholder for a non-rep. The plugin does not block boot, so the first navigation falls to the catch-all Matcher, which renders 404 once the slug lookup returns. The plugin's init() then registers the routes for everyone, and reResolveOnceSettled replaces to the real route, whose guard redirects. Whether the 404 paints depends on whether the slug lookup or the plugin settles first. No GA4 page_view titled 404 was observed in 20 flash events: page_view went out with the generic pre-render title at /company/<route>, then with the destination title.
