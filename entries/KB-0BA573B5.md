In the News admin article blade the SEO 'URL slug' was set to a value with a double space, uppercase letters, '&', '%', 'ü' and '!', with SEO Active on. No inline error appeared, Save stayed enabled, PUT /api/news returned 200 and GET /api/news/{id} returned semanticUrl byte-for-byte as typed (double space kept). xAPI slugInfo resolved that exact raw string to the article. The News app's slug field (vc-module-news dev, news-article-details.vue) has only a conditional 'required' rule and the server NewsArticleValidator has no SEO rule, while the platform SEO detail blade (vc-module-seo seo-utils.js) rejects any slug matching /[$+;=%{}[\]|\\/@ ~#!^*&?:'<>,]/ as invalid. So the same value the platform SEO blade refuses is accepted for news articles.
