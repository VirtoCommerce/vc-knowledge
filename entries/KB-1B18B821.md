Nothing computes tax inline. CartAggregate.EvaluateTaxesAsync starts from an EMPTY TaxRate sequence and only fills it by calling taxProvider.CalculateRates, so with no provider every tax field keeps its default: taxTotal 0, taxDetails empty, and taxPercentRate 0 on every line item, shipment and payment. GetActiveTaxProviderAsync gates twice and BOTH gates must pass: the store setting Stores.TaxCalculationEnabled must be true, and the store's own provider list must contain one with IsActive true - it returns Results.FirstOrDefault(x => x.IsActive), so a registered-but-inactive provider is the same as none. There is no error, no warning and no field saying tax was skipped, which is why a zero here reads like a bug in the arithmetic rather than a store that was never configured. On this deployment the two arms of round two that looked both found NO ACTIVE provider for B2B-store while the store setting was true, and they DISAGREED about what is registered: one read the Store blade Tax providers widget as empty, the other read a FixedRateTaxProvider row with isActive false. Nobody has re-checked which.
