Admin Store > Search configuration > Facets writes the store setting Catalog.BrowseFilters.FilteredBrowsing (JSON: Attributes / AttributeRanges / Prices, each with an Order). Reordering an attribute (drag), adding an already-indexed catalog property (HEAD_TYPE) and removing it, and adding/removing a USD price-range bound each showed up on the very next Query.products term_facets/range_facets call and on the storefront /catalog sidebar, with no index rebuild and no cache wait. Price ranges are a list of bounds: Under b1, b1-b2, ..., Over bN; adding bound 75 split range 50-100 into 50-75 and 75-100. GET /api/catalog/aggregationproperties/{storeId}/properties reflects isSelected for the added property. There is no PUT /api/stores/{id}/aggregation-properties endpoint; writes go through the store setting.
