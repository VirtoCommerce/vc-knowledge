The barcode-search blade sorts EVERY row by its display label and only then partitions it: saved (checked) fields first, unchecked after, so within the checked group the order is alphabetical by label, not the stored order. On Catalog 3.1049.0 (and on the PR 909 build the entry and its dispute both saw on vcst, 2026-09-28) barcode-search.js sortRows is `_.sortBy(rows, row => (row.text||'').toLowerCase())` then `filter(isChecked).concat(reject(isChecked))`; the file has a single commit (b1b1b8fc, PR #909) and never changed, so the ordering is the same on both builds. A saved selection [code, gtin] (SKU, GTIN) therefore reopens listing GTIN then SKU. The frozen-while-toggling order, Exact-with-zero-fields disabling Save, Reset, the dirty-close Save-changes prompt, and the separate validation-failed prompt when closing dirty AND invalid all hold.
