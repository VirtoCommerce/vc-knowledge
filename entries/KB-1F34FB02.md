On the stand, B2B-store StoreMode read null in GET /api/stores/{id}. The full store body was read with GET, only the settings[] entry MultiFactorAuthentication.StoreMode replaced (valueType ShortText, objectType Store, objectId = store id) with CustomerChoice, and sent back with PUT /api/stores (204); read-back CustomerChoice, defaultCurrency/defaultLanguage/url intact. Within a minute the storefront's /account/security showed the CustomerChoice switch (Query.mfaSettings storeMode CustomerChoice) and a customer's turned-on mode challenged the next password sign-in - no restart and no Admin store save. Writing value "" the same way read back null again. Unlike Loyalty.LoyaltyBalanceCalculationMode written through the settings API (KB-0761662A), the full-store PUT path needs no Admin save to take effect.
