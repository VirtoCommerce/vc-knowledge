QA Storybook (storefront UI kit), story components-organisms-vcstatwidget--prepend-slot with URL arg loading:!true (switch-vertical icon in the prepend slot). A real pointer click on the prepend icon never lands: Playwright reports that div.vc-loader-overlay intercepts pointer events, for 30 s of retries. Measured: the overlay is position:absolute, z-index 996, pointer-events auto, and spans the card's whole inner box (card 256x106, overlay 251x104 inside the borders), so the head row (prepend, icon, label) is under it. The overlay only blocks the pointer: it is not a focus trap, so a focusable control in prepend would still be reachable by keyboard. Whether a prepend control (the slot doc names a drag handle) should stay operable while loading is not stated by the PR.
