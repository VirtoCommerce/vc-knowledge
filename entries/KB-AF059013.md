2026-10-13, admin token. POST /api/order/customerOrders with items[0].imageUrl set -> GET returns that imageUrl. PUT /api/order/customerOrders with the full GET body and items[0].imageUrl changed (to null, or to a URL on an order created without one) -> 200, but a subsequent GET shows the original value; the same PUT left status, total and createdDate unchanged. So imageUrl is effectively write-once at creation: a seeder that must add images to already-seeded orders has to delete and recreate them (which re-assigns createdDate).
