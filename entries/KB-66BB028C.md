On vcst 2026-11-04 with an admin token (mfa:manage): GET /api/mfa/modes/users/{random guid} answered 200 {mode: Off}; PUT /api/mfa/modes/users/{random guid} {mode: Required} answered 200 and the GET then read Required, while GET .../users/{same guid}/status answered 404. PUT /api/mfa/modes/organizations/{random guid} {mode: Enabled} answered 200, GET read Enabled, and GET .../organizations/{guid}/status answered 200 listing every CustomerChoice store row as isRequired true, requiredBy Organization. So the mode write has no existence check and leaves an orphan object setting; it was reset to Off afterwards (the rows are not deletable through this API).
