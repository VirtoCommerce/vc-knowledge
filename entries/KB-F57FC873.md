saveSalesRepLayout stores the layout as a Customer-module CustomerPreference on the calling user's ApplicationUser id, named SalesRepLayout.<scope> when no storeId is passed and SalesRepLayout.<scope>.<storeId> when one is. The two names are independent: salesRepLayout(scope, storeId) reads only the matching row, so a rep can have a saved layout with storeId and null without it (and vice versa). Deleting the matching row via DELETE /api/customer-preferences?ids=<id> (found with POST /api/customer-preferences/search {userId}) makes salesRepLayout return HTTP 200 with data.salesRepLayout = null and no errors immediately - no cache delay was observed. The preference is not removed when the sales rep is deleted.
