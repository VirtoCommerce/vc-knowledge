Read in code, not observed live on this build (the rep had no list, and creating one was out of scope). The picker is wishlist-customer-sharing.vue in the sales-rep storefront plugin (vc-module-sales-rep @ 7007756): a VcSelect with multiple, autocomplete, clearable and lazy, and no enable-teleport, so its list is rendered inline right after the field inside the Share dialog. In the host UI kit (vc-frontend @ 80e49d1e4, vc-select.vue) the input trigger opens the list on focus (line 91, @focus="open"), options are buttons with tabindex 0 (vc-menu-item.vue line 141), and an option's Tab key is prevented and moves to the next option (line 142, handleTab), wrapping at the end. So after Tab reaches the picker, the next Tab lands on an option and further Tabs cycle through the customers. Message and Share are not reached until Escape returns focus to the picker. The same mechanism was observed live on /account/profile (KB-D179558F). An earlier storefront build showed the same live once (theme 2.59.0-pr-2476, an unfiled draft). Selects whose list is teleported, such as those in the task popups, instead leave the list open over the next field (KB-8424A640). Open vc-frontend PR #2482 (VCST-5923) replaces this model with aria-activedescendant, no open on focus, and close on focusout.
