POST /api/catalog/products/configurations/search is where configurability is read, but an empty criteria body counts configurations regardless of isActive, so its totalCount is not the number of configurable products on the deployment. After creating one configuration and then deactivating it, the empty body returns totalCount 1, {isActive:false} returns 1 and {isActive:true} returns 0, and the product reads isConfigurable false. Since there is no delete route, deactivated rows are permanent, so the empty-body count drifts upward from the number of genuinely configurable products and never comes back. Use {isActive:true} for the count of products a buyer can actually configure.
