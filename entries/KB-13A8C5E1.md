The admin's GET /api/platform/profiles/currentuser read Language 'en' (stored), RegionalFormat null and TimeZone null, although the Manage profile blade displays browser fallbacks for the last two ('English (United States)', the browser time zone). Choosing Deutsch in the blade's Language select saved immediately with POST /api/platform/profiles/currentuser (204) and loaded GET /api/platform/localization?lang=de. The read-back was Language 'de' with RegionalFormat and TimeZone still null. After a reload the whole Admin was German. Choosing English the same way wrote 'en' back, and the read-back matched the starting state exactly. The server ignores settings posted with a null value, so a setting that was never stored cannot be returned to unset through this blade. Each Admin boot also issues two POST currentuser calls that leave the language unchanged.
