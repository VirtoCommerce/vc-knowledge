On vcptcore_qa1 a punchout buyer cart with 5 units was turned into a PunchOutOrderMessage (createPunchoutRequisition) and the matching cXML OrderRequest was posted to POST /api/punchout/cxml after the product stock was lowered to 1 (cart validation PRODUCT_QTY_CHANGED, 2 runs) or the product was set isBuyable=false (CART_PRODUCT_UNAVAILABLE, 1 run). Each time the endpoint answered HTTP 200 with cXML <Status code="500" text="Internal Server Error"/> and no message text, and no customer order was created. The cart was nevertheless saved before the failure: purchaseOrderNumber = the OrderRequest orderID, Shipping and Billing addresses from ShipTo/BillTo, one shipment with no shipmentMethodCode, and one payment with no paymentGatewayCode for the cart total. After restoring the stock or isBuyable, re-posting the same document returned Status 200 and created exactly one order. Source (vc-module-punchout d2e3683): CreateOrderFromCart throws GraphQL.ExecutionError, not FluentValidation.ValidationException, so the processor's generic catch maps it to OrderError (500, no message). The module's developer QA plan expects 400 with the validation message.
