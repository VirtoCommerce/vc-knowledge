In the Page Builder shell page blade, permalinks '/my page test 0812', '/page&test?q=1#anchor0812' and '/страница-тест-0812' were all saved as typed ('Page saved successfully', GET grouped returns the raw permalink) and published. On the storefront the space and Cyrillic permalinks resolve (browser percent-encodes them), but '/page&test?q=1#anchor0812' typed or linked as shown in the blade (storefront host + permalink) returns the 404 page because ? and # start the query/fragment; only the fully percent-encoded path /page%26test%3Fq%3D1%23anchor0812 resolves the page.

Build range (judged 2026-10-29): the 'no sanitising or validation' clause holds only up to VirtoCommerce.PageBuilderModule 3.1037.0 (no PageBuilderPermalink rule in the source). From 3.1038.0 (vc-module-pagebuilder PR 178, VCST-6443, released 2026-10-27) POST create-group-page, POST grouped and PUT grouped reject a permalink with whitespace, control or format characters, ? # & % \ " < > { } | ^ `, '//', '.' or '..' segments, or more than 2048 characters with 400 text/plain, and the Page Builder shell shows a field error and disables Save. Cyrillic is still accepted and stored verbatim. On 3.1038.0 a page with ? or # can no longer be saved through these doors; the 404-at-natural-URL clause above was not re-checked and describes permalinks stored before the rule.
