Read in vc-frontend-next source at PR #11 head d67b0e0a and on dev: client-app/pages/matcher/matcher.vue overrides the previewer priorities with internal: 0 ("'internal' always wins so the built-in main page is never replaced by Builder.io or page builder content"), and internal.vue maps the root path '/' to pages/demo-home/demo-home.vue (introduced by commit a9f509b2, VCST-6048 #2508, 2026-09-24). Upstream vc-frontend 2.60.0 has no such override, so there Page Builder content for '/' wins. Live on vcst_qa theme 3.1.0-pr-11 the home page DOM is div.matcher > div.demo-home with hero/categories/popular/suppliers/why-buy/changes/brands/cta sections and no Page Builder block markup. Consequence: a case needing a Page Builder block on the home page cannot run on the Next theme; use a dedicated Page Builder page instead.
