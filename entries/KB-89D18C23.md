Guest, Chromium, store B2B-store (default culture en-US). Product c94d730a-a1e3-41d3-bba6-8e9eb9fe45e8 has an SEO URL only in de-DE (vintage-wedding-cake under products-with-options/dreamy-cakes). Opening /products-with-options/dreamy-cakes/vintage-wedding-cake in a new tab with empty sessionStorage (previousCultureSlug {"",""}) renders the client-side '404 Page not found' view (title 'QA & 404 Page not found', HTTP 200 soft 404). The same URL renders the PDP only when it is reached through the language selector, because the session then carries previousCultureSlug {de-DE, slug} and GetSlugInfo is asked in de-DE. So the en-US URL the language switch produces is not shareable for such a product. Observed on theme 2.61.0-pr-2604-149a (local storefront, vcst_qa backend); the fix for VCST-6501 does not change it.
