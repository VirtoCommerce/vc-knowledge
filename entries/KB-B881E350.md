vcst_qa, 2026-11-04, regression REG-2026-11-04-1531 case MFA-035. Created a disposable store with MultiFactorAuthentication.StoreMode=Disabled and three Customer accounts bound to it (emailConfirmed, twoFactorEnabled false, user.Roles empty): a role-less customer; an organization employee whose 'Organization employee' role is set only on its POST /api/customer/organization-memberships row; an organization maintainer whose run role (incl. xapi:my_organization:mfa:manage) is set only on its membership row. With global MultiFactorAuthentication.Enabled=true, POST /connect/token grant_type=password with storeId=<that store> answered 200 with access_token+refresh_token and no twoFactorToken for all three; no MfaSignInEmailNotification journal row was written for any of them; GET /api/mfa/modes/users/{id}/status read isDisabledModeSkipped=false, isRequired=false, requiredBy=None for all three on that store. Cross-check on existing stand users (global off, status API only): two users whose org role is only on the membership read isDisabledModeSkipped=false on every store; a user whose 'Organization maintainer' role is in user.Roles reads true on some stores. So the Backoffice-account check (IAdminUIAccessPolicy over role permissions) reads user.Roles, not membership roles; the 'any org role loses the Disabled skip' population (KB-9CE07DBB, VCST-6686) is the user.Roles holders.
