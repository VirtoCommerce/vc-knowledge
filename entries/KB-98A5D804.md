Introspection of the live /graphql schema (admin token, Xapi 3.1024.0, XOrder 3.1013.0, XCart 3.1038.0 PR build) lists these order-related mutations: createOrderFromCart(cartId), changeOrderStatus(orderId, status), initializePayment(orderId, paymentId, storeId, cultureName, parameters), authorizePayment(same shape), addOrUpdateOrderPayment(orderId, payment), updateOrder*DynamicProperties, plus cart-side ones. No mutation named processOrderPayment exists, although the published xOrder developer guide documents a process-order-payment page. Queries: order(id, number, cultureName), orders and organizationOrders (after, first, sort, facet, filter, cultureName, userId / organizationId), orderStatuses, orderLineItemStatuses, paymentStatuses, shipmentStatuses (each returns items of key/value). The orderStatuses dictionary holds 8 entries: Cancelled, Completed, Custom, New, Payment required, Pending, Processing, ReadyForPickup (label Ready for pickup); 'Paid', used as the example status value in the published change-order-status page, is a payment status, not an order status. Anonymous calls to orders and order return an Unauthorized error.
