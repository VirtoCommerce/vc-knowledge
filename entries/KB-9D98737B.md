Read at vc-module-mfa@1a0f481, MfaSelfService.GetSettingsCoreAsync: CanChangeUserMode = isCustomerChoice && UserMode != Required, with no look at the organization modes; ChangeUserModeCoreAsync refuses only when CanChangeUserMode is false. So in a CustomerChoice store a member of a Required or Enabled organization is not refused by the API (the widget hides the switch), and the stored user mode changes. The sign-in requirement is unchanged because GetChosenRequirement checks the organization modes first (requiredBy Organization). NOT observed live; also PUT /api/mfa/modes/users/{id} writes the setting for any non-empty id without checking the user exists, while GET .../status answers 404 for an unknown user (MfaModesController, MfaModeService.SetModeAsync).
