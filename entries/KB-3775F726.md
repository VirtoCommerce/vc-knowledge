On Stable 16 a contact's Html and LongText dynamic property values containing <b> plus an img onerror / svg onload probe (harmless text/title markers) were stored and returned by GET /api/members/{id} byte for byte. Reopening the contact in Admin shows the Html value in a code editor and the LongText value in a textarea as literal source; neither probe fired (no inserted text, document.title unchanged). No storefront JS chunk references dynamicProperties, so member dynamic properties are not rendered there. Any consumer that renders these values as HTML must sanitize them itself.
