vcst_qa 2026-10-29, Node fetch against the storefront host. Query.passkeyCreationOptions and Query.passkeyRequestOptions answer with Set-Cookie Identity.TwoFactorUserId (path=/, secure, samesite=lax, httponly) - the ceremony state. Without that cookie, Mutation.createPasskey with a valid attestation (fmt none, ES256, clientDataJSON origin = storefront origin) answered errors[].code INVALID_OPERATION 'Error trying to resolve field createPasskey'. With the cookie but no Origin request header it answered succeeded=false, errors[].code invalid_passkey_attestation 'The authenticator response had an invalid origin https://<storefront host>'. With the cookie AND Origin: https://<storefront host>, createPasskey succeeded=true, and POST /connect/token grant_type=passkey (form, scope offline_access, storeId, credential = the assertion JSON with userHandle = user.id from the creation options) answered 200 with tokens when the same cookie and Origin were sent. A browser sends both automatically, which is why the in-page flow works.
