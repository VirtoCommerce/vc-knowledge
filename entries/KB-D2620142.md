Admin Stores > store > widget 'Debug SEO' opens 'Debug SEO links' (Store and Default language read-only; Language code select listing the store's languages, preset to the default; Permalink; Organization; Debug disabled while Permalink is empty). Debug calls GET /api/seoinfos/explain and opens 'Debug SEO links Stages' with 7 rows: 'Stage 0: Candidates - SEO records with this slug that the resolvers considered, including the rejected ones.' then Stages 1-6 with unchanged titles. Stage 0 opens 'Debug SEO links Candidates' with columns Semantic URL, Resolved, Rejection reasons, Object Type, Object ID, Language, Store, Active and the footnote 'Rejected records are listed only for modules that can explain their resolution.' (shown for ContentFile results too). Reasons are joined with '; ' and long ones are truncated in the cell. Clicking Stages 1-6 swaps the child blade to the items grid and Stage 0 swaps it back, with no stale blade. When nothing has the slug the Stages blade shows 'Nothing found for your request' and no rows.
