On Platform 3.1076.1 with BackgroundJobs 3.1052.0 and Subscription 3.1005.0, one storefront order placed with a manual payment method failed its background job on all 3 retries, at Orders[0].InPayments[0].PaymentMethod.PaymentMethodType in JsonJobPayloadSerializer.Deserialize. That was the only order and the only new failed job that day. Subscription's CreateSubscriptionOrderChangedEventHandler enqueues CreateSubscriptionsFromOrdersJob with a payload whose Orders property is CustomerOrder[], so the whole orders, payments included, are serialized. BackgroundJobs serializes payloads with its own static JobJsonSettings.Default, which has no TypeNameHandling and no platform polymorphic converters, so the abstract PaymentMethod cannot be recreated. No configuration setting changes JobJsonSettings, so this is a code defect in the payload design, not missing settings. The Orders module's job payloads and Loyalty's carry order ids instead and do not fail this way. Effect: the subscription handler never runs, so no subscription is created from any order. Placing the order itself is unaffected.
