Started a Product Build (POST /api/search/indexes/index) and, while it ran, a Category Build. The second run's notification got "Indexation is already in progress.", and the platform pod that executed it logged: "Lock status: Conflicted (Acquired: 0, Conflicted: 1, Error: 0), vcptcore-qa1:IndexationJob" followed by "ERR Indexation skipped: the 'IndexationJob' lock is held by another run, so nothing was indexed. JobId: <id>, User: admin, DocumentTypes: Category. If this repeats, the lock is stuck behind a hung indexation holder." This was seen for 5 contended runs in the pod logs pulled from Argo CD. Every acquired run logs "Lock status: Acquired". A lock-store failure would log "Indexation could not run under the 'IndexationJob' lock" instead; no such line appeared. Search the pod logs (stdout, Serilog Console sink) for "Indexation skipped" or the job id.
