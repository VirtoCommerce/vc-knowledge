Wrote the setting with POST /api/platform/settings (false -> true) and read it back. A product rename saved right after became findable by its new keyword in xAPI Query.products within ~6.6s and the revert dropped out within ~6.3s, far from the next IndexChangesJob tick (cron 0/8). Control with the flag false: the same kind of rename was NOT findable within 79s. The catalog handler IndexProductChangedEventHandler reads the setting per event, so no restart is needed. Two traps: xAPI Query.products returns the product name hydrated from the database, so the returned name changes instantly even when the index did not; assert on a keyword hit instead. And price/inventory index updates are gated by Pricing.Search.EventBasedIndexation.Enable and Inventory.Search.EventBasedIndexation.Enable, not by the catalog flag.
