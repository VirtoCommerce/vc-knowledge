GET /api/seoinfos/explain (and the Admin Debug SEO links tool) for '<never-used-parent>/<slug>' on a Long-links store, where <slug> belongs to four top-level categories, returned 7 stages: Candidates 4, every record isResolved false with PermalinkMismatch and details '<slug>' (the store's own link), Stages 1-6 empty. ParentNotResolved ('The parent path doesn't resolve') was not reported. In the Catalog resolver (catalog PR 910) the parent check only runs when at least two objects already have a store path equal to the requested permalink; when none does, each record is rejected by its path instead. So ParentNotResolved does not appear for a mistyped parent of a category slug.
