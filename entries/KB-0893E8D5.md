As admin on QA-STORE, set SiteBuilder.Store.GitContentEnabled=true while the platform's GitHub App was configured but not installed on its organization (git/site answered enabled:true with an error naming the organization / app installation). POST /api/site-builder/designer/save of a database page -> 200; grouped publishing -> 200 and the page content went live; history/status -> {status:'enabled'}. The Site Builder page list showed no warning (its only requests were the store read and the pages list; it never called git/site), and the designer showed no warning ("Version history" in the toolbar instead of "Enable history"). After resetting the setting to false: no warning, "Enable history". The developer's round-2 note said such a store should get an error instead of publishing live and see a warning with a GitHub-setup button; neither happened on this build. Setting restored to false and re-read.
