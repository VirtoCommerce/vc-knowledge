On vcptcore_qa1 (2026-09-30, VirtoCommerce.Otp, DetailedErrors on) POST /api/otp/request {storeId: B2B-store, email} for a Customer contact whose account storeId is AGENT-TEST-OTP-FOREIGN-STORE (no such store; not in B2B-store.trustedGroups) returned 200 {outcome: StoreAccessDenied}. The same request for a fresh Administrator (isAdministrator true, no member, no storeId) and for a Manager with no member and no roles both returned CodeSent, as did a contact on New-super, a store in B2B-store.trustedGroups. So the store rule refuses a non-matching storeId without needing the store to exist, and exempts administrators and non-contact accounts at request time.
