Two-org B2B buyer, BuildRight active, TechFlow non-active, memberships locked through the REST lock endpoint. At 1280x900, /account/dashboard > header 'Organizations' button (data-test-id=organizations-button) opens a dialog 'Organizations' with listbox 'Organizations'. With TechFlow permanently locked (isLocked=true, lockoutEnd null, isCurrentlyLocked=true): 2 options, BuildRight [selected], TechFlow [disabled] with a padlock icon; its accessible name is the org name only; ArrowDown in the listbox skips it. The page-context response still reports contact.organizations.totalCount=2 and the organizations list returns isLockedForCurrentUser true for TechFlow only. A lock applied while the user is signed in does not evict the session: client-side navigation keeps working, every /graphql stays 200, and the next panel open shows the row disabled (also in a second tab of the same context). After the lock is removed (no re-login, ~70 s later, fresh page load) the row is enabled with no padlock. With isLocked=true but lockoutEnd in the past (isCurrentlyLocked=false) the row is enabled from the first load and stays enabled after a 65 s wait. With an option disabled, the listbox state, selected org and position are identical across a reload and across a ~130 s idle wait.
