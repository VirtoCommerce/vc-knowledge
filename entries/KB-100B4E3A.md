Chrome 155, 1440x900. Schedule call opens with Due date empty (placeholder MM/DD/YYYY) and Save disabled. After a real click into Due date and then into Title (or Tab through it) the field gets aria-invalid=true, aria-describedby=input-N-details and a red 10 px message 'this is a required field' (yup default text, lower case, no field name). Measured before/after: the Due date + Time row grows from 66 to 82 px (+16); Priority, Notes, the Add to calendar fieldset and the Cancel/Save buttons move +8 px and Title, Customer, Due date and Time move -8 px because the dialog is vertically centred; no x shift. The message is a plain div linked by aria-describedby; it sits in no role=alert/status/aria-live region (the only live regions in the dialog are the empty VcSelect sr-only polite spans), so it is not announced when it appears, only when the field is refocused. Picking a day removes the message and the layout returns. The same insertion mechanism applies to the Title error ('this is a required field' under an emptied Title). Violates BL-UI-003 (validation-message insertion must not move adjacent elements); the empty required Due date is the default state of Schedule call, so the path is hit by simply tabbing through the form.
