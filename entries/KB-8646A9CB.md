With the deployment's lockout policy (5 failed attempts, 15-minute lockout, detailed errors on), the next failed sign-in returns user_is_temporary_locked_out with lockoutEnd about 15 minutes ahead. Organization members used to receive the permanent code user_is_locked_out ('contact your administrator') for the same temporary lock, because an organization validator treated any future lockoutEnd as permanent; that was fixed and they now get the temporary code too. An administrator's organization block is a different path: it yields user_is_locked_in_organization. A failed-attempt lockout does not change the contact's status.
