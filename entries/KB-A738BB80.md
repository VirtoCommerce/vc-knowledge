Dead session simulated as in KB-80B0069F: expires_at in the past and an invalid refresh_token, then the addresses table page switch. The refresh fails, which emits unauthorizedErrorEvent: fetchUser, then router.push to sign-in. The page request itself then goes anonymous and gets errors[] code Forbidden, which emits forbiddenEvent and routes to /403. The final page was /403 on 1 of 2 runs and /sign-in?returnUrl=/company/info on 1 of 2 runs for theme 2.62.0-pr-2620, and the same 1 and 1 for 2.62.0-pr-2647. So the two handlers race, and the PR 2647 watcher fix does not decide the outcome. On /403 the user is already anonymous (header shows Sign in), and the page says 'You do not have permissions to access the requested page'. Not checked against docs.
