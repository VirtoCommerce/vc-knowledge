Edge lane, virtual authenticator, B2B buyer on store B2B-store. A passkey was registered under the password session, then an admin POST /api/platform/security/users/{userName}/resetpassword {forcePasswordChangeOnNextSignIn:true} (same password) made GET user read passwordExpired=true. Control: the storefront password sign-in lands on /change-password?returnUrl=/ (heading 'Change your password'; the route is /change-password, not /account/change-password). Passkey: /sign-in loaded with presence off, presence on, 'Sign in with Passkey' clicked: POST /connect/token grant_type=passkey 200, then the browser lands on /change-password?returnUrl=/ as well; the page's own xAPI Query.cart for the buyer answers HTTP 200 with errors[].code PasswordExpired and cart null, and the console logs ApolloError 'This user has their password expired'. The Sign-in log records a succeeded Passkey row. So the expiry is enforced on a passkey session; BL-AUTH-018 says it should be enforced only for a password sign-in (VCST-6630). After resetpassword {forcePasswordChangeOnNextSignIn:false} the flag reads false again.
