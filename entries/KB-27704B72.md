On vcst 2026-11-04 with an admin token: a disposable customer account and its organization were created by the MFA fixture creator; PUT /api/mfa/modes/users/{userId} {mode: Required} and PUT /api/mfa/modes/organizations/{orgId} {mode: Enabled} answered 200. The account, contact, memberships and organizations were then deleted (DELETE /api/platform/security/users?names=..., DELETE /api/members?ids=...; GET by id afterwards returned empty). After deletion GET /api/mfa/modes/users/{deletedUserId} still answered 200 {mode: Required} and GET /api/mfa/modes/organizations/{deletedOrgId} 200 {mode: Enabled}; GET .../users/{deletedUserId}/status answered 404 and GET .../organizations/{deletedOrgId}/status 200 (no required rows once the only CustomerChoice store was deleted too). The module keeps modes as platform object settings (ObjectType ApplicationUser / Organization) and registers no delete handler, so the setting row outlives the entity; it can only be set back to Off through this API, not removed.
