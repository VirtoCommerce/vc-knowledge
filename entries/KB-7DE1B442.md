A storefront buyer's own checkout orders carry customerId = the security account id (POST /api/order/customerOrders/search with customerId=<user id> returned 49 orders; with customerId=<contact/member id> returned 0). Three orders then created via admin POST /api/order/customerOrders with customerId = user id, organizationId = the buyer's token org, storeId B2B-store, USD, status New, one line each, were counted immediately by Query.orderStatistics for that buyer's password-grant token: period over their creation window gave count 3 / total 755.25, and the week and month-to-date periods moved from 0 to 3 / 755.25 with no reindex or wait. So stamp customerId with the user id, not the contact id.
