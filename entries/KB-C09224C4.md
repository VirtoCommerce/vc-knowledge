Global MultiFactorAuthentication.Enabled=true, a store-less Manager with a back-office role signed in on #!/login. On #!/sign-in-code the Code input is document.activeElement on arrival, a 'Resend code in N s' countdown starts at 30, the email is masked (a•••e@example.com). A wrong code (POST /api/mfa/signin/verify) shows "That code didn't work. Check it and try again." inside a role=alert element and focus stays on the input; the input carries no aria-invalid and no aria-describedby. The card is vertically centred and grows when the alert appears, so the input moves up 29px (top 542 -> 513 at 1920x1080). Sign-in log: 3 x MFA InvalidCode, the 4th wrong code logs MFA CodeAttemptsExceeded and the screen replaces the form with role=alert "Too many incorrect codes. Wait a few minutes and sign in again." (focus falls to BODY). Signing in again with the right password within ~1 min logs Password RequiresTwoFactor + MFA CodeAttemptsExceeded immediately, sends no new code, and shows the same message. Right code -> #!/workspace, log Password RequiresTwoFactor + MFA (no reason). Resend after the countdown shows "Code sent again." as plain text (no role/aria-live) and sends a new code. A Manager with emailConfirmed=false gets role=alert "We can't send a sign-in code to this account. Confirm its email or contact your administrator."; log Password RequiresTwoFactor + MFA ProviderNotAvailable. Opening #!/sign-in-code with no pending sign-in shows, after ~1-3 s of a disabled form, role=alert "Your sign-in session has expired. Sign in again." (localized, no raw key). With global off the same Manager signs in in one step (one Password row, no reason).
