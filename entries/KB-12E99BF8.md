On vcst_qa (theme 2.61.0-pr-2570-5cc5, whose head commit 5cc519ff built vc-frontend PR 2570; MFA module 3.1000.0-pr-1-41b3) an anonymous POST of {twoFactorToken:"bogus",provider:"Email"} to the STOREFRONT host at /api/mfa/resend returned HTTP 405 from nginx (an HTML "405 Not Allowed" page), while the same body to the back-office host answered the platform's JSON (200, succeeded false, invalid_two_factor_token). On the same storefront host POST /connect/token grant_type=mfa answered the platform's JSON 400 invalid_two_factor_token and POST /api/otp/request answered 200 user_not_found, so those paths are routed and /api/mfa is not. The PR's useMfaSignIn calls the relative path "/api/mfa/resend", the same pattern as the OTP request that was blocked the same way on this stand earlier (VCST-5748). Not exercised through the UI because MultiFactorAuthentication.Enabled was off.
