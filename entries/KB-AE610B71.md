On storefront 3.0.0-alpha.2685 (Paprika theme), signed in as the buyer, order details > Request return opens /account/returns/new/{orderId} (title "Select items to return"). The lines render in a VcTable (div.vc-table > table.vc-table__desktop, caption "order lines available for return") with columns Item / Ordered / Returnable / Return qty. The table has no selection column and no per-row checkbox. A line is selected by giving it a Return qty above 0, either with the per-row number spinbutton (aria-label "Return quantity for <product name>", min 0, max = returnable) or with the "Select all eligible lines" checkbox above the table, which fills every eligible line's qty with its returnable quantity. The footer then reads "1 selected · N items" and Continue becomes enabled. The row element itself never changes: class stays "vc-table__row", there is no vc-table__row--selected and no aria-selected, and its background stays transparent whether qty is 0 or 5. Hover is a real background on the tr: light #f1eae0 on the widget's #fffdf9 (about 1.18:1), dark #2f2722 on #29201b (about 1.09:1), the same on a line with qty 0 and qty 5. The vc-table selected-row fill (primary at 8% light / 16% dark alpha) is never applied on this page, because the page's VcTable sets no selectionMode. The only cues that a line is selected are the qty value in its input and the footer count. Keyboard: Shift+Tab from the qty input reaches the select-all checkbox (visible 2px focus ring), Space toggles it, Tab returns to the qty input, and ArrowDown lowers the qty.
