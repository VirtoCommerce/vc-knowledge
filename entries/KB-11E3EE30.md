Yes on both. On vcst_qa (2026-10-05) each item of POST /api/catalog/search/products {responseGroup:'ItemInfo'} carries minQuantity, maxQuantity (0 = no limit), packSize, trackInventory and isBuyable, matching GET /api/catalog/products/{id}. Without a sort the page comes back in index order (it shifts whenever the catalog changes); adding sort:'code:asc' (or sort:'code') returned the page ordered by product code. GET /api/catalog/products?ids=..&ids=..&respGroup=ItemInfo returns the same fields for a batch of ids, and a deleted id is simply absent from the array.
