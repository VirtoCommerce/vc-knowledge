Electronics store (no theme publication yet), admin MCP token on POST /admin/mcp. create_section_type saved a draft custom type; create_page made a never-published landing page; edit_page_draft add_section placed the type on that page's draft. search_site_pages with section_type then found the page and section ("Scanned all 2 pages"). publish_theme dryRun called right after answered drafts[0].placed_sections = {pages: [], coverage: "Scanned all 2 pages (2 language versions). Templates are not scanned..."}. So the dry run's page list counts published page versions only: a page that places the type only in its draft is not named, and the coverage text does not say any page was skipped as unpublished. In the module source at the build's PR head, ThemePublishingTools.DescribeSectionTypeAsync calls SectionTypePages.FindAsync with published: true (change_section_type's dry run uses published: false), and SectionScanCoverage.Describe excludes NotPublished pages from its unread count. No published page existed on the store, so the positive published branch was not observed live.
