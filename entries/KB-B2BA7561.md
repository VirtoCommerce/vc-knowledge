Observed on a dev stand (Platform 3.1077.0-alpha, Seo module PR build for the explain-candidates change). Store > widget "Debug SEO" > "Debug SEO links" form > Debug opens the Stages blade; its first row "Stage 0: Candidates" opens the blade "Debug SEO links Candidates", a fixed 810 px wide (__xlarge-wide) ui-grid with 8 columns in this order: Semantic URL, Resolved, Rejection reasons, Object Type, Object ID, Language, Store, Active. Resolved and Active render an `<i class="table-ico fa fa-check">` when true and nothing when false. Rejection reasons are joined text from candidate-reasons translations (with ": details" appended, e.g. "The store's link to it is different: seed-books/seed-books-fiction"). A footnote "Rejected records are listed only for modules that can explain their resolution." is shown under the grid in every non-empty state. Long values are clipped with text-overflow: ellipsis (no escape into the next cell, no document scroll at 1920/1280/1024): header cells carry a title tooltip, Rejection reasons cells carry a title tooltip, but Semantic URL / Object Type / Object ID cells have none. Default column widths are ~77 px for Semantic URL/Object Type/Object ID and 231 px for reasons, so a 36-char GUID shows as "efa1eab…" and a 52-char base64 ContentFile id as "QjJCLXN…"; maximizing the blade at 1920 widens the reasons column enough to read a 66-char reason but the 36-char GUID stays truncated (275 px needed, 201 px available). Object ids are 32-char (catalog category) or 36-char hyphenated GUID or a 52-char base64 id for ContentFile records. An unknown slug yields an empty Stages grid with the message "Nothing found for your request" at the bottom of the Stages blade (the Candidates blade cannot be opened); that message is a div[ng-if] > em with no role/aria-live.
