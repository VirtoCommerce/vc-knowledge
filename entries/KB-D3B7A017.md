Admin signed in, Tasks app (/apps/tasks) > All tasks > Filters > Type filter 'Other' > Apply gave 29 tasks with a page size of 20. Page 1 read '1–20 of 29' (correct). Page 2 sent POST /api/task-management/search {take:20, skip:20, type:'Other'} and showed the remaining 9 distinct rows, but the label read '16–24 of 29' instead of '21–29 of 29'. The unfiltered list of 58 rows labels page 2 '21–40 of 58' correctly, because there ceil(58/3) = 20 equals the page size. The vc-shell framework 2.1.0 bundled in the app computes the counter as from = (currentPage-1) * ceil(totalCount/pages) + 1 and to = min(from + items.length - 1, totalCount), using total/pages as the page size instead of the real page size. The vc-shell docs describe the counter as 'Showing X-Y of Z' for the displayed rows, and their VcPagination recipe uses (currentPage-1)*pageSize+1. The rows and the request are right; only the label is off. KB-359D6046 is the same symptom in the Sales Reps app ('14–18 of 25' for rows 21–25), which matches the same formula.
