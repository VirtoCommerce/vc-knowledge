On FileExperienceApi 3.1007.0-pr-25, XCart 3.1040.0-pr-149, XOrder 3.1015.0-pr-55, Quote 3.1004.0-pr-159 (Platform 3.1076.0): a text file uploaded to POST /api/files/product-configuration, attached via Mutation.addItem configurationSections File fileUrls, then converted with Mutation.createOrderFromCart, reads 200 with identical bytes for the ordering buyer (also after a fresh token) and for admin; 403 for a buyer of another organization (including one holding the Organization maintainer role in other organizations), 403 for a customer with no organization, and 403 anonymously. Query.order files.url carries the same /api/files/{id} that was uploaded. The same file while still cart-owned reads 200 for the cart owner and 403 for other buyers and anonymous. Measured 5 orders (3 single-file, one 2-file order across two configurable lines, all 200 for owner). Orders placed before these builds keep files that read 403 for every non-admin non-owner tested; the owner's read of such legacy files was not measured. Pre-fix builds returned 403 to the owner after order creation (VCST-5995).
