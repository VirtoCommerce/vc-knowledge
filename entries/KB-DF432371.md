Established live on vcst-qa (BACK_URL=https://vcst-qa.govirto.com). A storefront customer account (role __customer, 0 permissions in the token) minted a valid platform token via POST /connect/token password grant. Against SettingController (vc-platform Web/Controllers/Api/SettingController.cs, class-level [Authorize] + method-level [Authorize(SettingQuery)]): GET /api/platform/settings -> 403; GET /api/platform/settings/modules/{id} -> 403; GET /api/platform/settings/{name} -> 403. But TWO actions are NOT SettingQuery-gated and returned 200 to the same non-admin token: GET /api/platform/settings/values/{name} (decorated only with [ApiExplorerSettings(IgnoreApi=true)], NO permission attribute — only the class [Authorize], so any authenticated identity reads it; returned array of the setting's AllowedValues/Value) and GET /api/platform/settings/ui/customization ([AllowAnonymous] — even an unauthenticated request returned 200). Anonymous (no token) got 401 on all the [Authorize]-gated routes and 200 only on ui/customization. So a non-admin token cannot enumerate or read arbitrary named settings, but CAN read any single setting's value list via /values/{name}, and anyone can read ui/customization. SettingQuery/SettingUpdate are the platform permissions gating query/update.
