Created a disposable contact via POST /api/members with an address Line1 of 128 chars (200 OK), then re-saved it via PUT /api/members with Line1 of 129, 200, 256 and 300 chars: every one returned HTTP 500 with a DbUpdateException / SqlException 'String or binary data would be truncated in table ...Address, column Line1' — the Customer module has no length validator, the DB column is nvarchar(128). Via xAPI mutation updateMemberAddresses (admin token) Line1=200 returned a GraphQL error with code DB_UPDATE (the ProfileExperienceApi AddressValidator allows up to 256, above the column size), Line1=300 returned code VALIDATION. Cart and order addresses store Line1/Line2 up to 2048, so an address copied from an order/cart into the customer address book with Line1 > 128 cannot be saved. Same on two stands with different Customer module lines (3.1011.1 and 3.1029.0).
