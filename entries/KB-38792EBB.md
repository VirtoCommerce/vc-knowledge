User with roles A (admin-shell:access + order read) and B (admin-shell:access + marketing read). PUT /api/admin-shell/menu/roles/B {"sections":{"marketing":{"hidden":true}}} -> 204: the user's GET /api/admin-shell/menu still shows section marketing; adding the same patch to role A removes it; the same with {"items":{"marketing":{"hidden":true}}}. Single-role users and the administrator are unaffected. PUT {} on both roles restores the menu and GET roles/{id} returns the empty patch. The hide counts even from a role that has no permission for the item. PUT to a role id that does not exist also answers 204 and is stored and returned by GET (no validation, no cleanup endpoint).
