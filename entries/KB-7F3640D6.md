On vcst_qa, a Number property created with POST /api/catalog/properties on one category (catalogId = an AGENT-TEST physical catalog, categoryId = a root category of it that is linked into B2B-store's virtual catalog) was returned by GET /api/catalog/aggregationproperties/B2B-store/properties right after creation. Source agrees: for a virtual catalog the list is every property (catalog- or category-level) whose CatalogId is a physical catalog that owns a category linked into the virtual catalog (CatalogRepositoryImpl.GetAllCatalogPropertiesAsync), plus the Price <currency> rows and __outline/__outline_named/__path. A property that exists only as inline product values (no definition) is not in that list, so it cannot be picked as a facet in the admin blade. Products of that category inherit the category property and their values index as a numeric field.
