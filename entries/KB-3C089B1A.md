On vcst_qa, two buyers with no back-in-stock subscriptions called activateBackInStockSubscription(storeId, productId) and then deactivateBackInStockSubscription for the same product (isActive false returned). Afterwards Query.backInStockSubscriptions(storeId, first 100) for each buyer still listed those subscriptions with isActive false (3 rows for one buyer, 1 for the other). Running the same activate a second time returned the SAME subscription id as the first time, so the number of rows stays one per buyer and product. xAPI has no mutation that deletes a subscription; a case that subscribes leaves an inactive row, not nothing.
