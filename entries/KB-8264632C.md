The cart page has ONE coupon slot and it is driven by CouponType.isAppliedSuccessfully, not by whether a coupon is on the cart. A coupon that applied renders as a DISABLED box holding the code with a remove control beside it; a coupon that is on the cart and did NOT apply renders as an ENABLED box holding the code with an Apply button -- visually identical to text the shopper typed and never submitted. So a stored-but-dead code is unannounced: no error, no marker, and Discount just reads 0.00. The page shows exactly one entry, so when a cart holds several the others are invisible; the remove control takes away only the code it names, and a dead one left behind then takes over the single slot. The only page-reachable way to get rid of a dead code is Clear cart, which drops the coupons along with every line item -- there is no control that removes a coupon the page is not calling applied. Pressing Apply runs Query.validateCoupon FIRST and calls addCoupon only if it came back true, which is why a wrong code typed on the page never reaches the cart even though the mutation would happily store it. The message shown for false -- 'This code does not match any active coupons' -- is the page's own sentence, not something the API returned, and it is wrong whenever the code is live and its promotion simply does not match this cart. The discount line expands to one row per reward showing the promotion DESCRIPTION and the amount: the page selects DiscountType.coupon and then never renders it, so nothing on the page ever links a reduction to the code that unlocked it. On an empty cart the coupon box is not rendered at all.
