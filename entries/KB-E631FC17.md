On Notifications 3.1018.0 / platform 3.1090.0: GET /api/notifications/AbandonedCartEmailNotification?tenantId=B2B-store&tenantType=Store returned the store-level notification (its own id, en-US template with a 51 KB body). The same call with tenantId=b2b-store returned the GLOBAL notification instead (same id as the call without a tenant), with the requested tenant echoed in tenantIdentity. So the lookup matched the store override case-sensitively. AbandonedCartReminderJob journal rows with tenant Store:b2b-store were rendered from the global en-US override, whose body was empty. Each row had subject from that override, body empty, status Error, lastSendError "'Body' must not be empty.", sendAttemptCount 0, so they were never sent. Rows for Store:B2B-store were rendered from the store template as usual.
