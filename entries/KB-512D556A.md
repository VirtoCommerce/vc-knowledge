Compared two B2B accounts on the same build. A SINGLE-organization member (Organization maintainer of one org) signed in and the header account button rendered only the person's name, with no organization prefix; the account dropdown held just a profile link and Logout, and no data-test-id="organizations-search" existed. That same user's org context was demonstrably present: the sidebar showed a Corporate group, /company/members listed the member roster without a 403, and /company/info resolved the organization name. A MULTI-organization user on the same build rendered the header button as "OrgName / UserName" and the dropdown contained an Organizations listbox plus organizations-search. So the org-name prefix and the switcher UI appear to be gated on the user having more than one organization, not on org membership as such. Whether the single-org case is intended or a gap is not determinable from the storefront alone.
