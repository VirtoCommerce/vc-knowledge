2026-10-14, admin token. Rejected, nothing written: GET /api/assets?folderUrl=../ (also .., <folder>/../.., %2e%2e%2f) -> 500; POST /api/assets/folder with parentUrl ../ -> 500; DELETE /api/assets?urls=../x -> 500; POST /api/assets?folderUrl=../x, folderUrl=%252e%252e%252f, or multipart file name ../../t.txt -> 405; POST /api/assets/localstorage with file name ../x.txt -> 500 "Invalid upload file name". A folder NAME containing ../ gets a proper 400 from the validator. Every Invalid path message contains the resolved absolute filesystem path of the storage root on the server. On the older deployment (Assets 3.1005.2, FileSystemAssets 3.1003.1, Platform 3.1039.13) the status codes are the same and the 500 bodies also carry the .NET stack trace with build-agent source paths; on the newer one (Assets 3.1010.0, FileSystemAssets 3.1006.0, Platform 3.1076.1) stackTrace is null but the path stays in the message. Source: FileSystemBlobProvider.ValidatePath throws PlatformException("Invalid path {fullPath}"); AssetsController upload catches PlatformException and returns 405. Anonymous requests get 401.
