Observed on Return module 3.1003 (PR build). GET /api/return/{id}/available-statuses returned: New -> [New, Completed, Canceled, Processing, Cancelled]; Requested -> [Requested]; Draft -> [Draft]; Approved -> [Approved, Completed, Processing]; PartiallyApproved -> [Completed, Processing, PartiallyApproved]; Rejected -> [Rejected]; Cancelled -> [Canceled, Cancelled]; a legacy Completed return without decided lines -> [New, Completed, Canceled, Processing, Cancelled]. The admin status dropdown shows the same list. On a decided return, PUT /api/return changing approvedQuantity, itemState, line quantity or decline reasons returns 200 and the stored decision is unchanged (the fields are discarded without an error); moving to Approved/Requested/Cancelled or adding/removing a line returns 400 with a message. On a Requested return a PUT that raises a line quantity within the order's availability returns 200 and changes the buyer's requested quantity with no notification; above availability it is 400 'LineItem ... has incorrect quantity'. Moving a decided return to Processing and then Completed keeps the released quantities.
