On the ProductComparison PR build (3.1000.0-pr-1), moveCompareListItem(storeId, userId, itemId, position) returns and persists the new order: a re-read of compareList shows positions renumbered without gaps; a position beyond the end puts the item last; position -1 or an empty itemId returns errors[].extensions.code VALIDATION; another user's userId returns Forbidden; an unknown but well-formed itemId returns 200 and changes nothing. saveProductsToCompareList rejects with VALIDATION and saves nothing: 501 products in one call, an empty or 129-character productId, an empty products array, a valid plus an empty id in one call, duplicate sectionId, and more than 30 configuration sections for one product (30 is accepted; code constant MaxConfigurationSections = 30, not the 100 a developer comment states). A productId that does not exist IS saved (200, the item reads back with product: null), and section ids not belonging to the product are stored. VALIDATION errors carry only the generic message "Error trying to resolve field 'saveProductsToCompareList'" — the validator's own text does not reach the client. Items saved without categoryId all land in one null category group, so the per-group MaxItems cap (5) then limits the whole list.
