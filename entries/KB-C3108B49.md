On vcst_qa 2026-10-23 (B2B-store with MultiFactorAuthentication.StoreMode=Enabled), a buyer belonged to org A and org B. On the storefront /sign-in password form, the password request (grant_type=password) carried NO organization_id. The mfa request (grant_type=mfa, two_factor_token + code) carried the org last picked in the account-menu switcher. Control: both orgs active, B picked in the UI, contact currentOrganizationId reset to A through the API before sign-in. The mfa request sent organization_id=B, the access token came back organization_id=B (amr=mfa), the header showed org B, and the contact's currentOrganizationId was rewritten to B. Locked case: the membership in A was locked and the mfa request sent organization_id=A. HTTP 200, the token's organization_id was B, the header showed B, and currentOrganizationId was rewritten from A to B. A fresh browser with no remembered org sent no organization_id; with A locked and current=A, it resolved to B through the chain. Sign-in log rows for these sign-ins carry organizationId null.
