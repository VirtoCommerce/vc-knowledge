Built two Security-only archives (Manifest.json + PlatformEntries.json with Roles=[], Users=[one disposable Manager user with a role holding order:access+order:read], UserApiKeys=[rows for that user only]), uploaded each to the backups folder (POST /api/assets?folderUrl=backups), and restored with POST /api/platform/import (handleSecurity true, no modules/settings/binary/dynamic properties). (1) New shape: a row with ApiKeyHash = lowercase hex SHA-256 of the UTF-8 key (46-char vc_ value), ApiKeyHint 4…4, no ApiKey. Before restore the key answered 401; after, header api_key and ?api_key= both gave 200 on POST /api/order/customerOrders/search and 403 on GET /api/platform/modules (a random key stayed 401). (2) Old shape: rows with only a plaintext ApiKey (20 and 12 chars, no hash/hint fields). After restore both authenticated the same way (200/403, header and query). GET users/{id}/apikeys returned no key and no hash: apiKey = hint, which was first4…last4 for the 20-char key and the bare '…' for the 12-char key. A Security backup taken afterwards (POST /api/platform/export) listed those rows with a 64-hex ApiKeyHash and the hint and no ApiKey field; the export of UserApiKeys carries only ApiKeyHash/ApiKeyHint, never ApiKey. Import upserts only: the restore job log listed Roles, Users, UserApiKeys imported with no errors, and the restore removed its uploaded blob from the backups folder on a clean run.
