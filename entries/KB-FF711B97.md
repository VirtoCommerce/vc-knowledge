I read a File-type section through POST /api/catalog/products/configurations/search and through Query.productConfiguration. It carries id, name, type, isRequired, displayOrder, allowCustomText, allowPredefinedOptions, maxLength, dependsOnSectionId and options, and no file size or file count field. The storefront component (vc-frontend option-file.vue) calls useFiles("product-configuration"). That calls Query.fileUploadOptions(scope) and merges the result over defaults DEFAULT_FILE_MAX_COUNT=5 and DEFAULT_FILE_MAX_SIZE=1 MiB (1048576 bytes, base 1024) from client-app/shared/files/constants.ts. On this stand fileUploadOptions(scope:"product-configuration") returned null, so the defaults apply: 1 MB per file and 5 files, which matches the PDP hint. A test fixture should read these limits from fileUploadOptions when it is non-null and from the storefront defaults otherwise. It should never copy them from a section, because a section has none.
