B2B-store active pickup-location count set to 50, 51, 100 and 101 (isActive via PUT /api/shipping/pickup-locations, then a PickupLocation reindex); every active location was listed for the cart (GlobalTransfer). Confirmed pickup point on page 1: 50 -> GetCartPickupLocations first:50 totalCount 50, hasNextPage=false, 'Showing 50 of 50', no Load more. 51 -> hasNextPage=true, 'Showing 50 of 51', one Load more; after:"50" -> hasNextPage=false, 'Showing 51 of 51', button gone. 100 -> one Load more (after:"50") ends it. 101 -> after:"50" leaves hasNextPage=true and 'Showing 100 of 101'; after:"100" ends it. Each after:N response also carried the confirmed pickup location at items[0] (51 items for the after:"50" page at 100; 2 items for after:"100" at 101); the dialog de-duplicated it, so entry counts stayed 51/100/101. When the confirmed location was itself the 51st of 51 (outside page 1, so prepended on page 1), the dialog opened 'Showing 51 of 51' and still rendered Load more; clicking it fetched after:"50", which returned only that same location, and the list did not change.
