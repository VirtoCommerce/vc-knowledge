Signed in as a single-org storefront buyer (B2B-store), POST /graphql updateContact(command:{id:<the caller's own me.id>, firstName, lastName}) returned errors[] NULL_REFERENCE "Error trying to resolve field 'updateContact'", and lockOrganizationContact(command:{memberId:<me.id>}) returned INVALID_OPERATION "Error trying to resolve field 'lockOrganizationContact'". The same two mutations with a random GUID or with the caller's Organization id returned Forbidden "Access denied.". Identical on vcptcore_qa1 (ProfileExperienceApi 3.1022.0-pr-149-2242) and vcst_qa (3.1022.0), so it is not caused by PR #149. Apparently authorization lets the caller's own id through and the handler then finds no Contact. Nothing was written. Test authors: do not use me.id as a "nonexistent member id" baseline for these mutations; use a random GUID.
