---
Locking or deleting a membership revokes the user's tokens server-side, but an already-issued access token keeps working. Locked in a sibling organization while active in an unlocked one, the user's session carries on: GraphQL calls keep returning 200, navigation works, the cart is kept, and the locked organization simply renders disabled the next time the account menu opens. If the active organization is the one locked, re-authentication moves the user to an unlocked sibling. If every membership is locked the user lands on /403 with Access denied and a switcher whose every row, including the selected one, is disabled.
