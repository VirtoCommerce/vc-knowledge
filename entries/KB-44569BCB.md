On vcptcore_qa (ProfileExperienceApiModule 3.1026.0-pr-153-495e, VCST-6970 fix), POST /graphql updateUser from a caller WITHOUT platform:security:update may update only their OWN account and only email/phoneNumber/photoUrl. It returns succeeded:true but silently IGNORES userType, roles, passwordHash, securityStamp, memberId, storeId, lockoutEnd, accessFailedCount, twoFactorEnabled (stored values kept, confirmed by user(id) read-back; original password still authenticates). userType and securityStamp are NON_NULL required inputs, so they are ignored rather than rejected. Targeting ANY id other than the caller's own — an existing same-org user OR a non-existent id — returns errors[] code Forbidden ('Access denied.'); the ownership check precedes the existence check, so an unprivileged caller never sees 'User not found.'. A caller WITH platform:security:update (admin/isAdministrator) retains full behavior: privileged fields APPLY, and a non-existent id returns succeeded:false message 'User not found.'. Changing email via updateUser without the permission sets EmailConfirmed:false. Verified 2026-11-23 by self-registering a B2B 'Organization maintainer', 3x per attack.
