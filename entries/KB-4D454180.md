A single /graphql/sales-rep operation that aliases the same root field twice (e.g. perOrg + crossOrg salesRepTopSellers, or five salesRepDocuments keyword aliases) returns HTTP 200 with one alias null and errors[] 'Error trying to resolve field <alias>' extensions.code ARGUMENT in roughly 13-40% of requests; WHICH alias fails varies (perOrg as well as crossOrg). The same field queried alone never failed (8/8). Reproduced at the same rate on SalesRep 3.1014.0 (documents, 2 of 15 runs) and 3.1015.0-pr-15 (2 of 15), so it is not version-specific. Suspected cause: both query builders call xAPI CopyArgumentsToUserContext, which TryAdd's into the shared per-request UserContext Dictionary while top-level fields resolve in parallel. The storefront sends one field per operation and does not hit it.
