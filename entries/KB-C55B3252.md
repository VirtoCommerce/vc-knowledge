Firefox 151, 1440x900, theme 2.60.0, signed in as a Sales Representative (a contact of a sample organization). On /account/profile the First name was emptied with Ctrl+A then Delete. vee-validate validates on model update, so the message 'This field is required' appeared at once, with focus still in the field. In the same instant the input got aria-invalid="true" and aria-describedby="input-N-details", and div.vc-input-details__message was inserted inside div#input-N-details. Neither element, nor any ancestor up to body, has role=alert, role=status or aria-live. A MutationObserver over the page's live regions (the polite notifications host and two polite VcSelect sr-only spans for Default language and Default currency) recorded no mutation. Tab moves focus to Last name, which has no aria-describedby, and Update stays disabled. A screen reader user therefore hears the error only when they return to First name. The input has no aria-required on this build either. The code agrees: client-app/ui-kit/components/atoms/input-details/vc-input-details.vue renders the message as a bare div, which has had no live-region attributes since the file was created in 2023. Only the character counter at its limit gets role=status and aria-live=polite. VCST-5713 tracks the same unannounced error on the address form. Restoring the original value removed the message, and nothing was saved.
