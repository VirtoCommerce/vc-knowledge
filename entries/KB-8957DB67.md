Admin Settings > Orders > General > Customer order statuses (setting Order.Status) > a value row opens the "Edit dictionary value" blade (System value + one textbox per language; toolbar Save disabled until the form is dirty). On platform 3.1084.0-pr-3139-3b31 (vc-platform PR 3139 build, not a release), observed as admin in Edge: (1) three consecutive single-click saves each sent exactly one POST /api/platform/localizable-settings/Order.Status/dictionary-items = 204, followed by GET /api/platform/localizable-settings = 200; the payload is the full alias list of the setting with all localizedValues, and re-opening the value showed the new text once. (2) A double click on the blade's Save sent exactly ONE POST (204), and the value was stored once. (3) Editing a translation and then clicking another value row opens a dialog "Save changes" / "This dictionary value has been modified. Do you want to save changes?" with Yes / No / Cancel(x). Yes sent one POST (204), stored the edit and then opened the clicked row; no console error. No sent no request, kept the stored value, and re-opening the value showed the stored text, not the discarded edit. The in-flight disabled state of Save could not be observed with Playwright MCP, because a click returns only after the request it triggered settles. Per VCST-6148 the pre-fix builds behaved differently (double click sent two POSTs; Yes threw a TypeError and saved nothing), so this behaviour is build-dependent.
