Theme 2.60.0 pr-2523-466f, Chrome, canonical layout-shift observer injected at document start, cold document loads, 2 per page, identical values on both. At 375x812 the details page of a 1-line return is 1005-1115 px tall (taller than the 812 px viewport, 15 px scrollbar): colleague's Requested return 0.2440, own Requested return 0.2824 and 0.2685 (1075 px), own Cancelled returns 0.2824. One shift at ~1.1-1.3 s after navigation start carries 0.215-0.254: the shell (greyed H1 'Returns', centred spinner overlay, decorative background svg and the footer visible at y~600) is replaced by the loaded return, the spinner moves 310-360 px, the svg 190-300 px and the footer is pushed out of the viewport. A separate 0.028 shift (34 px, container background below the sticky header, ~0.8-0.9 s) occurs on every account page at this width. The same 1-line pages fit a 1920x1080 viewport (scrollHeight == innerHeight, no scrollbar) and measure 0.0012-0.0013; with the viewport lowered so the page is taller than the screen: 1920x880 (page 1000 px) own return 0.1017, colleague's 0.0835; 1920x720 own 0.047, colleague's 0.039. Same mechanism as the 3-line case already recorded: the shift appears whenever the loaded content is taller than the viewport, independent of line count. The loading structure (loader overlay with the empty-view swap) is identical before and after the organization-returns change; the colleague's page is ~110 px shorter than the owner's (no cancel footer) and shifts slightly less.
