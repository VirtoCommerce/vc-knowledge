With a storefront token of an Organization employee whose me.permissions held only storefront:organization:view and storefront:user:view (no xapi:my_organization:edit), Mutation.updateMemberAddresses(command: {memberId: <the organization's id from me.contact.organizationId>, addresses: [one new address]}) returned HTTP 200 with no errors. The returned member listed the new address (addresses.totalCount 8 to 9), and Query.currentOrganizationAddresses read by the same employee showed totalCount 8 before and 9 after; the 8 existing addresses were all still present, so the call added and did not replace. No guard answered with a refusal code, so the platform has no server-side permission check on this write for this role; the only gate seen is the storefront UI. The added address was removed again with Mutation.deleteMemberAddresses by an organization maintainer (200, totalCount back to 8). Whether the platform should refuse it is open (product-owner question); deleteMemberAddresses by an employee was not tested.
