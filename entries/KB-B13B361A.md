2026-10-12 on vcst_qa (Return 3.1005.0-pr-28, theme 2.60.0-pr-2523-4263). A test organization whose only member holds xapi:my_organization:return:view: the member raised return R1, an admin renamed the organization (GET then full-body PUT /api/organizations, only name changed), then the member raised R2 on the same order. After a fresh storefront sign-in the organization tab on /account/returns was labelled with the NEW name; POST /api/return/search {organizationId} and xAPI organizationReturns both reported organizationName = the OLD name for R1 and R2. The return copies the organization name from its order (the order snapshot), so a rename never reaches returns on pre-rename orders. The storefront return details page does not display the organization name. Whether a rename should reach returns is an open product question; this records behaviour, not intent.
