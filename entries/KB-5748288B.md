Anonymous Query.themeSnapshot(storeId) for two stores that had no publication yet returned a snapshot, not null and not an error: publication 1, cultureName en-US, theme default, catalogHash null, publishedDate equal to the moment of the read (12:40:33Z and 12:40:34Z, the time of my query), content with the theme's default template_rules (one product rule default-b2c -> product.b2c), empty templates/brand/menus. A repeated read returned the same publication 1 and publishedDate, so the first read writes the publication once and later reads reuse it. GET /api/site-builder/theme/status then reported {publication:1, drafts:[], newDrafts:[]}. So the first anonymous read is itself the write that creates publication 1; a test that reads 'before' to get a baseline number changes the state it measures.
