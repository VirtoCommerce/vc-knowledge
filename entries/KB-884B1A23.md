On vcptcore_qa1 a punchout buyer's cart was filled via xAPI addItem, the PunchOutOrderMessage taken from createPunchoutRequisition, and a cXML OrderRequest posted to POST /api/punchout/cxml (Status 200). The created order (GET via POST /api/order/customerOrders/search) was compared field by field. 4 runs, 1 line priced 24.00 always ordered: (1) config without default methods, cart = only the ordered line: total 24, PaymentIn.sum 24 (match). (2) config with DefaultShipmentMethodCode=FixedRate (rate 10): total 34 (shipping 10), sum 24. (3) config without default methods, cart holds an extra selected 12.00 line that is not in the OrderRequest: the extra line is unselected and stays in the cart, order total 24, sum 36. (4) both factors: total 34, sum 36. So PaymentIn.sum is always the cart total as it stood when the cart was loaded (all selected lines, no new shipment), not the order total; it matches only when the order covers the whole cart and no shipping price is added. Compare against PaymentIn.sum (not PaymentIn.total, which is the method fee).
