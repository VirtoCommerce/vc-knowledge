Measured live in the Marketplace Vendor Portal on @vc-shell/framework 2.6.1 (Chrome), reading the accessibility-snapshot [active] node after a 1 s settle, 2-12 reps per transition. Sign-in redirect -> the shell workspace (main). Sign-out -> main of the unauthenticated login layout. Blade open by row click or Enter on a keyboard-focused row -> the opening row keeps focus (the blade-open repair declines when something live holds focus, by design). Maximize/Restore via the header button OR the Ctrl+\ shortcut with focus on the expand control -> hands off to the replacement control (Restore after maximize, Maximize after restore). Ctrl+\ with focus in the sidebar (Notifications button, nav search field, Home menu button) -> the blade root on both maximize and restore; nothing stays focused inside the inert sidebar. Save as draft on a product blade -> the blade root region, but the product blade remounts on each save, so this does not isolate the watch(loading) repair from the mount repair. Closing a delete dialog via Cancel or Escape -> the opener button. Self-disabling pagination First/Last -> main, never body. Before 2.6.1 several of these left document.activeElement as BODY (2.5.0: Ctrl+\ on the expand control; 2.6.0-rc.0: Ctrl+\ from the sidebar). The framework documents the per-transition targets in framework/core/utilities/focus.docs.md. A Tab-once check is non-discriminating on sidebar paths because the nav precedes main in DOM order.
