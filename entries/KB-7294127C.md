Signed in on the storefront (B2B-store) as a user whose member is an Employee, so GetMe returns me.contact = null. /account/profile shows empty First name and Last name, the email (disabled) and a disabled Update button. After typing a first and last name, Update becomes enabled; clicking it opens the "Profile update" dialog "Profile successfully updated!", the form resets to empty names, and OK reloads the page with the names still empty. No updatePersonalData (or any other) mutation is sent: neither the browser request list nor the session HAR holds one. Cause in vc-frontend: useUser.updateUser returns early when user.contact is null, and the profile page's onSubmit opens the success modal whenever updateUser does not throw. The success message is therefore shown for a save that never happened.
