On vcptcore_dev the B2B-store broken-link list (POST /api/seo/broken-links/search, 70 records, all Active) holds 66 records shaped like storefront application routes (account/dashboard 87 hits, sign-in 76, cart 52, company/dashboard 120, catalog, bulk, change-password, plus per-user ids such as account/orders/<guid>, shared-list/<guid>, cart/<guid>, product/<id>) carrying 836 of 875 hits (96%); the rest are one home-page key (__index__home__page__), two stale category-like slugs and a 404 probe. The storefront calls pageContext(permalink = current path) at boot, so any hard load of a path that has no SEO record (every application route) reaches the not-found event; per-user ids make the table grow without bound. Four permalinks keep a locale prefix (de/..., fr/...) and three of them carry a language that disagrees with the prefix. Read the Active count and HitCount as 'unresolved landings', not as dead external links. The store blade widget 'Active broken links' shows the Active-status count of this list.
