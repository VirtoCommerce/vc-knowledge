With two products sharing one code in different physical catalogs (one linked into the store's virtual catalog, one only in an unlinked legacy catalog), POST /api/catalog/search/products {searchPhrase:'code:"X"'} returned both, and the unlinked one was often first. POST /api/catalog/listentries {keyword} without catalogId behaved the same. Anonymous xAPI Query.products for the store returned only the store-visible product. Consequence: any lookup by code that takes the first hit without a catalog filter can resolve to a product shoppers can never see.
