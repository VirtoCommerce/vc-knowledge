Unserved (rep unassigned via PUT /api/sales-rep): the owner's sharingSetting.targets still returns the org with name and city/region subtitle, the org's members keep Read by key until the rep removes it; removeSharedWithIds of it succeeds, after which its members get Access denied. Adding that org to any list (alone, with a served org, or re-adding it where it is already a target) returns Access denied and writes nothing. Deleted (DELETE /api/members?ids=): targets keep the id with name, subtitle and imageUrl null; the storefront Share dialog renders that recipient as the raw GUID and the list card still counts it; removal succeeds. A member token minted before the delete (organization_id = deleted org) keeps Read by key until the target is removed; a fresh grant is denied. The rep record still lists the deleted org, salesRepCustomers omits it, and echoing the record back with PUT /api/sales-rep returns 500 (FK_MemberRelation_Member_AncestorId) and writes nothing.
