As a non-admin Manager with no store and a full builder role: GET /api/pagebuilder/template type=foo -> 400 {"error":"The content type must be themes, pages or blogs."}; path=../../x.page -> 400 "Path \"../../x.page\" must stay inside the store's content folder."; storeId=NO-SUCH-STORE -> 400 "Store \"NO-SUCH-STORE\" does not exist."; theme=../x -> 400 "Theme \"../x\" must be one folder name.". POST /api/pagebuilder/save with files [<theme>/config/qa-probe.json themes] -> 400 "... is in the theme's config folder, which is deployed with the theme: only config/settings_data.json is saved through the builder."; [<theme>/x.txt themes] -> 400 "is not a theme JSON file."; [x.html pages] -> 400 "is not a page document: pages and blog articles are .page or .page-draft files."; nothing is written. A user without builder:update gets 403 on save and on POST /api/page-builder-pages/grouped/{id}/content; a user without builder:publish can save drafts (200/204) but gets 403 on save draft=false for pages/blogs, POST /api/pagebuilder/git/publish and POST /api/page-builder-pages/grouped/publishing/{id}, and the live page stays unchanged. A user whose account StoreId is A gets 403 for storeId=B (and for a non-existent store, so stores cannot be enumerated); a user with no store works with any store.
