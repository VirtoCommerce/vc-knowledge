Read at vc-module-mfa@1a0f481 (PR 3), MfaRequirementService.CanSkipCodeInDisabledStoreAsync: the code is skipped only when user.StoreId equals the named store and IsBackofficeAccountAsync is false. IsBackofficeAccountAsync is true for IsAdministrator, userType Administrator or Manager, or when IAdminUIAccessPolicy.EvaluateAsync admits the user from the permissions of their roles. The platform default ConfigurationAdminUIAccessPolicy (vc-platform) denies only when RequireAnyPermission is on and the user has no permission, so a customer whose role holds any permission is treated as a Backoffice account. README says the same ("by default, any user with a permission"). Consequence read from source, NOT observed live: an organization maintainer whose run role adds a permission is expected to be asked in an own Disabled store while a member without permissions is not. Whether that is intended for storefront-only permissions is a product question.
