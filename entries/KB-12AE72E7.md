As the platform admin in the Vendor Portal, opening an offer or seller-product details blade whose entity already has a conversation fires POST /api/vcmp/message/search {entityId, entityType, unreadOnly:true, sort, take:20} three times; each returns 500 {"message":"Value cannot be null. (Parameter 'userId')","stackTrace":null} and the blade shows a red error banner with that text. Entities without a conversation return 200 {totalCount:0}. With a vendor selected in the Vendor Switcher the UI still omits sellerId from this body (it does send sellerId on seller/offers/search), so the 500 repeats; the same request with sellerId added returns 200. The unread-only search resolves the recipient from the request's SellerId only, with no operator-group fallback, unlike /api/vcmp/message/unreadcount on the same build. Related on the same stand and role: the Communication page's POST /api/vcmp/conversation/search {skip,take,responseGroup} returns 500 {"message":"UserIds"}, and opening the messenger on an order with no seller returns 500 from POST /api/vcmp/communicationuser/seller ("... has no Seller"). No stack trace or server path is exposed in any of these.
