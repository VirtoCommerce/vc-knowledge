Storefront B2B buyer (userType Customer, storeId B2B-store, no global role). POST /api/platform/security/login {userName, password} -> 200 {succeeded:true,isLockedOut:false,isNotAllowed:false,requiresTwoFactor:false} with a .VirtoCommerce.Identity.Application cookie; GET /api/platform/security/currentuser with that cookie -> 200, permissions empty, isAdministrator false; GET currentuser/sign-in-methods -> 403. With the buyer's own password-grant token (storeId set) POST /api/passkeys/creation-options -> 403 and POST /api/passkeys -> 403, so a Customer cannot make a platform-host passkey; a password grant without storeId -> 400 invalid_grant user_cannot_login_in_store. A storefront-host passkey of a Customer is not offered by the browser on the platform login page (rpId mismatch), so the passkey cookie sign-in refusal for a Customer is not reachable.
