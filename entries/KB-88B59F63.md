On VirtoCommerce.Content 3.1007.0-pr-224 the Admin SPA Pages blade keyword search sends POST api/content/search with body {contentType, storeId, keyword, searchPhrase:"<kw> contentType:<type>"}. Response is 200 with a bare JSON array of ContentItem (fields incl. name, relativeUrl, published, hasChanges); a no-match keyword returns []. Earlier builds returned a serialized Task envelope {result:[...], status, isCompleted...} that the SPA unwrapped with transformResponse .result. In the served bundle the search action is defined with transformRequest + isArray:true and no transformResponse. Clearing the search reloads via GET api/content/{contentType}/{storeId}/search. The Published badge renders on search results from the item's published flag. GET /api/content/search/enabled still returns an object {"result":true} by design of that endpoint.
