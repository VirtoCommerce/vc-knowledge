Sales Representative created through POST /api/sales-rep serving two organizations; token by password grant with storeId B2B-store. createSalesRepTask(command:{name, description, type:"Call", priority:"Normal", dueDate, customerId}) with a served organization returned HTTP 200 with the saved task, customerId = that organization and customerName = its name; salesRepTask(id) returned the same values, and the admin GET /api/task-management/{id} showed objectType "SalesRepCustomer" and objectId = the organization. With customerId = an existing organization of the same store that the rep does not serve, createSalesRepTask returned HTTP 200 with errors[0].message "Customer not found." (path createSalesRepTask, no extensions code) and data.createSalesRepTask null; updateSalesRepTask on the rep's own linked call with that customerId returned the same error. A random GUID that is no organization returned exactly the same message and shape on both mutations. After every refusal salesRepTasks totalCount was unchanged, the linked call still read back its original customer with an unchanged modifiedDate, the admin task search by responsibleId was unchanged, and the WorkTask table held no row for the refused names.
