Each request was pinned to one of the two platform pods with the ingress affinity cookie (pod confirmed with check_capacity machine_name and App Insights cloud_RoleInstance). Replaying the same answer + S on the pod that consumed it -> input_required (refused) 6/6; replaying it on the OTHER pod -> accepted once more (second Declined result and audit row) 3/3, then refused there too. Unpinned, each of 3 states was accepted exactly twice. Source at vc-module-mcp df74972 (McpCallToolFilter.TryUseConfirmationState) stores the used nonce in the in-process IMemoryCache, whose own comment says it is per instance; the platform Redis backplane only propagates evictions, so the store is per instance regardless. From the same code path (not tried live): an accept + confirm=true replay on another instance would run the tool again. The README says the state is valid "for 10 minutes and once".
