With scope Customer: message empty string or whitespace-only is stored as null; a padded message is stored trimmed; omitting message keeps the previous one; 1024 UTF-16 code units are stored verbatim (ASCII, u-umlaut, and a string containing an emoji surrogate pair counted as 2); 1025 is rejected with only the generic GraphQL error 'Error trying to resolve field changeWishlist.' code INVALID_OPERATION, and nothing in that command persists, including a target added in the same addSharedWithIds (atomic). Removing the last remaining target with removeSharedWithIds is refused with the same generic INVALID_OPERATION error and the share is left unchanged. createWishlist accepts scope Customer + addSharedWithIds + message in one call and round-trips them. Adding an organization the rep does not serve returns Access denied (Forbidden) and persists nothing. Switching to Private empties targets and sets message null; re-sharing without a message does not restore the old message. Observed on x-cart 3.1037.0-pr-141, cart 3.1011.0-pr-194, sales-rep 3.1012.0-pr-21.
