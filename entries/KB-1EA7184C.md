Yes. Anonymous products(storeId: B2B-store, cultureName: en-US, query: "<13-digit GTIN>") on vcst_qa returned exactly the one product carrying that GTIN (totalCount 1), and a 12-digit prefix of the same GTIN returned the same product. The value is not in the product's name or code, and none of the properties the query returns carries it. The xCatalog full-text docs list name, code, slug, property values and variation codes/properties as the searched __content, and do not mention gtin, so this is observed behaviour the docs do not state. Checked 2026-09-29. Different from the filter syntax (gtin:"..."), which @kb(KB-A0B3940F) covers.
