POST /api/page-builder-multilanguage-pages {storeId, name, permalink, defaultCultureName:"xx-XX"} on a 13-language store returned 200 and persisted the root. GET /{id}/languages then listed xx-XX first with isDefault:true and isStoreLanguage:true, and POST /{id}/languages/xx-XX created a version (200). PUT of an existing root changing defaultCultureName to xx-XX returned 400 text "'xx-XX' is not a language of store '<storeId>'." A later PUT that leaves the invalid default unchanged (e.g. renaming in the admin blade) returns 200, so the invalid value persists. Convert of a Landing page in xx-XX is refused (400 "must have a language of store"), but Link existing of the same page is accepted and the row is labelled "not a store language".
