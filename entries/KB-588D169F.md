Edge lane, WebAuthn virtual authenticator (ctap2, internal, resident, automaticPresenceSimulation ON), buyer with one passkey, /sign-in loaded with presence OFF then presence switched ON and the button clicked. Single click: GraphQL GetPasskeyRequestOptions (load), GetPasskeyRequestOptions (click), POST /connect/token grant_type=passkey 200, GetMe, then ANOTHER GetPasskeyRequestOptions and a second POST /connect/token grant_type=passkey whose request carries 'authorization: Bearer <new token>' and referer /sign-in and shows no response status (the page navigates away). Double click: the same - exactly one click-triggered GetPasskeyRequestOptions and one 200 grant (the second click is ignored), then the re-armed query; in one of two double-click runs the extra grant POST was also sent, in the other only the extra options query was in flight, so the lane log shows 1 or 2 grant POSTs and is not a stable count. The platform Sign-in log recorded exactly one successful Passkey row per click ceremony (three ceremonies, three rows). Source: passkey-provider.vue signInWithButton ends with 'await startAutofillSignIn()' after signIn(), and signIn(conditional) does not skip when the user is already signed in. With a real authenticator the re-armed conditional request stays pending (no autofill field); the second grant exists only because automaticPresenceSimulation answers it.
