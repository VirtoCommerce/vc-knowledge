Global MultiFactorAuthentication.Enabled=true, a store with MultiFactorAuthentication.StoreMode=Disabled: POST /connect/token grant_type=password with that storeId answered 200 with tokens and no code for that store's customer, for a Manager-type user with no store, and for a Customer holding a back-office role. Store-less, the same Manager answered two_factor_required. A customer of a DIFFERENT store naming the Disabled store answered user_cannot_login_in_store (store rule, no code step). This follows ticket comment 112278 (StoreMode applies to every user) and contradicts the deployed setting description ("not required for this store's own customer accounts that are not administrators; everyone else follows the global setting"). With StoreMode=Enabled and global off the Manager naming the store is challenged (two_factor_required).
