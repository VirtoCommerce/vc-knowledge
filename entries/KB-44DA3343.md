On vcst_qa, a storefront user created through Entra ID sign-in, whose account has an expired password, added a passkey on Account > Security. After signing in with "Sign in with a passkey", the storefront opened the Change Password page and Query.me returned passwordExpired: true. Signing in with "Sign in with a code" (email OTP) also opened the Change Password page. In code the expiry check is skipped only for an external (SSO) sign-in or impersonation: vc-module-x-api UserManagerCore checks `user.PasswordExpired && !isExternalSignIn && !isImpersonated`, and vc-module-profile-experience-api UserType.passwordExpired and ProfileSchema use the same condition. The product owner's decision (VCST-6630) is that the expiry is checked only for a password sign-in, so this is filed as a defect. Observed by a QA engineer by hand; the SSO exemption was read in code, not re-observed.
