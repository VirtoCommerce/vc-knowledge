The storefront ships its colour presets bundled in the JavaScript as light and dark pairs, so a bundled preset returns 404 when requested as a file under /assets/presets - only a theme's extra presets are served there, and a 404 is not evidence a theme is broken. Dark mode is applied through an html.dark class that is set only when a dark preset is the store's selected preset; the operating-system colour-scheme preference does not trigger it, so emulating a dark colour scheme leaves the storefront light. The compiled dark component styles are present in the bundle regardless. The live theme is whatever the store's white-labeling record names; anonymous shoppers cannot switch presets.
