The Loyalty Admin SPA bundle's add-program blade lists exactly two program types: type "Default" (i18n key order-loyalty, the "Order loyalty" program) and type "ProductPoints". GET /api/loyalty-programs/new/{programType} returned 200 with an order-style skeleton (condition block offering UserGroupsContainsCondition / UserGroupIsCondition / order-status conditions, plus a reward block) for "Order", "OrderLoyalty" and "OrderPoints" alike, echoing the given string as programType — it does not validate the type. A program POSTed from GET new/Default with an empty BlockLoyaltyCondition and BlockLoyaltyReward persisted with both blocks empty. A seeder must use "Default", not a guessed name like "Order", or it creates a program of a type the Admin SPA does not know.
