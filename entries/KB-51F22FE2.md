Matrix on one build, fresh articles seeded via REST: (a) article with en-US content AND en-US SEO: edit Title/Name/Summary -> Reset => banner gone, green header dot, blade closes without a prompt. (b) en-US content, NO SEO entry: edit Title -> Reset => Title reverts, Save/Reset disabled, but yellow 'Has unsaved changes' banner + orange header dot stay and closing asks 'You have unsaved changes. Close anyway?'. (c) same article, edit the non-localized Name -> Reset => same stuck state (the field edited does not matter). (e) en-US SEO but NO content entry: same stuck state. (d) edit Title then type the original value back (no Reset) => banner clears, no close prompt. (f) article from (a), switch the blade locale to pt-PT (no entries for it), no edit => banner appears immediately with Save/Reset disabled, and closing prompts. No PUT is sent in any case; the stored article is unchanged. Source (vc-module-news news-article-details.vue, identical at 3.1004.0/3.1005.0/3.1006.0/dev): the Reset handler calls resetNewsArticle(); setBaseline() synchronously while the watch([newsArticle, currentLocale], ensureLocalizedEntries) pushes empty placeholder content/SEO entries for the current locale on the next flush, so vc-shell useBladeForm's deep watcher sees data != snapshot; the mount path awaits nextTick() before setBaseline() for exactly this, and setLocale never re-baselines. Save/Reset use the module's own newsArticleIsDirty (which strips empty entries), the banner/dot/close guard use useBladeForm.isModified, so the two disagree and the user cannot clear the banner.
