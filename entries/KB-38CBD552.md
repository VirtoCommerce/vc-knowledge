With an authorization-code+PKCE token (client claude-admin-qa, IT Platform Operator role) on vcst_qa at 15:53Z: tools/call get_pending_change with nonexistent change_id values of 128, 129 and 200 characters, reject_pending_change with 128 and 129, and get_pending_change again with 129, all returned HTTP 200 with isError true, "Pending change '<id>' was not found." and a _meta trace_id. POST /api/mcp/audit/search for the user in that window returned only the two 128-character calls (outcome Failed, pendingChangeId of 128 chars); searching the Agent audit log by the trace id of a 129-character call finds nothing. App Insights shows the INSERT INTO McpAuditEntry dependency of those operations failing with SQL error 2628 (string or binary data would be truncated) while the request is 200, and search_errors shows "Failed to write the MCP audit entry for tool reject_pending_change". These are registered, permission-checked tools, not unknown names. A padded id (real id plus trailing spaces) does not resolve a real change (GET /api/mcp/pending-changes/{id} answers not found), so only failed lookups are lost.
