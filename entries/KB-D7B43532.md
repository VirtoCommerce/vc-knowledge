On FileSystemAssets 3.1006.0 / Assets 3.1010.0, DELETE /api/assets?urls=<root folder url> on a tree where one child folder held 30 files and 25 empty sub-folders returned 500 {"message":"Directory not empty : '<path>/folders'"} and left the tree. A small tree (one file per folder, one empty sub-folder) did delete in one call. Deleting every folder's files first (batched urls=…) and then the folders deepest-first succeeded, and the parent listing then showed no residue. After a successful folder delete the parent GET /api/assets listing may still show the folder for a few seconds.
