On Punchout 3.1000.0-pr-2 (PR #2 head f9403cbb) with XCart 3.1042, a punchout session buyer's default cart held a simple product, a variation and a configurable product, and Mutation.createPunchoutRequisition then returned the cXML. In ItemIn/ItemID, SupplierPartID = the cart line's sku: the simple line sent its product code, and the variation sent its own code, not its parent's. The configurable line sent "Configuration-AGENT-TEST-CFG-031-20260527", which is XCart's synthesized configured-line sku, not the catalog code. SupplierPartAuxiliaryID was the cart LINE id for every line, not the product id. Source: PunchoutOrderMessageBuilder.BuildItemIn sets SupplierPartId = lineItem.Sku and SupplierPartAuxiliaryId = lineItem.Id. The product code is reachable through CartAggregate.CartProducts, which the same builder already uses for UnitOfMeasure. Whether the configurable value is intended is an open question to the module author; the ticket's QA guide says SupplierPartID = product SKU.
