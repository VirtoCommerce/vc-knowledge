On a vc-frontend 2.59 barcode build with the header-bar fix, both header bars (desktop and the 390 px overlay) show an empty box whenever the first barcode query value is non-empty, so the Barcode scan button stays visible (when the scanner is enabled) and the results are the barcode lookup's. The box shows q exactly when the page runs a keyword search: ?barcode=&q=<t> and ?barcode=&barcode=<code>&q=<t> (first value empty) run a keyword search for <t> and the box shows <t>; ?barcode=%20%20&q=<t> is a lookup (untrimmed) and the box stays empty. With scannerEnabled false the box is still empty and no scan button is shown. Enter in the empty box navigates to /search with no q and no barcode (all products); a typed term + Enter navigates to /search?q=<term>. A submit made while already on /search replaces the current history entry rather than pushing a new one, so Back skips the page the submit was made from.
