On vc-theme-b2b-vue 2.59.0-pr-2476-31b5 (x-cart pr-141 / cart pr-194), the Share dialog's Save opens a confirmation for any change from a shared scope to a different scope. Shared to Private: title 'Stop sharing this list?', body 'Everyone the list is shared with will lose access. You can share it again any time.', buttons Cancel / Stop sharing; it is accurate, every reader immediately gets sharedWishlist null. Scope swap between shared scopes: title 'Change who can access?', body 'The link stays the same. Some users may lose access.', buttons Cancel / Change access, shown in BOTH directions. Specific customers to Anyone with link (widening) shows it although nobody loses access: the target org member keeps Read and anonymous and other-org users gain Read through the same key, and the copy never says that the list becomes public. Anyone with link to Specific customers (narrowing) is accurate: same key, anonymous gets Unauthorized, non-target orgs Forbidden. No confirmation at all for Private to any shared scope, adding a customer, or removing a customer within Specific customers; a removed organization loses read immediately with no warning. Private to Anyone with link reuses the old key, so any link sent earlier opens for anyone again without warning. Cancel, the X button and Esc on the confirmation save nothing; Esc closes only the confirmation and returns to the Share dialog. This held up to vc-theme-b2b-vue 2.59.0-pr-2476-31b5 (2026-10-02). vc-frontend commit e4a4cf58 (VCST-6104, 'sharing targets change warning', 2026-10-02) changed the rule: from 2.59.0-pr-2476-0abb, and still on 2.60.0-pr-2511-81f1 (vcst) and 2.60.0-pr-2522-6f90 (vcptcore) on 2026-10-12, widening to Anyone with link saves without a confirmation and removing a recipient inside Specific customers asks 'Change who can access?' (KB-E6436922 states that matrix).
