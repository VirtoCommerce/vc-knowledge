On vcptcore_dev (Return 3.1005.0-pr-28-fb4f, Xapi 3.1027.0-alpha.216, platform 3.1079.0-alpha.13411), 2026-10-09:
- A storefront user holding only xapi:my_organization:return:view held two unexpired access tokens (expires_in 1799, minted 5 and 10 seconds before the calls).
- DELETE /api/platform/security/users?names=<userName> answered 200 succeeded:true, and the user read back as null both by name and by id.
- With either token, Query.returns, Query.organizationReturns and Query.return(id) each answered HTTP 200 with data null and errors[].code Unauthorized ("Anonymous access denied or access token has expired or is invalid."). Neither was ever refused with an HTTP 401 at the transport.
- Query.returnStatuses answered HTTP 200 with its 10 statuses.
The token still passes authentication; the refusal comes from the per-field account-state check, which finds no user. A client therefore sees the deletion as a GraphQL error code, not as an HTTP status.
