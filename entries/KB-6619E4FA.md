B2B-store, admin, publication 16 with drafts sections/header-group.json (invalid announcement-bar colour token, planted via the legacy save) and sections/footer-group.json (valid). POST /api/site-builder/discard-draft?storeId=B2B-store&path=default/sections/header-group.json&type=themes&theme=default -> 204, same for footer-group.json -> 204. GET theme/status then answered {publication:16, drafts:[], newDrafts:[]} (first poll, 5 s later), and GET designer/theme-file for both files returned content and eTag byte-identical to the reads taken before the drafts existed. So a pending invalid theme draft that blocks theme/publish can be removed with discard-draft without spending a publication number.
