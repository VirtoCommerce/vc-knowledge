On 2026-10-20 I read promotion data over REST and called Query.validateCoupon directly. The promotion behind ZUR10 ("Test ZUR10", active, public, B2B-store, no end date, coupon expiry 2027-05-31) has the cart condition ConditionCartSubtotalLeast subTotal=100 and the reward RewardCartGetOfRelSubtotal 10. Coupon QA10OFF (unlimited uses, expiry 2026-12-31) is attached to two active promotions, each giving 10% off the cart subtotal with ConditionIsEveryone. On a fresh anonymous B2B-store USD cart with one item (total 226.80), validateCoupon returned true for QA10OFF, ZUR10, QA and SUPER. In the same day's regression run the buyer's cart subtotal was 49.98, and /cart showed "This code is not valid" for ZUR10. That rejection is therefore the subtotal condition working as configured, not an expired or broken coupon. A test that uses ZUR10 needs a cart subtotal of at least 100. The run also reported QA10OFF as not valid on that 49.98 cart for a signed-in buyer; that was not reproduced here, because QA10OFF validated on the anonymous 226.80 cart.
