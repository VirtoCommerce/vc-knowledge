POST /api/page-builder-multilanguage-pages {storeId,name,permalink,defaultCultureName} (no visibility) returned the root with visibility:false; POST {id}/languages/en-US created a version group with visibility:false. With a standalone everyone page live on the same permalink, POST {id}/publish-all returned processedCultureNames [en-US,...] with skipped [] and single grouped/publishing of the version returned 200 (no 409): a visibility:false page is not counted as the same audience as an everyone page. With visibility:true on the root the same fixture gives skipped [{en-US, PermalinkConflict}] and single publish 409. The admin shell form creates roots with Visibility switched on by default, so this only affects API-created roots. Test fixtures that build conflicts from API-created roots must send visibility:true.
