2026-11-10 ~18:50Z, anonymous tools/call on POST {FRONT_URL}/ucp/mcp. resolve_country {query: 12345} -> HTTP 200, result.isError true, text 'UCP operation failed unexpectedly.' + 'Trace ID: <id>', structuredContent {is_error:true, code:'internal_error', status_code:500, message:'An unexpected UCP error occurred.'}; no stack trace. resolve_country {} -> isError true, text "Argument 'query' is required." (the argument is named). For comparison: query 'Afghanistan', 'AFGHANISTAN' and 'AFG' all resolve to country id AFG (case-insensitive, accepts the code); an unknown 24-letter string -> invalid_request status_code 404 "Country '<q>' was not found."; GET /ucp/v1/geography/countries/resolve?query=Afghanistan returns the same id. So a type mismatch in client input is reported as a server-side internal_error rather than invalid_request (same class as KB-324C2F16 on /admin/mcp).
