Switching get_environment_profile off in Admin Shell #/mcp-tools set MCP.Tools.Disabled to "admin/get_environment_profile"; tools/list dropped from 19 to 18; a raw tools/call returned HTTP 200 with result.isError=true and text "Tool 'get_environment_profile' is disabled by the administrator. Tell the user that this action is not available now." plus _meta.trace_id, and the audit row outcome was Disabled. An unknown tool name instead gets JSON-RPC error -32602 "Unknown tool" and is audited as Error with the caller-supplied name. Switching the admin scope off (a confirmation dialog appears; switching on has none) wrote "admin/*": tools/list returned [] and calls got the same disabled text, but prompts/list still returned the scope's 6 prompts and prompts/get still worked. Switching back on cleared the setting to null (not the empty-string default). A tool the user lacks permission for returns JSON-RPC error -32600 "Access forbidden: This tool requires authorization." and is audited Forbidden.
