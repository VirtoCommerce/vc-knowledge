Wrote VirtoCommerce.Search.IndexSettings through POST /api/platform/settings with a Product/color mapping holding two values, one without a Synonyms property. POST /api/search/index-field-settings/search returned it with "synonyms": null. A Product Build (POST /api/search/indexes/index) then finished "Indexation completed with errors", processed 0/0, error "System.ArgumentNullException: Value cannot be null. (Parameter 'source') at FieldValueConverter.TryGetNewValue", so no document was reindexed (the existing index kept its documents). Saving the same shape through POST /api/search/index-field-settings does not hit this, because the save normalizes missing synonyms to an empty list; only a direct write of the setting (settings API or configuration override) reaches it. Clearing the setting and rebuilding restored a clean 413/413 build. FieldValueConverter is not changed by vc-module-search PR 158, so this is not introduced by it.
