Read at vc-frontend dev a6ee5ce36 (2.63.0): app-runner.ts calls getDesign() then setDesignAttribute() and loadDesignStyles() at boot; getDesign() reads settingsData.settings.design from the bundled client-app/config/settings_data.json ('Read from the bundled settings, so the design is known before any request') and resolveDesign() maps any value that is not a folder name under client-app/designs/ to classic. useThemeContext builds settings from that bundled copy and keeps the backend's store settings separately as storeSettings; the preset name (themePresetName) comes from white-labeling at runtime, the design has no equivalent. So one deployed theme build serves one design to every store and organization; changing it means rebuilding the theme. DESIGN_NAMES currently holds one entry, soft; classic has no folder. Not observed live beyond the network (a classic stand requests no designs/soft chunk).
