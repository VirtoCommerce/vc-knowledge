Signed-in B2B buyer, Chromium 1920. On /bulk-order, Copy&Paste tab: input with leading/trailing spaces, spaces around the comma and an empty line between records ('  SKU , 2  \n\nSKU2,1') enables Add to cart with no error (not submitted). Input 'SKU,2,' and 'SKU,1234567890' -> clicking Add to cart sends no GraphQL mutation (only polling queries in the network log), adds nothing to the cart, and shows no inline, toast or modal message. Source of the deployed tree: copy-and-paste.vue validates each record against ^[A-Za-z0-9_-]+,\d{1,9}$ and emits 'error' on a mismatch, but pages/bulk-order.vue registers no @error listener, so the rejection is silent. The pre-merge tree has the same missing listener (with an older single regex), so this is not new with the 2.61 merge.
