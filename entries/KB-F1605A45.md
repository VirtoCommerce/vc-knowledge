On vcst_qa 2026-11-27 a disposable organization had a disabled record R1 (POST /api/white-labeling, isEnabled:false) and then, after Mutation.changeOrganizationLogo, a second enabled record R2 created 3 s later. Before the mutation GET /api/white-labeling/organization/{id} returned R1 (disabled — the endpoint does not filter on isEnabled); after it, the same GET returned R2, and R1 stayed reachable only through GET /api/white-labeling/{R1-id}. After both records were PUT to isEnabled:false the GET still returned R2. This matches the module source (search with Take=1, default sort CreatedDate descending, no IsEnabled criterion). The module exposes no search endpoint, so an older duplicate is invisible to every by-organization read; a record id has to be known to reach it. xAPI whiteLabelingSettings, by contrast, reads only enabled records.
