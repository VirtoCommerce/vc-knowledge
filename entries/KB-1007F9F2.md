I deleted a cart line's product from the catalog. Query.cart validationErrors(ruleSet:"*") then reported CART_PRODUCT_UNAVAILABLE on the LineItem. Both createOrderFromCart and createQuoteFromCart returned HTTP 200 with data null and exactly one error: message "The cart has validation errors", extensions {code:"ValidationError", codes:["ValidationError"]}. The extensions held no per-error code such as CART_PRODUCT_UNAVAILABLE and no code-to-message dictionary. This held 2/2 runs and on every attempt, whether order or quote, cache miss or cache hit. A client therefore cannot tell from the mutation response which rule failed, and has to query Query.cart validationErrors to find out.
