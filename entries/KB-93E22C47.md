Signed in as a rep whose token carries sales-rep:access, with the store's SalesRep.Enabled = true (both read from the app's own pageContext response), on a vc-frontend-next build whose deployed bundle gates its built-in sales-rep module on the theme setting sales_rep_builtin_enabled (false). The store query lists the sales-rep plugin (3.1017.0-pr-31) and the browser fetches its mf-manifest.json, which declares requiredHostVersion ^0.2.4, but never fetches its remoteEntry.js; the host's core-api facade in that build is 0.2.3. Result, for rep and buyer alike: no header hub icon, no Sales Rep Hub section in the account menu, no Corporate "Sales reps" link, and a cold load of /company/dashboard ends on the theme's 404 page (title "404 Page not found") instead of the hub or a redirect to /account/dashboard. No console error names the skipped plugin (only an unrelated script-404 line). Anonymous visitors are sent to /sign-in?returnUrl=... because this store requires sign-in on every page. So on a Next build, a missing hub can be a host/plugin version mismatch rather than a permission or setting problem: compare the plugin manifest's requiredHostVersion with the host's facade version first.
