Measured with full Pages rebuilds (POST /api/search/indexes/index, documentType Pages) on VirtoCommerce.Sanity 3.1004.0-pr-4-f7a8. A document id present in two datasets of one project was indexed from the dataset marked isPriority; with no isPriority, from the dataset listed first. Each dataset contributed only its own documentTypes (a 'landing' doc in a dataset whose list lacks 'landing' was never indexed). A dataset without documentTypes used Sanity.DocumentTypes. Sanity.DocumentTypes ' virtoPage , footerNavigation;siteSettings' was split on , and ; with spaces trimmed. An entry with apiToken '${name}' not defined in Sanity:Secrets was skipped while the other entries still indexed; an entry without apiToken inherited Sanity.ApiToken; an entry without projectId was skipped. Invalid JSON or an empty Sanity.Projects fell back to the single ProjectId/Dataset project; with Sanity.DocumentTypes empty, a store that had a stored (hidden) Sanity.PageType kept indexing that type. drafts.* ids were indexed with Status Draft. Caveat: the same rebuilds reported more documents processed than ended up in the index, and one siteSettings document was lost in 3 of 4 rebuilds (the signed webhook indexed it), so a missing document after a rebuild is not proof it was filtered.
