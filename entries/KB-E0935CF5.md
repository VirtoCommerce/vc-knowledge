Anonymous GET /health returned HTTP 200 (application/json) in about 0.6 s. The body is an object keyed by check name: "Background jobs", "Background jobs store", "Modules health", "Cache health", "Redis health", "SQL Server health". Each value has Data, Description, Duration, Exception (null) and Status ("Healthy" for all six). The Background jobs description names the active engine ("Active background-job engine 'RabbitMQ'"). A smoke check should read every Status, not only the HTTP code. Per KB-B858E12A, a 200 here does not prove a new build is serving.
