As administrator, permalinks '/a<U+E0001>b', '/a<U+E0041>b', '/a<U+1D173>b', '/a<U+1BCA0>b' (all Unicode category Cf, outside the BMP) on POST /api/page-builder-pages/create-group-page, POST /api/page-builder-pages/grouped and PUT /api/page-builder-pages/grouped each returned 200 and GET grouped stored them verbatim. A BMP Cf in the same position (U+2060) returned 400 with the permalink InvalidMessage. The Page Builder shell and the legacy content edit-page blade both show the permalink format error and disable Save/Create for all four values. Source at add254f: PageBuilderPermalink.IsInvisible checks each UTF-16 char with char.GetUnicodeCategory, which returns Surrogate for both halves of an astral character, never Format; the clients use a /u regex with \p{Cf}, which works on code points. The rule as stated by the author rejects invisible formatting (Cf) characters, so the server under-rejects.
