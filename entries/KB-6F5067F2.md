On a store with 125 settings, three full-body PUT /api/stores calls each changed only mainFulfillmentCenterId. After one of them, GET returned the same 125 settings, but Stores.SeoLinksType (a setting with a stored row id) had moved from index 8 to index 112, so an index-wise comparison reported about 670 differing paths. Its value was null before and after. The order was then stable across repeated GETs and across the next PUT. A by-name comparison of all settings against a snapshot was empty. Order is not a contract: diff settings keyed by name.
