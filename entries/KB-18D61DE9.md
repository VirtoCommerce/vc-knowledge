Return 3.1005.0-pr-28-fb4f, 2026-10-12, admin token. GET /api/platform/settings/Return.Status allowedValues = [Completed, New, Canceled, Processing, Approved]: no Draft, Requested, PartiallyApproved, Rejected or the Cancelled spelling the flow writes, although the module guide says the dictionary holds both cancelled spellings. GET /api/return/{id}/available-statuses answers: New -> [Completed, New, Canceled, Processing]; Approved -> [Completed, Processing, Approved]; PartiallyApproved -> [Completed, Processing]; Cancelled -> [Canceled] (not the return's own spelling); Requested, Rejected and Draft -> []. Other stands (vcptcore_dev, vcptcore_qa1) answer [Cancelled] for a Cancelled return and offer the full dictionary, so this is the stored dictionary of the stand, not module behaviour. Explains why the storefront Status filter on vcst lists Approved, Cancelled, Completed, New, Processing only. That was the stored dictionary of the stand, not module behaviour, and it changed: on 2026-10-12 (about 10:32Z per the QA who wrote it; settings writes are not change-logged, so the time cannot be read back) the dictionary was set to the module default of 10 values (ModuleConstants.cs:42-63 at fb4fc43). Read on 2026-10-13: allowedValues = Completed, New, Requested, Draft, Canceled, Rejected, Processing, Cancelled, Approved, PartiallyApproved; xAPI returnStatuses serves all 10; available-statuses answers Requested -> [Requested], Cancelled -> [Cancelled], Canceled -> [Canceled], Rejected -> [Rejected], Draft -> [Draft], New -> [Completed, New, Cancelled, Processing] (see KB-21F4F161 for the spelling rule).
