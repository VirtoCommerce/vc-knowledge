Not guaranteed. XCatalog IndexSearchRequestBuilder maps sort to only the requested field (default: score desc; price -> price_{currency}) and the ElasticSearch8 provider adds no _id tie-breaker, so the order of documents with equal sort values is not stable across requests. Observed 2026-10-14 on XCatalog 3.1023.0 + ElasticSearch8 3.1011.0 (~800-doc product index): paging all 362 store products with first:16 and no sort returned 12-27 duplicated items per pass (whole 15-item windows repeated on the next page, the same number missing), different pages affected each pass; price-descending showed 0-1 duplicate inside a 50-item equal-price group. A single page repeated in isolation returned identical content. A 65-product store on XCatalog 3.1007.4 + ES8 3.1007.0 showed none. The sort code is the same in XCatalog 3.1007.4, so this is latent, not introduced in 3.1023.
