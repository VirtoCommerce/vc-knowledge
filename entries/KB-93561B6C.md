SalesRep 3.1013.0-pr-18-42c1, 2 replicas, pod-pinned reads. With Cart TTL 60 and CartInvalidateOnChange=false, a cart-statistics key was warmed on both pods and then made stale by a rep cart change (K 6 against a cold twin 8, on both pods). Cart TTL was then set to 0 at runtime: 6 s later the same key was still served stale on both pods (6 against 8), and it was still stale after TTL went back to 60. For a key first computed while TTL was 0, every rep cart quantity change (6 changes alternating between the two pods) showed up on the next read, and K equalled the twin each time. So TTL 0 stops new entries from being cached but leaves existing ones in place until their original TTL or an eviction. Read latency for cart statistics on this small dataset was about 190-210 ms both with TTL 0 and when cached.
