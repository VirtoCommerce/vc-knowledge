Punchout session on store B2B-store, storefront /cart in punchout mode. After a successful Create requisition (session status Returned), every further createPunchoutRequisition from the session owner — browser Back then click, a second tab, or a repeated API call — returns errorCode null and the STORED cXML again, byte-identical (same payloadID and timestamp), and the storefront posts it to the return URL again. It is not rebuilt from the cart: after the buyer changed the cart (4 lines, 168.49 on screen) the replay still carried the first document (3 lines, Total 56.50). Two parallel calls on an Active session give one document plus either SessionExpired or the identical document, never two different documents. A password token, an anonymous call, or the session token with another storeId get SessionNotFound and no cxml. With store setting Punchout.Enabled off, a returned session gets StoreNotConfigured (no replay); an active session gets the same, with the toast "Punchout is not set up for this store. Please contact the store administrator." (German translation on /de). No REST endpoint exposes the stored order messages, so their count cannot be read.
