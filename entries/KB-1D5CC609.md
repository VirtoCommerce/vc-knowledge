On vcptcore_qa1 (platform 3.1087.0), Security shows Users, Roles, OAuth applications and Sign-in log. Opening a user from Security > Users shows the User information blade: toolbar Save, Reset, Change password, Lock account, Login on behalf; fields Is administrator, Login, Email + Verified (Resend link), Status, Account type, Locked state, Last login date, Container (store); widgets Show contact, Roles, Changes, API key, Active sessions and Sign-in log (each with a count). The Active sessions widget opens a blade with columns IP address and User agent and toolbar Refresh and Terminate all; a user who had just signed in by a REST password grant showed one session with user agent "node". There is no Active sessions entry in the Security menu itself, so the session list lives only per user. A Customer account with no permission signing in to the Admin SPA is stopped at route #!/contact-admin (an Access denied card with "Login with other credentials"). The platform permission for Login on behalf is platform:security:loginOnBehalf.
