On PageBuilderModule 3.1033.0-pr-170-236e (Platform 3.1076.0), as an administrator: POST /api/page-builder-shared-components with storeId "b2b-store" (the real store is "B2B-store") returned 201, and the component was persisted with storeId "b2b-store" exactly as sent, not normalized to the canonical id. It was not an orphan: GET /{id} returned 200, and it was returned by POST /api/page-builder-shared-components/search under BOTH "B2B-store" and "b2b-store" (count 7 to 8). A store-scoped user whose user.StoreId is "B2B-store" could GET and rename it (200). So the store lookup, search and store-scope authorization all match case-insensitively; the only effect is a non-canonical storeId value in the data. Components were deleted afterwards (204, then 404).
