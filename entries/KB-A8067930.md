On /#!/workspace/embedded-app/push-messages the string "QA" renders twice. Badge 1 is the AngularJS host: div.vc-env-badge.vc-env-badge--test[role=status][aria-live=polite][ng-if=showEnvironmentBanner], position:fixed, top of the platform header. Badge 2 lives inside the embedded app's same-origin iframe (src /apps/push-messages#?EmbeddedMode=true) as aside.vc-environment-banner.vc-environment-banner--warning[aria-label="Environment indicator: QA"] > span.vc-environment-banner__label, a direct child of div.vc-app, position:fixed top:0 left:840px z-index:2000. It is present immediately on load of the LIST view, before any blade is opened, and stays identical when the New push message blade opens; being fixed on the iframe viewport it does not scroll with blade content. The component is defined in the shared framework bundle vc-shell-framework*.js (__name:"vc-environment-banner", props {name, color}), NOT in the module's own index*.js. In the same bundle the vc-app root computes isEmbedded from the route query EmbeddedMode==="true" and passes it to other config, but the banner's render condition is only `!isIgnored && environmentName` — it ignores isEmbedded, which is the defect. The badge text is derived client-side from window.location.hostname by substring match (prod/dev/qa|test/stage|uat/demo), mapping test->label "QA" and color "warning"; it is not an env var, setting or build constant, and isIgnored suppresses it on prod. Of the five apps the platform reports with supportEmbeddedMode:true (push-messages, vc-sales-rep, vc-news, tasks, system-operations), push-messages and vc-sales-rep double the badge and their vc-shell-framework bundle contains the vc-environment-banner class; vc-news and tasks do not double it and the string is absent from every asset they ship (they carry a differently-sized, older framework build). system-operations is not a vc-shell app at all. So it is a vc-shell framework behaviour gated by framework version, not a per-module one.
