On Quote 3.1004.0-pr-159, XCart 3.1040.0-pr-149, XOrder 3.1015.0-pr-55, FileExperienceApi 3.1007.0-pr-25: a file uploaded to POST /api/files/product-configuration and attached with Mutation.addItem fileUrls, then converted with Mutation.createQuoteFromCart, appears on QuoteType items.configurationItems (type File) files with the SAME /api/files/{id} url as the upload, with name, size and contentType filled. That url reads 200 with identical bytes for the quote's buyer and admin, and 403 for a buyer of another organization (including an Organization maintainer elsewhere), a customer with no organization, and anonymous. It still reads 200 after 5 minutes, after a fresh login, and after removeCart deletes the source cart. The source cart is kept with itemsCount 0. Same-session control: Mutation.clearCart on a cart holding a configuration file with no quote deletes the file (404 for buyer, admin and anonymous), so cart-owned files are still deleted on clear. 3 of 3 runs, plus a 2-file quote, a file line plus an ordinary line, and a no-file configurable line. The File configuration item's own name is null on the quote. Pre-fix builds returned 404 to everyone right after createQuoteFromCart (VCST-5999).
