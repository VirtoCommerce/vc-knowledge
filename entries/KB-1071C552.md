Deployed a package set with the VirtoCommerce.ApplicationInsights module removed while the environment kept Serilog__Using__1=Serilog.Sinks.ApplicationInsights and Serilog__WriteTo__1__Name=ApplicationInsights. The pod loaded every module (Loaded modules: 98, with errors: 0) and then stopped in Program.Main -> HostBuilder.Build on 'Unhandled exception. System.IO.FileNotFoundException: Could not load file or assembly Serilog.Sinks.ApplicationInsights', thrown from Serilog ConfigurationReader.LoadConfigurationAssemblies (Startup.cs ConfigureServices). The pod never became ready; the previous ReplicaSet kept serving. The platform itself does not ship the sink (its appsettings Serilog Using lists only Console and Debug); the module does (Serilog.Sinks.ApplicationInsights 4.1.0 before the SDK 3.x migration, 5.0.0 after), as the docs say ("The module includes a sink for Serilog"). So uninstalling the module requires removing the Serilog sink entries from configuration too; this is configuration, not a module defect.
