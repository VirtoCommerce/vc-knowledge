Submitting the /sign-in form triggers a REST call to POST /connect/token (OAuth2 password-grant style), not a GraphQL mutation over /graphql. On invalid credentials it returns HTTP 400 with a JSON body shaped like {"error":"invalid_grant","errorDescription":"...","code":"login_failed","count":N}. The body also carries "errors":[{code,description}] and every other OpenIddict response field as null. count is NOT a failed-attempt counter: it is OpenIddictMessage.Count, the number of parameters set on the response (error, error_description and code for login_failed, hence always 3), serialized because the platform returns its TokenResponse object as JSON. It stays 3 on repeated failures and for a nonexistent user. No failed-attempt counter is exposed in the token response. A locked-out account is expected to surface a different code (user_is_locked_out) rather than login_failed.
