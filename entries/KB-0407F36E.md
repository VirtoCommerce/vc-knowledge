Submitting the /sign-in form triggers a REST call to POST /connect/token (OAuth2 password-grant style), not a GraphQL mutation over /graphql. On invalid credentials it returns HTTP 400 with a JSON body shaped like {"error":"invalid_grant","errorDescription":"...","code":"login_failed","count":N} where count appears to be a running failed-attempt counter (observed count:3 on a seeded test account, consistent with the documented 5-attempts/15-minute lockout policy referenced in BUG-org-user-temporary-lockout-shown-as-permanent-VCST-5374). A locked-out account is expected to surface a different code (user_is_locked_out) rather than login_failed.
