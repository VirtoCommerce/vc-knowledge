No. The SalesRepDetailsValidator added in vc-module-sales-rep 3.1011.0 guards only the /api/sales-rep aggregate save path: POST/PUT /api/sales-rep answer empty names with 400 'Validation failed: -- FirstName: First Name must not be empty.' But PUT /api/members with firstName=null,lastName=null on the same contact still returns 204 and clears them, after which the storefront me.contact query fails with INVALID_OPERATION again. Two further details: fullName is NOT recomputed by that members write, so it keeps its stale old value while firstName/lastName go null; and the platform's other contact writers (Contacts blade, customer import, storefront updatePersonalData) share the same uncovered path.
