Signed in as a sales rep (store B2B-store), opened /company/customer-sales?period=q4&customer=<id of an existing organization the rep does not serve, holding a rep-authored October order>. The page first sent POST /graphql operation SalesRepMonthlyOrderStatistics with organizationId=<that id>; the response was HTTP 200 {"data":{"salesRepCustomerOrderStatistics":null}} (no errors[]). The page then rewrote the URL to ?period=q4 (customer dropped), selected "All my customers (N)" and showed the rep's all-customer figures; the unserved organization's order never appeared. ?customer=garbage behaves the same (falls back to All, parameter dropped). ?period=bogus shows Current year and keeps period=bogus in the URL. So membership scope holds server-side, but the page issues one statistics call with the unvalidated id before it resolves the rep's customer list.
