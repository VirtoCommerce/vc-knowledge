On CatalogCsvImport 3.1009.0 the classic Admin wizard stores {eTag, propertyMaps, propertyCsvColumns} in browser localStorage (lastKnownImportData) when Start import is pressed. After a later upload, if the eTag returned by GET mappingconfiguration matches the stored one (same CSV header), the stored mapping is merged over the server auto-mapping. Observed: after importing with Name->AltName and CategoryPath/Vendor cleared, a fresh wizard with a different file but the same header opened Map columns with that edited mapping, although the server response held the auto-mapping (Name->Name, CategoryPath->CategoryPath, Vendor->Vendor). A file with a different header got the plain auto-mapping. The memory is per browser and survives closing the wizard.
