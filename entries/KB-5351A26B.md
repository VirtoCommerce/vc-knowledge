As a sales rep (bare password grant with storeId, then POST /graphql), salesRepCustomerCartStatistics(storeId, currencyCode USD[, organizationId]) was read with two aliased periods over the same window: period(from,to) with no filter and period(filter:"active-carts", from,to). For one served org whose only USD cart was a rep-authored cart with a custom name (lines 3 selected + 7 not selected for checkout), no filter returned 3/7 count 1 and active-carts returned 0/0 count 0; across all orgs no filter 12/7 count 4 vs active-carts 7/0 count 2. After the same two lines were moved into the rep's cart named "default" (same org, USD) and the named cart removed, active-carts for that org returned 3/7 count 1 and the all-org roll-up 10/7 count 3; emptying those lines brought the org back to 0/0 at once. So the built-in active-carts kind is an include-list by cart NAME ("default", the storefront cart), not a non-empty/non-wishlist test; the dashboard Active carts card, which queries active-carts, cannot see a named cart. This matches the module source/README: the active-carts rule resolves to names [DefaultCartName]. A cart in another currency (EUR "default") is not counted in a USD read. Fixture consequence: a split fixture for the card must live in the rep's "default" cart for that org/currency.
