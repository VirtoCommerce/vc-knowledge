2026-10-29 on vcst_qa, storefront origin. Target: a Customer whose security account storeId names a store that exists on no env. Its password grant answers 400 invalid_grant user_cannot_login_in_store with storeId=B2B-store, with its own store id and with no storeId. An operator (Manager, storeId B2B-store, one role holding only platform:security:loginOnBehalf) took a password token with storeId=B2B-store, then POST /connect/token grant_type=impersonate user_id=<target id> with that Bearer: 200 and a token. So the impersonate grant does not apply the store rule to the target (consistent with KB-4E1FD1E8: the target is checked for existence only). The impersonated token is still refused passkey management (passkeyCreationOptions: Access denied, KB-B93A97C4), so this does not give the target a way to register a passkey.
