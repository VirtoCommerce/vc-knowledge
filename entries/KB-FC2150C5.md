Read in vc-module-white-labeling 3.1008.0: ChangeOrganizationLogoCommandHandler.GetWhiteLabelingSettingAsync searches by OrganizationId with searchCriteria.IsEnabled = true; when nothing is returned it instantiates a new WhiteLabelingSetting with that OrganizationId and IsEnabled = true, sets LogoUrl and saves through IWhiteLabelingSettingService. WhiteLabelingSettingValidator (duplicate-store-or-organization, store-and-organization-set) is invoked only by the REST controller's POST and PUT, not here. For an organization whose record exists with isEnabled=false this reads as a second record for the same organization (resolution then takes the first match; which one is not established). An empty logoUrl sets LogoUrl to null and DeleteLogoUrlFile is a no-op, so the uploaded file is not removed. Not observed live: it needs the mutation on a disposable organization.
