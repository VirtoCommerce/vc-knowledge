Firefox, 1920 px, Sales Representative accounts on B2B-store. (1) Schedule call on a served org's /company/my-customers/{id}, with the org unassigned from the rep (PUT /api/sales-rep) while the dialog was open, then Save: Mutation.createSalesRepTask (POST /graphql from the plugin) returned HTTP 200 with errors[0].message "Customer not found." (no extensions code) and data null. (2) Edit call on /company/tasks for a call whose task is linked to another record (ObjectType CustomerOrder; the list line reads "Customer not assigned"), with a customer picked: Mutation.updateSalesRepTask returned HTTP 200 with "This task is linked to another record, so it cannot take a customer.". In both cases the rep saw only the global toast "Something went wrong. Please try again later." with a Report a problem button, built by vc-frontend's graphqlErrorEvent handler (the console shows the VcAlert outline-dark notification plus the plugin's own "[sales-rep] createSalesRepTask failed" / "updateSalesRepTask failed" log line). The dialog stayed open with every field filled and Save enabled, with no inline message, and nothing was written. Saving again gave the same refusal and the same toast, so the toast's "try again later" advice cannot clear these refusals: only re-assigning the org did (the same draft then saved with "Task saved"). Source at this build (vc-module-sales-rep PR 26 StorefrontApp): useSalesRepTaskMutations uses useMutation without SUPPRESS_ERROR_NOTIFICATIONS_CONTEXT and its run() logs and discards the ApolloError, and sales-rep-task-modal save() returns silently on a failed write ("useMutation keeps the global error toast"). The same plugin's sendCustomerCommunication does opt out, and the hub elsewhere has the copy "Customer not found or not in your customers.". What looked odd: the server's specific reason never reaches the rep. This is not marked as a defect because no doc or BL rule covers task error copy; a triage classified it as a UX defect pending a ticket.
