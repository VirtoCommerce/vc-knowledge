The contact's persisted default organization (organizationId), which sign-in uses as the active organization, is not validated against the blocking membership statuses, while the contact's organizations list correctly excludes blocked ones. Sign-in therefore pins the user to an organization the backend has just filtered out, and every organization-scoped query returns Forbidden inside an HTTP 200. A single-organization user is locked out of /account/dashboard, which is also where a pending invite would be accepted; a multi-organization user can recover through the org switcher on the 403 page. Switching organization persists organizationId server-side (it survives a fresh browser) and it is not writable through PUT /api/members.
