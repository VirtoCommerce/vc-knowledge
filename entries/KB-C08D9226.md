I opened /sign-in as an anonymous visitor at 1920px. The page sent POST /graphql GetStorePlugins(domain, plugins(appId:"vc-frontend")). The response listed one plugin: id "sales-rep", version equal to the deployed VirtoCommerce.SalesRep module version, permission null, entry type "script" at /modules/$(VirtoCommerce.SalesRep)/plugins/vc-frontend/remoteEntry.js, remote name "sales-rep" exposing "./plugin". Its contributions JSON is gated on setting SalesRep.Enabled. It declares Company child routes (sales-reps, dashboard, my-customers and sub-routes, customer-orders, tasks, documents), each gated on can:sales-rep:access, with documents also gated on sales-rep-documents:read. It also declares one header menu entry (sales-reps, group corporate) and one slot (sharedList/provenance-note). With nobody signed in, the host still fetched mf-manifest.json?v=<hash>, remoteEntry.js, the plugin JS/CSS chunks, the shared-dependency loadShare chunks and the en locale chunk from /modules/$(VirtoCommerce.SalesRep)/plugins/vc-frontend/assets/, and every one returned 200. So the plugin is fetched no matter who is signed in, and access is enforced by the route-level "can" gates, not by whether the plugin gets loaded.
