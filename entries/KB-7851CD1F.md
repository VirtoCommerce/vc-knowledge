Source read: the platform SettingsPropertyService.GetDescriptors() filters descriptors with !IsHidden for every Settings v2 values endpoint (tenant, me, global). The Admin Shell module registers AdminShell.Menu.Recent under tenant UserProfile with IsHidden = true and writes it per userId in AdminMenuService.AddRecentAsync. So GET /api/platform/settings/v2/tenant/UserProfile/{userId}/values never includes it; a test cannot read Recent back through Settings v2 and must judge it through the Admin Shell menu response (recent[]) or the 403 of the refused write instead. Live consistent: on vcptcore_qa1 the tenant values response (also with ?moduleId=VirtoCommerce.AdminShell) had no AdminShell.Menu.Recent key.
