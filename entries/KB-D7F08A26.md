On x-cart 3.1037.0-pr-141 / cart 3.1011.0-pr-194 a list keeps exactly one CartSharingSetting row plus one target row per organization (admin GET /api/carts/{id} shows sharingSettings[0].targets[] with sharedWithId and createdDate, and a legacy sharedWithId on the row equal to the first target). Stop sharing (changeWishlist(scope Private); in the storefront, Share dialog Private + the 'Stop sharing this list?' confirm) deletes the target rows and clears the message: the row stays (same id = the sharing key) with scope Private, targets [] and no sharedWithId. While the list is Private, sharedWishlist(key) for the former target returns data null with an empty errors array, not Forbidden (an org removed from a still-shared list, or a non-target on an active Customer share, gets errors[] 'Access denied.' Forbidden instead). Re-sharing reuses the same sharing key/URL and restores neither the previous recipients nor the message: changeWishlist(scope Customer, addSharedWithIds [other org]) yields targets = only that org, and a member of the former target org is then refused on sharedWishlist(key) and wishlist(listId) with HTTP 200 errors[Forbidden 'Access denied.']. The Rename dialog holds only List name + Description (no sharing details). No toast appears after Stop sharing or after saving Anyone-with-link / My organization, while Specific-customers saves toast 'List shared with N customers.' / 'List saved. Now shared with N customers.' On one test deployment 2026-10-02 none of 36 shared wishlists in storage (420 wishlists) had more than one sharing row, mixed scopes, or a Private row with a target.
