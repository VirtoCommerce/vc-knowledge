On x-cart 3.1037.0-pr-141 / cart 3.1011.0-pr-194 a list keeps exactly one CartSharingSetting row plus one target row per organization (admin GET /api/carts/{id} shows sharingSettings[0].targets[] with sharedWithId and createdDate, and a legacy sharedWithId on the row equal to the first target). changeWishlist(scope Private) deletes the target rows: the row stays (same id = the sharing key) with scope Private, targets [] and no sharedWithId. Re-enabling with changeWishlist(scope Customer, addSharedWithIds [other org]) yields targets = only that org, same key. A member of the former target org is then refused on sharedWishlist(key) and wishlist(listId) with HTTP 200 errors[Forbidden 'Access denied.']. While the list is Private, sharedWishlist(key) returns data null with NO errors entry (a non-target on an active Customer share gets Forbidden instead). On one test deployment 2026-10-02 none of 36 shared wishlists in storage (420 wishlists) had more than one sharing row, mixed scopes, or a Private row with a target.
