Published pages (visibility on, anonymous) with permalinks '/x-100%', '/x-a%2Fb', '/x-a%3Fb'; xAPI slugInfo matches each only by the raw stored string. Opening /x-100% returns HTTP 400 Bad Request from nginx before the SPA loads; /x-100%25 renders the page (the route decodes to 'x-100%', which equals the stored string). /x-a%2Fb: GetSlugInfo is sent permalink 'x-a/b' -> entityInfo null -> 404. /x-a%3Fb: GetSlugInfo permalink 'x-a?b' -> null -> 404. Rule that follows: the page opens only at encodeURI-of-the-stored-string, so any stored escape needs double encoding.
