On both vcst_qa and vcptcore_qa1, POST /connect/token grant_type=password for a username that does not exist (with or without storeId) returned HTTP 400, error=invalid_grant, code=login_failed ("Login attempt failed. Please check your credentials."), userId null, lockoutSecondsRemaining null, count=3. The nonexistent user is not disclosed on the wire even though the same stand's POST /api/otp/request answers user_not_found for the same address. The Admin Security > Sign-in log nevertheless recorded those attempts as Failed with reason UserNotFound, Type Password: the log keeps the true cause while the client sees the collapsed login_failed.
