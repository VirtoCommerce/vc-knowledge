subject: Target-org member reads a Customer-scope share only through sharedWishlist(sharingKey); wishlist(listId) is Forbidden and wishlists() omits it
Only sharedWishlist(sharingKey), where the key is the list's SharingSettingType.id (the storefront /shared-list/<sharingKey> link): for a member whose active organization is a TARGET of the Customer-scope share it returns the list with access Read, isOwner false, the current sharingSetting.message, and targets [] and sharedWithId null (owner-only fields stay empty). The same member gets errors[Access denied., code Forbidden] with data.wishlist null from wishlist(listId) (observed with a share whose single target was the member's active organization), and the list is absent from that member's wishlists() roster (observed totalCount 0, so the storefront Lists page shows 'You have not created any lists yet'; wishlists() is not necessarily empty or free of non-owner lists, though: it returned an Organization-scope list of the member's own organization with isOwner false while the Customer share was absent). Members of each targeted organization opened /shared-list/<key> and saw the list with 'Recommended by your sales representative'; a removed organization's member got /403. A member of a served organization that is not a target gets Access denied (Forbidden, no message text in the response) from sharedWishlist; a member of a different organization gets the same Access denied from wishlist(listId); an anonymous caller gets Unauthorized. Observed on the multi-target sharing build (sharingSetting.targets[] / addSharedWithIds; x-cart 3.1037.0-pr-141, cart 3.1011.0-pr-194, sales-rep 3.1012.0-pr-21) on a share created through the storefront; the same wishlist(listId) denial was observed on the older single sharedWithId model.
