vcst 2026-11-04, B2B store in a CustomerChoice window, disposable customer with a confirmed email, mode Off. The admin PUT /api/mfa/modes/users/{id} {"mode":"Enabled"} (200). The customer signed in with the password and the journal code, then opened /account/security. Query.mfaSettings answered isRequired true, requiredBy "User", userMode "Enabled", canChangeUserMode true, isProviderAvailable true, destination masked. The widget read "On" / "You turned it on: we send a code to <masked> every time you sign in." with a Turn off button. The admin's status endpoint also says requiredBy "User". MfaSettings has no field naming who set the mode, and the widget picks the "Administrator" text only for mode Required. So an admin-set Enabled, which the module README lists as a normal way to set Enabled, is credited to the customer. The same text appears for an unconfirmed-email customer, there with an empty destination.
