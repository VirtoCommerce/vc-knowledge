Sending PUT /api/products/prices with rows for a single price list changed only that list. The same products' rows in two other price lists came back identical (ids, list, sale, minQuantity). A row sent with its existing id was updated in place and kept that id; rows sent without an id were added. The source shows the flip side: an existing row in a list that is in the payload but is left out of it is deleted, so a product's full desired set for that list must be sent. Raising an assignment's priority via GET + PUT /api/pricing/assignments with only priority changed made that list win over another unconditional list at the same scope, as seen in POST /api/pricing/evaluate.
