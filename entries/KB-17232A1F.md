On Return 3.1005.0-pr-28-62f9 the organization list holds every buyer's returns whose status is not Draft, the caller's own non-drafts and admin-created New returns included, with customerName and organizationName. A return belongs to the ORDER's organization (id and name copied when the return is created, also for admin-created returns), so a return on an order without an organization is in no list, a return created with another organization selected still lands in the order's organization, and renaming the organization or removing the buyer does not move existing returns. Drafts are excluded by their current status only: a draft the buyer cancels without ever submitting appears as Cancelled and is readable by holders (reported as a defect candidate). Keyword matches RMA, order number and buyer name in any case; an upper-cased organizationId returns the same rows. That status rule holds up to Return 3.1005.0-pr-28-62f9. Commit d9233ee1 (VCST-6226, 2026-10-08; unreleased PR VirtoCommerce/vc-module-return#28) keys the list on Return.SubmittedDate instead: ReturnsQueryHandler sets SubmittedOnly for organizationReturns, and SubmittedDate is stamped at the first save outside Draft/Cancelled and kept on a later cancel. On pr-28-fb4f (vcst, 2026-10-12, own fixtures, 2 runs) a draft cancelled without submit is absent from a holder's organizationReturns (unfiltered, statuses [Cancelled], keyword = its RMA) and return(id) is null, a submitted-then-cancelled return is listed as Cancelled, a submitted one as Requested, statuses [Draft] gives 0; the owner still lists all four. The migration set SubmittedDate = CreatedDate only for returns not in Draft/Cancelled, so returns cancelled before the build dropped out of every organization list.
