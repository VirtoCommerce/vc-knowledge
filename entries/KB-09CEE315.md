---
Applying Start and End dates on /company/my-customers/<orgId>/orders sends the salesRepCustomerOrders query with filter createddate:["<start local midnight as UTC>" TO "<end local 23:59:59.999 as UTC>"]; with only End set it sends createddate:[TO "..."], and with both cleared it sends an empty filter. Chips read 'Start: MM/DD/YYYY' / 'End: MM/DD/YYYY' in the input format, and removing one chip re-queries with that bound dropped. An end date before the start date marks both inputs aria-invalid, shows 'End date must be on or after start date', and keeps Apply disabled.
