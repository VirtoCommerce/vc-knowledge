Admin SPA Content -> store -> Pages -> Add -> Design page (and opening an existing Design page draft). Typing a permalink with a leading space (' /x'), a trailing space ('/x ') or a leading tab ('\t/x') shows no format error and leaves Create/Save enabled; an inner space ('/x y') shows 'Permalink cannot contain spaces, the characters ? # & \, double slashes, or . and .. segments' and disables Create. On Create and on Save the blade sends POST /api/content/pages/{store}?draft=true&folderUrl=/ (multipart) whose settings.permalink is already trimmed ('/x'), and the stored .page-draft holds the trimmed value byte-for-byte. The trimming happens client-side (AngularJS ng-model default ng-trim, the permalink input has no ng-trim="false"), so the format validator never sees the edge whitespace. The Content API itself does not validate the permalink: the same POST sent directly with ' /x' (and with '/x y', draft and non-draft) returns 200 and stores the value verbatim. Net: through the legacy blade an edge-whitespace permalink is silently normalized rather than rejected; nothing invalid is stored through the UI.
