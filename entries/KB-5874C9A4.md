On vcst_qa 2026-10-23, B2B-store had StoreMode=Enabled and the buyer was a fresh customer each run. A correct password returned POST /connect/token 400 two_factor_required (twoFactorToken, providers[{Email, masked destination}], resendSecondsRemaining=30). The form then swapped in place on /sign-in. The heading read "Enter the sign-in code", followed by "We sent a code to a•••1@example.com." The one-time-code link was hidden, while the external IdP buttons stayed. The Code field took digits only ("1a2 b3-" gave 123). Sign in stayed disabled under 6 digits, and the 6th digit auto-submitted grant_type=mfa. A pasted "111 222" was sent as 111222. Enter during the in-flight request sent no second request, and Resend and Back were disabled while it ran. Wrong codes 1, 2 and 3 each answered 400 invalid_code, showed one alert "That code didn't work." and emptied the field (marked invalid). This held both when typed slowly and within the cooldown. The 4th submit, even with the right code, answered code_attempts_exceeded. The UI returned to the password form with "Too many incorrect codes. Wait a few minutes and sign in again." and kept the email and password. Resend showed "Resend code in N s" (disabled) for 30 s. After that, clicking it called POST {storefront}/api/mfa/resend (200), showed "New code sent." and restarted the 30 s countdown, and the journal had a new MfaSignInEmailNotification. The first code was then refused (invalid_code) and the new code signed in. The token carried amr=mfa. The sign-in log had a Password row with RequiresTwoFactor plus an MFA row (InvalidCode / CodeAttemptsExceeded / success).
