B2B-store's Loyalty.LoyaltyBalanceCalculationMode was set to Customer with POST /api/platform/settings/v2/tenant/Store/B2B-store/values (204, read-back Customer). About 40 minutes later an earn order still produced an organization-scoped Earned row (user balance 0). Earlier, a write of Organization through the same API produced organization-scoped rows only after a platform restart two days later. After an administrator saved B2B-store in Admin (Stores > B2B-store > Settings: mode toggled away and back to Customer > store Save), the next earn orders produced Earned rows with no organizationId and the user balance rose (0 -> 31565). So the loyalty module reads the mode from a store-level cache that the settings-API write does not invalidate, and a store save does.
