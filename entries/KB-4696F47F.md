Sent form-encoded POST /connect/token grant_type=passkey. No credential (also credential empty, or the wrong parameter name) -> 400 error=invalid_request, code=missing_parameters ("Missing required parameters: credential."). credential whitespace-only, "abc", "{}", a syntactically valid assertion JSON with garbage fields, with a nonexistent storeId, and with a store id of an existing store -> all identical 400 error=invalid_grant, code=login_failed ("Login attempt failed. Please check your credentials."), count=3, userId null, lockoutSecondsRemaining null. The grant name is case-sensitive: grant_type=Passkey -> OpenIddict unsupported_grant_type (ID2032). Sign-in log (POST /api/platform/security/sign-in-log/search) gets one row per attempt with signInType=Passkey, succeeded=false, failureReason=MissingParameter or InvalidPasskey, userName/userId/storeId/organizationId all null even when storeId was sent, ipAddress and userAgent filled. The wire reason is collapsed while the log keeps the real reason. Observed with deliberately bogus assertions only; a valid assertion was not exercised.
