On Return 3.1005.0-pr-28-fb4f, read through GET /api/return/{id} (submittedDate is not in the xAPI ReturnType): a buyer draft has submittedDate null after createReturn and updateReturn; submitReturn stamps it with the server time of that save (6 ms before modifiedDate); a later cancelReturn leaves it unchanged. A draft cancelled without ever being submitted stays null. An admin-created return in status New (Admin SPA Returns > Add new return > Make return, which sends PUT /api/return) is stamped at creation (2 ms from createdDate). PUT /api/return on a live Draft with submittedDate in the body answers 200 and the stored value stays null (status stays Draft). PUT /api/return without id creating a return already in status Cancelled leaves it null, even with a date in the body. The migration that added the column set submittedDate = createdDate on every existing return whose status was not Draft or Cancelled (Requested, Approved, New; checked on 31 returns) and null on Draft and Cancelled ones, including returns cancelled after they had been submitted. The organization returns list and a colleague's return(id) require submittedDate to be set, so returns cancelled before this build are invisible to organization holders while their owners still see them.
