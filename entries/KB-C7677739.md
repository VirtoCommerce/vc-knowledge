GET /api/sql-queries/database-information returns provider SqlServer and one connection string, SqlQueries.VirtoCommerce. POST /api/sql-queries/execute-preview with {query:'SELECT 1', connectionStringName:'SqlQueries.VirtoCommerce'} returns 500 in ~300 ms with message "Login failed for user '<env>_<db>_user_ro'". Reproduced on two stands (vcptcore_qa1, vcst_qa), module 3.1005.0, 2026-10-12. Without connectionStringName it returns 500 "Value cannot be null (request.ConnectionStringName)". The connection string is not defined in vc-deploy-dev infra/environments.yml (it is injected by the cloud provisioning), and no deploy branch overrides it. Consequence: any SQL Queries behaviour that needs a query to actually execute (results, timeouts, report export) cannot be tested on these stands until the read-only DB login is fixed by whoever provisions the cloud DB.
