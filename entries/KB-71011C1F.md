Observed on a vc-frontend build carrying the barcode scanner search setup (theme PR 2501 over x-catalog PR 113 and catalog PR 909), with the store's barcode fields set to gtin, code, manufacturerPartNumber and one short-text property. The page sends the products query with an empty keyword and the filter term barcode:"<value>"; the response reports the expansion as one isGenerated:true filter per configured field and no barcode chip is shown. Exactly one hit: the URL is replaced (router.replace) by the product's page, so Back returns to the page before the search and does not loop. When the hit is a variation that has its own SEO slug, the variation's slug page opens, not the parent. Several hits: a list under the heading 'Your search for barcode <value> returned the following', with no sidebar, no in-stock / purchased-before / branch controls and no chips; sorting works. Zero hits: 'No products found for barcode <value>' plus the search empty view and a Reset search button that navigates to /catalog, clearing barcode and q. A barcode request ignores ?facets= (dropped from the filter) and drops the in-stock filter even when the shopper's Show in stock preference is on, so an out-of-stock variation is still found. Adding &sort= to a single-hit URL shows a one-item list instead of redirecting. Anonymous and signed-in B2B buyers resolved identically. Values containing a double quote and a colon are escaped into one term and still match. HTML in the value is rendered as literal text in the heading.
