On vcptcore_dev, pageDocuments(storeId, keyword:"") listed 30 Virto Pages (source page-builder) with permalinks like /qa-partner-portal-support. slugInfo(permalink:"qa-partner-portal-support", storeId, cultureName:"en-US") returned entityInfo null and redirectUrl null for anonymous, personal-account, organization-account and admin callers, while a static content page resolved from "contacts" (objectType ContentFile, semanticUrl "/contacts") and the home page from "/" (ContentFile, semanticUrl "/"). The storefront (which strips the leading slash before the query) rendered 'B2B-store 404 Page not found', and a HEAD on that path returned HTTP 200 text/html (soft 404, as documented). The cause was not established (candidates: page not in the search index the resolver reads, publishing or language state, or the resolver expecting a leading slash); the miss also logs a broken link. So pageDocuments listing is not proof that the page is reachable by URL.
