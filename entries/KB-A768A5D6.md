For a storefront Customer account whose userName is a plain name (no @) and whose account email is a different string (<name>@domain), POST /connect/token with grant_type=password, storeId set, returned 200 with a token both when username = the user name and when username = the account email. So a test harness may sign in such an account by its user name; it does not need an email-shaped username.
