Firefox 151, 1440x900, theme 2.60.0, signed in as a Sales Representative. On /account/returns, Filters, Created date 'Custom date', 13452026 was typed into Start date (the mask shows 13/45/2026), then Tab. 'Invalid date format' appears under Start date: its details row goes from display none to flex (margin-top 4px + min-height 12px) and the Start date wrapper grows from 66 to 82 px. Because the range row is flex items-end, the End date field and the dash separator drop 16 px, so the two date inputs are no longer aligned (Start control top 478, End control top 494). The page's own reserved range-error row, the Status checkbox group, Reset and Apply all move down 16 px. In source, VcDatePicker and VcDateInput expose no showEmptyDetails prop, unlike VcInput, VcSelect and VcDateRangeInput, and a show-empty-details attribute on VcDatePicker falls through to its VcPopover root. The page therefore reserves a line only for its own range message, a separate VcInputDetails with show-empty, and the per-picker rows still collapse. Clearing the text removes the message. Nothing was applied.
