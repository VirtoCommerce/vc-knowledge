Read from the served CSS of both builds (theme 2.62.0-pr-2639). Both rules are single-class, both in @layer vc.kit: .vc-popup-sidebar__dialog sets width calc(100% - 1rem), max-width 21.25rem, position fixed, left .5rem; .vc-dialog sets width var(--w) (default 100% when no width prop). In the storefront the kit CSS lives in one lazy chunk where .vc-dialog comes AFTER .vc-popup-sidebar__dialog, so the root wins and the dialog is 100% wide (capped at 340px). In Storybook (one static style CSS, no per-story CSS) the order is reversed and the parent wins: the VcPopupSidebar With Footer story at a 320px viewport measures the dialog at x=8, width 304 (calc(100% - 1rem)). The storefront difference is visible only below ~356px viewport, where the panel starts 8px from the left and runs 8px past the right edge. VcTable sort icon (.vc-table__sort-icon vs .vc-icon) flips the same way but both resolve to .625rem, so no visible change. Only VcButton has a :where() base, so these other roots still depend on bundle order.
