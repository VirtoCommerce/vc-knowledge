On vcptcore-stable (Cloudflare+nginx edge), every POST /graphql whose body contains the createUser mutation is rejected at the EDGE with an nginx/Cloudflare HTTP 403 (challenge-platform JSD HTML), before reaching ProfileExperienceApiModule. Confirmed independent of payload (createUser with only userName+userType, no email/password/roles, still 403), independent of auth (anonymous AND admin-bearer both 403), and independent of client (Node fetch with a browser User-Agent AND a real Edge browser driving GraphiQL both got 403 on the createUser POST, while the same session's schema-introspection POST and a role(roleName:) query POST returned HTTP 200). The trigger is the createUser mutation itself, not privileged fields. Consequence: the app-layer createUser authorization / field-stripping behaviour (VCST-6974 check #1) cannot be observed via the external /graphql surface on this stand; the deployed module version is the deployment anchor instead.
