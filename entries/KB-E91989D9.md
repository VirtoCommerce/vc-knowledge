2026-10-09: a storefront-signed-in Customer (password grant with storeId B2B-store) POSTed a multipart PNG to /api/files/return-attachments. The response was HTTP 200 with body {"succeeded":false,"errorCode":"INVALID_SCOPE","errorMessage":"Unknown scope 'return-attachments'","errorParameter":"return-attachments"}. The failure is in the body, not the status code, so a caller that checks only res.ok treats it as a success. A buyer return created through Mutation.createReturn earlier on the same stand (2026-10-05, older module build) had reached Requested, so the scope was registered on that build and is not on this one. The store setting Return.AttachmentsRequired read null on the same day. A buyer-side return that needs evidence files cannot be attached through this scope on this build.
