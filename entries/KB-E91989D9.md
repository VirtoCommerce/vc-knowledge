2026-10-09: a storefront-signed-in Customer (password grant with storeId B2B-store) POSTed a multipart PNG to /api/files/return-attachments. The response was HTTP 200 with body {"succeeded":false,"errorCode":"INVALID_SCOPE","errorMessage":"Unknown scope 'return-attachments'","errorParameter":"return-attachments"}. The failure is in the body, not the status code, so a caller that checks only res.ok treats it as a success. A buyer return created through Mutation.createReturn earlier on the same stand (2026-10-05, older module build) had reached Requested, so the scope was registered on that build and is not on this one. The store setting Return.AttachmentsRequired read null on the same day. A buyer-side return that needs evidence files cannot be attached through this scope on this build. The refusal depends on the stand's configuration, not on the build: File Experience API reads its upload scopes only from the FileUpload section of the platform configuration (vc-module-file-experience-api 3.1008.0 Module.cs:32, FileUploadService.GetOptions), and the Return module only names the scope (ModuleConstants.ReturnAttachmentsScope) without registering it (its guide: the module cannot register one for you). On vcst on 2026-10-13 (Return 3.1005.0-pr-28-fb4f, FileExperienceApi 3.1008.0), after the scope was configured, the same buyer POST answered 200 [{succeeded:true, scope:'return-attachments', id, url}] (2 runs), and fileUploadOptions(scope) returned maxFileSize 5242880 and .jpg/.jpeg/.png/.webp/.pdf. An unconfigured scope is still refused in the body under HTTP 200: [{succeeded:false, errorCode:'INVALID_SCOPE', errorMessage:'Unknown scope ...'}].
