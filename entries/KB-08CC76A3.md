The code field takes digits only (typing 12a45 leaves 1245). Under six digits Sign in stays disabled and Enter sends nothing. The sixth digit auto-submits POST {storefront}/connect/token with grant_type=otp_email, scope=offline_access, storeId, email and code. Filling 7 digits keeps the first 6 and submits them; a spaced value (" 420 778 ") is submitted as 420778. A wrong code returns 400 invalid_grant with code invalid_code ("The code is invalid or has expired."), one call per entry and no automatic resubmit.

What the step shows for a wrong code depends on the theme build. Up to the 2.59.0 pre-release build observed 2026-10-01 morning it showed "That code isn't right. Check the latest email." and kept the digits. From theme 2.59.0-pr-2477 it shows a single alert "That code didn't work." and EMPTIES the field (marked invalid); the alert disappears once a digit is typed - observed live 2026-10-08 on 2.59.0-pr-2532. Resend clears the field and any alert and shows "New code sent." (each Resend writes a new OtpSignInEmailNotification); "Use a different email" returns to an empty email step.
