A file uploaded to POST /api/files/product-configuration and not yet attached to any cart (owner empty) reads 200 with the uploaded bytes for anonymous callers (no token) and for any authenticated buyer, not just the uploader. Observed identically on a pre-fix build (FileExperienceApi 3.1006.0, XCart 3.1039.0) on vcptcore_qa and on the fix builds (FileExperienceApi 3.1007.0-pr-25, XCart 3.1040.0-pr-149) on vcst_qa, so it is long-standing, not introduced by the fix. Once attached to a cart (addItem with fileUrls) the same id reads 403 for anyone but the cart owner and admin. Mutation.deleteFile by the uploader removes it (then 404).
