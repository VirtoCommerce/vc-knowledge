The Admin 'Customer orders' blade loads unfiltered via POST /api/order/customerOrders/search (16,883); applying a saved filter (Status = New) calls POST /api/order/customerOrders/indexed/search {statuses:['New']} and shows 16,555. The same criteria on POST /api/order/customerOrders/search return 16,655, all status New. Order CO261019-00007 (status New, created and last modified 2026-10-19) is in the DB search but absent from the indexed search (unfiltered indexed totalCount 16,783 vs DB 16,883; Search Index blade CustomerOrder count 16,797, last indexed 2026-11-18 16:04Z). So the filtered Admin view silently omits orders the index lacks; the gap is not index lag of minutes. Root cause (indexation runs skipped/partial on this stand vs a platform defect) not established.
