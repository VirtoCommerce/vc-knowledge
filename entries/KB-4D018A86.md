CustomerChoice run store, own session of each account. Accounts with emails of 66, 67 and 69 characters (three different kinds, with and without org roles): requestMfaChangeCode -> data null, errors[] "Error trying to resolve field 'requestMfaChangeCode'." extensions codes DB_UPDATE, SQL. Accounts with emails of 50-61 characters on the same store: succeeded true. The 67-character account's password grant with user mode Enabled still answered two_factor_required (the sign-in code path works). Root cause not established; a 64-character column limit on something written by the change-code path is the leading hypothesis.
