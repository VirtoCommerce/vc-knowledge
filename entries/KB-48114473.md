For a rep whose SalesRepLayout.customerProfile.<store> preference (saved via saveSalesRepLayout) had mainLeft = [orders, top_sellers] and no coupons block, /company/my-customers/{orgId} rendered "Available coupons" after Top sellers with 5 rows (SalesRepCoupons first 5). In Edit layout the block shows a Max rows spinbutton labelled "between 1 and 20": typing 0 and leaving the field sets it to 1, typing 21 sets it to 20. Saving 1 refetches SalesRepCoupons with first 1 and renders one row; saving 20 renders 20 rows when at least 20 are listed. Hiding the block and saving stores it with hidden:true (keeping maxRows); after reload the widget is absent and no SalesRepCoupons request is sent. Show from Hidden widgets appends it to the end of mainLeft; keyboard reorder (Space, ArrowUp x2, Space) announces "Available coupons dropped at position 1 of 3." and the order persists after reload. Edit layout > Reset + Save layout writes the registry default (coupons last in mainLeft, maxRows 5), not a null layout.
