Observed on a vc-frontend build carrying the barcode scanner search setup (theme PR 2501, x-catalog PR 113, catalog PR 909). Store settings are read at app load, so a change is seen only after a full reload. Defaults (scannerEnabled true, fields empty): the Barcode scan button shows in the desktop search bar and in the mobile (390 px) overlay bar; typing a GTIN into the box is a full-text search (?q=) that also matches the value inside other products' names; /search?barcode=<value> is still routed to the barcode heading, but the products query carries barcode:"<value>" as a literal filter term and returns 0, so the page shows 'No products found for barcode <value>'. scannerEnabled false with fields configured: the Barcode scan button disappears from both bars, yet /search?barcode=<value> still expands to the configured fields and opens the product, so the switch hides the entry point only. A whitespace-only ?barcode=%20%20 is not trimmed: it renders the empty state with a blank value in the heading, no error. On a category route (for example /<category-slug>?barcode=<value>) the term is applied inside that category's scope and the plain category heading is used.
