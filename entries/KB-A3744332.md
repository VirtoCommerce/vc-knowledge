Live introspection on vcptcore_dev: type SeoInfo has id String!, semanticUrl String!, objectId String!, objectType String!, isActive Boolean!, and nullable name, outline, pageTitle, metaDescription, imageAltDescription, metaKeywords, storeId, languageCode (no organizationId is exposed although the REST SeoInfo model carries one). categories(storeId:"Clothing"|"store-acme", first:300){items{seoInfo{id}}} returned per-item errors 'Error trying to resolve field id' (and objectType) for items with no applicable record, while the same selection on B2B-store (every category has a record) was clean. The cause is the fallback instance built when the best-match filter finds nothing (SeoExtensions.GetFallbackSeoInfo sets only SemanticUrl/LanguageCode/Name). On store-acme, which shares B2B-store's catalog but has no SEO records assigned to it, all 143 categories came back with slug null and a fallback seoInfo (storeId null). Select slug, semanticUrl, pageTitle, metaDescription; avoid id/objectType/objectId on seoInfo for lists.
