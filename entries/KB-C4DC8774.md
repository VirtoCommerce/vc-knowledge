For a personal storefront customer, xAPI me { contact { addresses(first:50) } } with no sort returns the addresses in NAME ASCENDING order - identical to sort:"name:asc", and the same on repeated reads. Addresses with a null name sort first under ascending (last under "name:desc"), and ties among them follow the address id (key) ascending, which is also the order GET /api/members/{id} uses for every address. So with names, the default is alphabetical (written Zulu, Alpha, Mike, Bravo -> Alpha, Bravo, Mike, Zulu); without names it equals the REST order, and deleting and re-adding the same unnamed addresses reorders them because they get new ids. Observed live 2026-10-08 on vcst_qa and vcptcore_stable. A test that compares a user-triggered sort against the default must read the default live and give its addresses names.
