For a personal storefront customer, xAPI query me { contact { addresses(first:50) } } with no sort returned the addresses in neither insertion order nor the REST order: after appending three addresses to the contact the order was O'Connor, Brown, Wilson, Doe; after deleting and re-adding the same three it was Wilson, Brown, O'Connor, Doe, with the pre-existing address last both times. GET /api/members/{id} in the same state listed them ordered by address key (GUID). A test that compares a user-triggered sort against the default order must therefore read the default order live, not assume the order the data was written in.
