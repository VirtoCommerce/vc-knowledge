Anonymous POST /graphql {passkeyRequestOptions} returns 200 with a JSON string: challenge (fresh on every call), timeout 300000, rpId, allowCredentials [] (so only discoverable / usernameless sign-in is possible; the query takes no user argument), userVerification "required", hints []. rpId equals the host the request arrived on: platform host /graphql -> platform host, storefront host /graphql -> storefront host; an Origin request header (own or foreign) changes nothing. Anonymous REST POST /api/passkeys/request-options on the platform host answers the same options (200); on the storefront host the same path answers an nginx 405 while /graphql on that host works. Query.passkeyCreationOptions and Query.signInMethods are 200 with errors[] Unauthorized when anonymous; with an admin bearer token passkeyCreationOptions returns rp (same host-derived id), user, pubKeyCredParams, authenticatorSelection residentKey preferred / userVerification required. A passkey registered on one host is therefore bound to that host's rpId.
