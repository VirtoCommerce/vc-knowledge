Measured on vcst-qa 2026-09-19. (1) POST /api/platform/security/users/{userName}/lock returns HTTP 200 with body {"succeeded":false,"errors":[]} and changes nothing — an empty errors array, so there is no message to act on. The same call with the account's GUID id in place of the userName returns {"succeeded":true,"errors":[]} and sets lockoutEnd to 9999-12-31T23:59:59.9999999+00:00. The matching /unlock also takes the id. Note that unlock does not restore lockoutEnd to null: it becomes 0001-01-01T00:00:00+00:00, and a PUT /api/platform/security/users carrying lockoutEnd:null is accepted (succeeded:true) but normalized back to 0001-01-01, so null is not reachable again once an account has been locked. Functionally the min date is unlocked. (2) POST /api/members/search returns {"totalCount":N,"results":[]} with N greater than zero unless the criteria include deepSearch:true; with it the same criteria return the populated results array. Neither failure raises an error, so both read as "no such member" to a caller that does not know.
