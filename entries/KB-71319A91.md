On vcst_qa a signed-in user placed a CyberSource order from /cart; the sandbox merchant's Decision Manager held the legitimate authorize for review (isSuccess true, order Payment required, PaymentIn New, 0 transactions, outerId set). Replaying storefront /graphql AuthorizePayment on the same orderId/paymentId within the token's 15-minute life: the unchanged token, a payload-edited token, a forged-signature token, an alg:none token and a token with a past exp claim each answered isSuccess true held for review AND changed PaymentIn.outerId to a new CyberSource payment id (6 distinct ids for one order); order status, payment status, isApproved and transactions never changed. A token whose jti was replaced (signature kept), not-a-jwt and an empty token answered errors[0].extensions.code API and left outerId unchanged. So the gateway binds the card to the jti, payload edits cannot change the card, but nothing stops repeated submissions and VC keeps only the latest gateway payment id. Admin Cancel document on the order does not touch the earlier gateway payments.
