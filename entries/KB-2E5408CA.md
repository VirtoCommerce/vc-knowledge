Two Manager accounts (isAdministrator=false), each with one role, differing only in platform:setting:read + platform:security:read. Base role: platform:setting:access, platform:security:access, catalog:access. With a password-grant token (no storeId), /connect/token returned 200 for both, and /currentuser listed exactly the role permissions. Base-only token: GET /api/platform/settings/v2/global/schema 403, POST /api/platform/security/users/search 403, POST /api/platform/security/roles/search 403. Base plus the two read permissions: all three returned 200. So *:access alone does not open these data endpoints; the read permission is what gates them. GET /api/platform/security/permissions (363 entries) has no platform:access, so the Manager userType is what lets a restricted account sign in.
