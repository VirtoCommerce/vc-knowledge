On an existing generated key, saving with PUT (and the same with POST) behaved as follows. apiKey "" or the key's own hint returned 200, the hint was unchanged and the key kept working. Another key's hint returned 400 "The API key looks masked. Send an empty value to keep the stored key, or a new key to replace it." A 31-char value returned 400 "The API key must be at least 32 characters long. Send an empty value to have the platform generate one." In both 400 cases the stored key kept working. A 32-char client value returned 200: the new value authenticated at once, the old value got 401, and the hint changed to the new value's 4…4. In the body, apiKeyHash and apiKeyHint were ignored: the stored hint stayed derived from the real key, and a new key POSTed with them still got a generated vc_ key. Whenever the client supplied its own value (32, 33 or 40 chars), the 200 response's apiKey field held that full value instead of the hint. Every other save response held only the hint, and apiKeyHash was null in all responses.
