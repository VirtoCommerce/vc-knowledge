The configuration a buyer assembled is not exposed on the storefront GraphQL order in the shape it had in the cart. CartConfigurationItemType has eight fields -- id, name, type, customText, files, productId, quantity and sectionId. OrderConfigurationItemType has five: id, name, type, customText and files. productId, quantity and sectionId are all dropped, and selecting productId, quantity, sectionId, sku, catalogId, categoryId or imageUrl on OrderConfigurationItemType is refused by validation error. So for a configuration section whose type is 'Product', this projection of the order gives the chosen option's NAME and nothing that identifies the product it was or how many were taken, and it does not give which section the choice answered. Anything reconciling a configured order back to catalog products through this projection has only a display string to match on. This is read off the deployment's own schema: read the same two type tables on any deployment and a diff either confirms it or retires it.
