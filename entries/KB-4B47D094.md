On a configurable product whose optional Product section offers an option with a FIXED quantity of 2 (unit $88.00, extendedPrice $176.00) on top of a $350.00 base: selecting that option moved the PDP "Price" from $350.00 to $526.00, i.e. base + extendedPrice, not base + unit price. The storefront sends Mutation.createConfiguredLineItem with configurationSections[].option = {productId, quantity: 2} and the server returns listPrice = salePrice = extendedPrice = 526.00 for the configured line. Mutation.addItem then carries the identical configurationSections payload; the resulting cart line has sku "Configuration-<parent code>", quantity 1 and price $526.00. The same $526.00 survived the cart page, the checkout review and the placed order line. Two related UI observations at the same coordinates: (a) the per-option quantity spinbutton on the PDP is rendered DISABLED, so the option quantity is fixture-fixed and not shopper-editable; (b) the cart's "Components list" renders a 4-column table (Number / Section / Value / Price) showing "1. | Select one: | <option label> | +$176.00", but the SAME components list on the placed-order page renders only "1. <option label>" — the Section and Price columns are absent on the order view, so the option's price contribution is not visible once the order exists.
