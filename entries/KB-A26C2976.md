On a customer account whose security user has storeId=B2B-store (approved, email confirmed, not locked out), POST /connect/token with grant_type=password, username, password and scope=offline_access returned 400 {"code":"login_failed"}. Adding storeId=B2B-store to the same form body returned 200 with an access token. The storefront's useAuth sends storeId with the password grant, so the UI is unaffected; scripts and API clients that omit it see a misleading credentials error, and each attempt increments the account's failed-access count.
