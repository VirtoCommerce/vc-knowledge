On theme 2.60.0-pr-2523-466f-466fa0a8 (Firefox 151, Windows), both 'My returns' and the organization tab of /account/returns render one card per return in two equal columns. The RMA value (16 px Lato, weight 900) needs 137.3 px for a default-template RMA (Return.ReturnNewNumberTemplate unset, default RET{0:yyMMdd}-{1:D5}, 15 characters, e.g. RET261009-00023), while its content box is 148 px minus 16 px right padding = 132 px at a 375 px viewport (124.5 px at 360). The value computes word-break: break-word (inherited from the VcTable mobile container .vc-table__mobile), white-space: normal, overflow: hidden and text-overflow: ellipsis; the ellipsis never applies because the text is allowed to wrap. Firefox finds no break opportunity between the hyphen and the following digit and splits the token where it overflows: 375 px gives 'RET261009-0002' / '3' (10/10 organization-tab cards, 5/5 own cards), 360 px gives 'RET261009-000' / '23' (10/10 and 5/5), 385 px is still split (content box 137.0 px), 386 px is whole (137.5 px). Query.organizationReturns returns every number whole (errors null) and each card's accessible name carries the whole RMA, so only the visual rendering is affected. The same run's Chromium lane saw the split at the hyphen instead ('RET261009-' / '00021').
