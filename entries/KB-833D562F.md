Observed with a personal customer (5 addresses, no organization) and a corporate org-maintainer (1 personal address, 22 organization addresses), read-only, on /graphql. Query.currentCustomerAddresses(ids:[...]) returns only addresses of the caller's own personal book: a foreign id (another customer's, or an organization's address) gives totalCount 0 and no error; a mix of own and foreign ids returns the own ones only; a duplicated id returns one item; an empty string id, a non-GUID string and an all-zero GUID give totalCount 0, status 200, no errors; ids:[] and ids:null behave as no filter and return the whole own book. Query.currentOrganizationAddresses(ids:[...]) behaves the same against the organization book (a personal address id gives 0, an own org id gives 1, two own org ids give 2), and a user without an organization gets totalCount 0. The two books are separate: a personal address id passed to the organization query, or an organization address id passed to the customer query, returns 0. An anonymous caller gets 'Access denied.' with data null. keyword is ANDed with ids: an own id whose address does not match the keyword returns 0, one that matches returns 1. Pagination runs over the narrowed set: ids of 4 own addresses with first:2 gives totalCount 4, 2 items and pageInfo.hasNextPage true, and after:<endCursor> gives the other 2 with hasNextPage false; keyword plus first:2 plus after:<endCursor> pages the same way, totalCount being the keyword match count (4 of 5 for one city term), not the page size. first:1 with one own id returns that item. An unparseable after cursor is not an error: it is read as the start, the first page comes back. first:0 returns 0 items with totalCount the full count and hasNextPage true. 200 ids in one call (one valid) is answered normally with 1 item.
