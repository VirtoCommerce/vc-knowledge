Guest adds go through saveProductsToCompareList with no Authorization header and the anonymous userId the storefront keeps in localStorage `user-id`; localStorage also keeps `vc-product-comparison:guest-list-id:<storeId>` (the list id, no product ids). After sign-in (connect/token then page load) the storefront calls mergeCompareList(userId=<account>, secondListId=<guest list id>); the account receives the guest items (an overlapping product stays once), and the guest list is deleted (compareList by the anonymous id then returns null). With the account's category group already full (MaxItems 5), the guest's items win and the account's newest items fill the rest; the oldest account items are dropped. Registration that does not sign in (email verification) defers the merge to the first sign-in. If the merge request fails, the user sees an empty list with no message; the guest list and its localStorage id remain and the next page load re-runs the merge. Access: without a token, a guest list is readable and writable by its anonymous id (the guest's only credential); a registered user's id without a token is Unauthorized; a signed-in buyer using another user's id is Forbidden; but any signed-in buyer may call mergeCompareList(userId=<own>, secondListId=<a guest list id>) and so take a guest list into their account, deleting it — the PR allows "a guest list or the caller's own" as the merge source.
