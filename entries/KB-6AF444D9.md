Rep token: salesRepLayout and saveSalesRepLayout fail validation (HTTP 400 FIELDS_ON_CORRECT_TYPE) on both /graphql and /graphql/sales-rep. /company/dashboard sends GetLayout {scope:"salesRepDashboard", storeId:"B2B-store"} on /graphql and renders six stat cards (Orders in "New" status, Active carts, Orders placed WEEK/MTD/YTD, My customers) from SalesRepCustomerOrderStatistics/CartStatistics/Counts; Edit layout → Hide Document library → Save layout sends one SaveLayout with that scope (documents block hidden:true) and writes preference Layout.salesRepDashboard.B2B-store; after reload no SalesRepDocuments request is sent, and after Reset + Save it is sent again. /company/my-customers/{orgId} sends GetLayout scope salesRepCustomerProfile and requests statistics only after SalesRepCustomer returns a customer; for a made-up or unserved org id SalesRepCustomer returns null, the page says "Customer not found or not in your customers." and no statistics request is sent. The rep's earlier SalesRepLayout.dashboard.B2B-store preference stays in place and is not read (new scope reads null until saved) — the PR declares this waiver; it does not count toward the 20-layout cap.
