A .page-draft was written straight through POST /api/content/pages/{store}?draft=true&folderUrl=/ with settings.permalink containing spaces (200, stored verbatim). Opened in Admin Content -> store -> Pages, the blade shows no format error for the untouched stored value and Publish is enabled. Changing File name enables Save; Save sends POST /api/content/pages/{store}?draft=true (200) plus DELETE of the old file name (204, the rename), and a second in-session rename-and-save also succeeds. GET of the saved file shows the original permalink with its spaces unchanged. Typing a different invalid value shows the error and disables Save and Publish; typing the stored value back clears the error and Save is enabled again. The check exempts only the value the page was loaded with.
