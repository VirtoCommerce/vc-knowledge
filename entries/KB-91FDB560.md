2026-10-06, x-cart 3.1038.0-pr-141-b404. createWishlist without scope returns sharingSetting {scope Private, access Write, isOwner true} but nothing is persisted: the createWishlist response, three consecutive wishlist(listId) reads and a wishlists() read each returned a DIFFERENT sharingSetting.id, and sharedWishlist(<the id from create>) returns data null with no errors. A list created with scope Private explicitly keeps the same id across reads. Org-mates get Forbidden from wishlist(listId) on the scope-less list (no Organization access is inferred). The resolver falls back to Guid.NewGuid() when the cart has no setting; that fallback already exists on the x-cart dev branch, so this is not introduced by the scope-registry refactor. sharedWishlist with a Private list's key, or a bogus key, also returns data null with no errors (not Forbidden).
