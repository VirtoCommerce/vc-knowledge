vcst_qa (>=2 instances), 2026-10-08. A poller sent 4 parallel cookie-less admin GETs of each of the 8 SalesRep.Statistics.* settings every ~1.5 s for ~16 min while another session changed them through the API. Each of the 3 changes seen (TopSellerInvalidateOnChange false->true, all four TTLs 60->1, TopSellerInvalidateOnChange true->false) appeared in the first poll tick after the write, with all 4 parallel reads of that tick and every later tick agreeing; no tick returned a mix of old and new values. Behavioural cross-check: statistics entries warmed on both instances after a flag was switched to true were evicted on both by the next change, so each instance had picked the new value for the token-attach side as well. Writing null to a stored value did not unset it (the stored value stayed), as noted by the session that made the changes.
