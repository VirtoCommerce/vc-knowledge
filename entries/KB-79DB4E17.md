On platform builds that include vc-platform PR 3125, bladeNavigationService.setError sets blade.error to '<status>: <statusText>' and builds blade.errorBody from the response body. For a bare array it joins each item's string or errorMessage with <br>. For an object it uses exceptionMessage, then message, then errors joined with <br>, but only when errors is an array. If none of these yields text (an empty array, items without errorMessage, ProblemDetails with no errors, errors as an object, or no body), errorBody falls back to blade.error. It never throws. A null or undefined response clears the blade error. Earlier builds threw TypeError 'reading join' on any body without exceptionMessage, message or an errors array, for example a bare FluentValidation list, and left View details empty.
