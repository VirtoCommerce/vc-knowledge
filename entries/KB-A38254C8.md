A product's configurability is NOT a field on the product. GET /api/catalog/products/{id} returns the full CatalogProduct record (59 top-level fields on Catalog 3.1048-3.1049, including mainProductId and variations) and carries no isConfigurable and no configuration at all, even for a product with an active configuration, so reading products can never tell you. The configuration is a separate entity keyed by productId (POST /api/catalog/products/configurations creates it; search by productId finds it). productType is Physical, Digital, null or an empty string - 'Configurable' is not one of its values, so filtering products by type finds nothing either. The storefront GraphQL Product type does expose a computed isConfigurable: false before a configuration exists, true while it is active, false again after it is deactivated (observed live 2026-10-08 on vcst_qa and vcptcore_qa1); it is computed for products the search index holds, so it answers a narrower question than the REST route does. A catalog can hold the configuration OPTION products and categories named for configurables while having no configurable product at all - the options are ordinary products.
