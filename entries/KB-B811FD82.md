On x-cart pr-141 / cart pr-194 / sales-rep pr-21, a changeWishlist refused with INVALID_OPERATION for an empty Customer set (scope Customer with no ids from Private or AnyoneAnonymous, or the same id in addSharedWithIds and removeSharedWithIds) writes nothing to storage (reads through a never-used cache key show the old state), but the owner's repeated wishlist(listId) reads with the usual cache key then alternate between the old state and the refused one (scope Customer, or targets empty). A later rename-only changeWishlist returned scope Customer and persisted it: an AnyoneAnonymous list became Customer with zero targets and its anonymous link stopped working. Refusals from checks that run earlier (Access denied for an unserved org, legacy sharedWithId on a 2-target list, message over 1024 chars) did not poison the read.
